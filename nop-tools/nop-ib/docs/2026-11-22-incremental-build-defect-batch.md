# 增量构建缺陷批：clean 不建上游 / 产物删除假"无变化" / 生成源模块增量编译失败 / 服务启动耦合

- 日期：2026-11-22
- 组件：`nop-ib`（增量构建与测试服务）
- 严重度：高——三处缺陷都会让用户看到**看似成功或看似无关**的结果，而非明确的错误
- 起因：在无任何 `target/` 的新工作树（clean 状态）与后续增量开发中连续暴露

## 缺陷 1：clean 状态下快路径不构建上游，报 javac 非法选项后"完成"

**现象**：新建工作树（零 `target/classes`）跑增量编译，javac 报
`非法的编译选项取值: -classpath=<某上游模块>/target/classes`，任务以"完成"收场，零产物。

**根因**：`IncrementalCompileExecutor.compileModule` 把模型声明的上游 reactor 目录直接拼进
javac classpath，从不校验其在磁盘上存在。

**修复**：编译前逐项校验上游 classpath 目录存在且指纹新鲜（`productsFresh()`：输出目录存在 +
单元索引覆盖每条手写主源）；缺失/陈旧按依赖拓扑序递归先建上游。整模块重建复用既有单模块
能力；带代码生成/注解处理的模块自动委派真实 Maven。

**附带修复**：`ClasspathMaterializer` 增传递闭包（模型只记录直接依赖，传递性兄弟模块缺条目）。

## 缺陷 2：产物被外部删除后指纹仍判"无变化"

**现象**：删除某模块 `target/classes` 后再跑编译，返回 `compiled: []`（认为无变化），
下游随后报"找不到符号"。

**根因**：指纹判定只看源与索引，不看输出产物是否真实存在于磁盘。

**修复**：指纹判定必须包含"输出产物存在"；不存在即 stale。测试缓存路径同款（缺失即返回
null，永不命中 cached-up-to-date，避免假绿）。

## 缺陷 3：带生成源的模块，增量快路径不认 generated-sources

**现象**：ANTLR 类模块（生成源在 `target/generated-sources/**`）产物齐全后，改动手写源跑增量
编译，报大量"找不到符号：<生成的类>"。

**根因**：快路径 javac 的源集只含 plan 选中的手写源，`sourcePath` 只含 `src/main/java`
+`src/test/java`；Maven `add-source-root` 进来的生成源完全不在视野内。

**修复**：存在生成源根时——①生成根加入 `sourcePath`（与 Maven 同权）；②生成产物的 `.class`
缺失则把这些生成源直接并入本次 javac 源集；③生成源文件本身不存在但 pom 声明了代码生成插件
→ 委派 Maven 重建；④`productsFresh` 对生成产物缺失判 stale。

## 附带修复（复现途中暴露的真实缺陷）

- **索引扫描崩溃**：全模块扫描的常量池字符串含孤立代理字符 → UTF-8 编码抛
  `UnmappableCharacterException` 整体中止 → 落盘前做代理字符清洗。
- **自身状态文件被当变更**：未跟踪的状态文件（`.nop-ib/`、`_tmp/`）被计为变更 → 过滤。
- **无主模块路径崩溃**：回退分支对非源码路径 `owningModuleOf` 崩溃 + `Map.of(..., null)` NPE。

## 教训

1. **"完成"与"成功"必须区分**：增量工具在无产物时返回 `compiled: []` 是最危险的形态——
   用户会以为无事发生。产物存在性必须进新鲜度判据。
2. **生成源是编译源集的一等公民**：凡 Maven `add-source-root` 语义的面，增量快路径必须同权
   纳入，否则"增量"与"全量"会产生不同结果。
3. **委派优于模仿**：代码生成、注解处理这类 Maven 生命周期职责，增量快路径不应自建，应显式
   委派真实 Maven 并如实报告。
