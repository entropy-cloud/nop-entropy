## Scope

### In Scope

- NFA 编译/执行路径对比：Flink 的 NFACompiler → NFA → NFAState → 状态转换 vs nop-stream 等价实现。检查 NFA state machine 的生命周期、状态迁移、事件处理循环
- SharedBuffer 实现对比：Flink 的 Dewey 编号（DeweyNumber）、引用计数（Lockable）、TElement/TCompletion 管理、SharedBufferAccessor 封装 vs nop-stream 等价实现
- CepOperator 对比：Flink 的 KeyedStateBackend 集成（NFA state、SharedBuffer、computation state 的 snapshot/restore）vs nop-stream CepOperator 实际使用的状态后端管路（`getKeyedStateBackend()` → `stateBackend.createKeyedStateBackend()` → fallback `MemoryKeyedStateBackend`）。评估状态后端创建、checkpoint snapshot/restore 接线是否完整
- 事件时间超时处理对比：Flink 的 within + TimerService 超时处理 vs nop-stream CepOperator 内部 watermark 跟踪（`currentWatermark` field, `processWatermark()` line 338）。真实缺口在外部 watermark 从 runtime 传播到 operator 的管路，而非 CepOperator 内部
- 匹配后策略对比：AfterMatchSkipStrategy 完整实现（NoSkip/SkipPastLast/SkipToFirst/SkipToLast/SkipToNext）vs nop-stream 等价实现
- 声明式模型对比：nop-stream 独有的 `CepPatternModel` / `CepPatternSingleModel` / `CepPatternGroupModel` 与 Flink Pattern API 的等价性
- 结论：差距列表、优先级（P0-P3）、修复建议

### Out Of Scope

- Checkpoint/barrier comparison (item 3)
- State management comparison (item 4)
- Window/time comparison (item 5)
- Distributed execution comparison (item 7)
- Code fixes or refactoring
- CEP watermark 集成（属于 roadmap item 11 讨论范围，本计划仅评估 `currentWatermark()` 现状的影响）
