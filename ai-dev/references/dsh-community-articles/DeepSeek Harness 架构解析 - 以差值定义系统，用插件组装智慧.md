# DeepSeek Harness 架构解析：以差值定义系统，用插件组装智慧

> 来源: https://mp.weixin.qq.com/s/Kf87hcNdSmY4ODWI4UZ8cg
> 作者: 数字双生子（Byte Logic）

## 引言：当我们谈论软件架构时，究竟在谈论什么？

在软件工程的历史长河中，我们见证过无数架构风格的兴衰：从单体应用到微服务，从面向对象到函数式编程，从 MVC 到 Clean Architecture。

但如果我们退后一步，问一个更本质的问题：**软件架构的核心难题是什么？**

答案是：**如何管理变化。**

需求会变，技术会变，团队会变。软件系统的熵增是永恒的敌人。所有的架构风格，本质上都是在回答同一个问题——如何让系统在变化中保持有序，在扩展中不失控。

今天，我想从“差值”这个数学概念出发，剖析 DeepSeek Harness 如何用一种近乎哲学的方式，重新定义了软件的组合与演化。

这篇文章，我们将超越具体的技术细节，进入软件架构的形而上层面。

## 一、差值思维：软件工程的数学之美

### 1.1 从微积分说起

微积分的核心思想是：**复杂的变化，可以分解为无穷多个微小的差值之和。**

这个思想在软件工程中同样适用。当我们说“扩展一个系统”时，本质上是：**新系统 = 旧系统 + 差值**。

这就是“差值思维”的核心：

> 不要重新构建整个系统，而是定义“你想要改变的部分”。

传统开发中，我们通过继承、通过配置、通过 if-else 来表达这种差值。但这些方式都有一个共同的问题：**差值与原系统紧密耦合。**

### 1.2 继承的困境

面向对象编程用“继承”来表达差值：

```
class MyAgent extends BaseAgent {
  // 我只写差异部分
}
```

这看起来很美，但实践中：

- **编译期绑定**：继承关系在编译时确定，无法运行时调整
- **脆弱基类问题**：基类修改，所有子类遭殃
- **单继承限制**：无法组合多个维度的变化
- **差值不可见**：你看到的是完整定义，而非变化本身

### 1.3 配置的局限

Spring 等框架用“配置”来表达差值：

```yaml
agent:
  tools: [search, code, file]
  model: deepseek-chat
```

配置解决了编译期绑定的问题，但：

- **表达能力有限**：只能配置“参数”，不能改变“结构”
- **静态性**：配置在启动时加载，运行时无法调整
- **全局命名空间**：所有配置扁平化，缺乏组合性

## 二、Cordis 的差值表达：Patch 机制

### 2.1 系统即差值的叠加

DeepSeek Harness 的 Cordis 框架给出了一种全新的差值表达方式。

它的核心思想是：**系统 = 基础 + Patch1 + Patch2 + ... + PatchN**

每个 Patch 是一个独立的、自包含的、可组合的变化单元。Patch 可以：

- 添加新插件
- 移除已有插件
- 修改插件配置
- 调整插件顺序

### 2.2 YAML 声明式差值

在 DeepSeek Harness 中，差值用 YAML 声明式表达：

```yaml
# base 配置
plugins:
  llm-deepseek:
    model: deepseek-chat
  tools-basic: true
```

```yaml
# patch1: 研究模式
$remove:
  tools-basic: true
$set:
  research-mode:
    depth: deep
  web-search:
    engine: exa
```

这个设计的精妙之处在于：

- **每个 Patch 是独立文件**：可以单独开发、测试、复用
- **Patch 之间可以组合**：多个 Patch 叠加形成最终系统
- **差值是一等公民**：你操作的是“变化”本身，而非完整定义

### 2.3 与 Git 的深层类比

Git 的成功在于它管理的不是文件，而是**变化**。

- 文件是状态的快照
- Commit 是差值的记录
- Branch 是差值流的分叉
- Merge 是差值流的汇合

Cordis 的 Patch 机制与 Git 有着深层的同构性：

| Git | Cordis Patch |
|-----|--------------|
| Commit | Patch 文件 |
| Branch | Profile（配置组合） |
| Merge | Patch 叠加 |
| Rebase | Patch 重新排序 |
| Diff | $remove/$set 操作 |

这不是巧合。两者都在解决同一个本质问题：**如何让“变化”本身成为可管理的对象。**

## 三、可逆计算理论：差值思维的理论基础

### 3.1 什么是可逆计算？

差值思维并非凭空出现，它有着深刻的理论基础——**可逆计算（Reversible Computation）**。

可逆计算理论（由徐昊提出，Nop 平台的核心思想）指出：

> 软件构造的本质是：**App = Delta(Biz, Buz, ...)**
>
> 即：应用程序 = 差值的叠加（业务逻辑、业务流程等的组合差异）

公式：**Y = X + ΔY**

- X 是基础系统（给定的、不可选择的）
- ΔY 是差值（可选择的、可组合的）
- Y 是最终系统

### 3.2 从 TreeSet 范式到 Agent 范式

Nop 理论中有个经典的“TreeSet 范式”：

> 给定任意两个复杂的树结构 A 和 B，总可以通过一个可计算的差值 Δ，使得 A + Δ = B。

这意味着：**任何目标系统，都可以表达为“某个基础系统 + 差值”。**

DeepSeek Harness 将这个理论应用到了 Agent 领域：

- **基础系统**：Cordis 运行时 + 核心插件
- **差值**：Profile、Preset、Patch
- **最终系统**：一个定制化的 Agent 实例

### 3.3 差值的组合代数

差值不仅是表达方式，还构成一个代数系统：

```
Δ1 + Δ2 = Δ3      （差值可以合并）
Δ · Δ⁻¹ = 0       （差值可以抵消）
(Δ1 + Δ2) + Δ3 = Δ1 + (Δ2 + Δ3)   （结合律）
```

这个代数系统保证了：

- **组合的安全性**：多个差值叠加，结果可预测
- **撤销的完备性**：任何差值都有逆，可以回到初始状态
- **顺序的灵活性**：差值可以重新排列（在满足约束时）

这正好呼应了 Cordis 的 Effect 机制——每个副作用的“解药”，就是一个**逆差值**。

## 四、Preset 系统：差值思维的工程落地

### 4.1 什么是 Preset？

Preset（预设）是 DeepSeek Harness 中差值思维的集中体现。

一个 Preset 定义了“一类 Agent”的完整配置：

```
presets/
  coding-agent/
    agent.cordis.yml    # 插件组合声明
    preset.yml          # 预设元数据
  research-agent/
    agent.cordis.yml
    preset.yml
```

比如官方内置的四个预设：code、cordis、minimal、standard。

### 4.2 Scope 链：差值的作用域

但 DeepSeek Harness 的精妙之处在于，它不只是静态的配置叠加，而是引入了**作用域链**：

```
全局 Scope → Preset Scope → Session Scope
```

- **全局 Scope**：系统的基础设施（LLM 接入、凭据管理）
- **Preset Scope**：该预设的能力组合（工具集、提示词）
- **Session Scope**：当前会话的动态状态

**差值在 Scope 链上按序叠加，每一层可以覆盖、遮蔽上一层的定义。**

这就是“分层遮蔽算法”（第五章会详述）：

- 子 Scope 可以覆盖父 Scope 的工具定义
- 子 Scope 可以遮蔽父 Scope 的服务
- 同名定义，最近者优先

### 4.3 运行时的差值计算

与静态配置不同，DeepSeek Harness 的差值是**运行时计算的**：

```
EffectiveTools = LayerN(...Layer2(Layer1(BaseTools)))
```

每个会话的工具集、提示词，都是在运行时根据 Scope 链实时计算的结果。这意味着：

- 会话 A 可以用 coding preset 的工具集
- 会话 B 可以用 research preset 的工具集
- 两者共享同一份全局基础设施，互不干扰

## 五、分层遮蔽算法：差值的运行时解析

### 5.1 工具的三层结构

在 DeepSeek Harness 中，每个 Agent 看到的工具集，由三层结构决定：

```
Layer 1: 全局工具（基础集）
Layer 2: 祖先 Scope 的覆盖（继承链）
Layer 3: 当前 Scope 的直接注册（最高优先级）
```

### 5.2 遮蔽规则

解析“当前 Agent 能用什么工具”的算法：

1. **加载全局层**：所有全局注册的工具，作为基础集
2. **应用祖先层的覆盖**：按 Scope 链从上到下，依次覆盖同名工具
3. **应用限制规则**：某些 Scope 可能禁用特定工具（黑名单）
4. **应用当前层的注册**：当前 Scope 直接注册的工具，覆盖一切继承来的定义

**关键规则：当前 Scope 注册的工具，优先于一切继承和限制规则。**

### 5.3 遮蔽的意义

这套机制看似复杂，但它解决了一个根本问题：**同一系统，不同视图**。

- 一个工具在全局注册，但被某个 Preset 遮蔽（改进版）
- 一个工具在某个会话中动态注册（临时工具）
- 一个工具被策略插件禁用（安全考虑）

所有这些，都不需要修改工具本身的代码。**差值在哪儿生效，工具就在哪儿变形。**

## 六、哲学升华：差值思维的诗意

### 6.1 《道德经》的智慧

有趣的是，差值思维与东方哲学有着深刻的共鸣。

《道德经》说：

> “三十辐共一毂，当其无，有车之用。埏埴以为器，当其无，有器之用。凿户牖以为室，当其无，有室之用。故有之以为利，无之以为用。”

翻译成软件语言：

> 三十根辐条安装在轮毂上，正因为有“空无”（差值），车才能用。揉捏陶土做器皿，正因为留出“空无”（差值），器皿才能用。开凿门窗建造房屋，正因为有“空无”（差值），房屋才能用。

**“有”给人便利，“无”（差值空间）才是真正的用处。**

一个设计良好的系统，不在于它预置了多少功能，而在于它预留了多少“变化的空间”。

### 6.2 雕塑家的智慧

米开朗基罗谈到雕塑时说：

> “我在大理石中看见天使，于是不停地雕刻，直到使他自由。”

差值思维正是如此：

- 大理石 = 基础系统（给定的）
- 天使 = 目标系统（期望的）
- 雕刻 = 差值操作（移除多余的部分）

**定义一个系统，不是从头构建，而是从基础中“雕刻”出你想要的形态。**

### 6.3 涌现与组合

最后，差值思维指向一个更宏大的命题：**涌现（Emergence）**。

复杂系统科学告诉我们：

> 简单单元的简单组合，可以涌现出超越单元的能力。

蚁群、鸟群、大脑——都是涌现的杰作。

DeepSeek Harness 的插件化架构，正是在为“Agent 能力的涌现”创造条件：

- 每个插件是简单的单元（单一职责）
- Patch/Preset 是组合的规则（差值代数）
- 最终的 Agent 是涌现的结果

**我们不是在“编写”智能，而是在“组装”智慧。**

## 七、工程启示录

### 7.1 给架构师的建议

从 DeepSeek Harness 的差值思维中，架构师可以学到：

1. **不要追求“完整”的系统设计**，而要设计“可差值化”的基础
2. **把变化封装为独立的单元**（Patch、Preset、Delta）
3. **让差值可组合、可逆、可审计**
4. **在运行时解析差值，而非编译期**

### 7.2 与 Nop 平台的呼应

有趣的是，DeepSeek Harness 的这些设计，与国内的 Nop 平台（基于可逆计算理论）有着惊人的相似：

| 维度 | Nop Platform | DeepSeek Harness |
|------|--------------|------------------|
| 理论基础 | 可逆计算 | Cordis（可逆副作用） |
| 差值单元 | Delta 模型 | Patch / Preset |
| 组合方式 | Delta 链叠加 | Scope 链遮蔽 |
| 逆转机制 | 可逆计算 | Effect 解药 |
| 目标 | 软件构造自动化 | Agent 能力组合 |

两者从不同的起点出发（Nop 从模型驱动，DSH 从插件运行时），却收敛到了相似的设计空间。这或许证明了**差值思维是软件构造的必然归宿**。

### 7.3 展望：差值即智能

如果说上一篇文章我们得出“插件化不是技术选择，而是让软件获得生命的方式”，那么这篇文章的结论更进一步：

**差值不仅是软件构造的技术，更是智能组合的语法。**

大语言模型的本质是概率分布的差值（微调 = 基础模型 + LoRA 差值）。Agent 的本质是能力的差值组合（Agent = 基础设施 + Preset 差值）。

**从某种意义上说，智能本身，就是差值的艺术。**

当我们可以精确地定义、组合、逆转差值时，我们就获得了创造智慧的“乐高积木”。

DeepSeek Harness 让我们看到了这种可能性的工程实现。虽然它还在早期（v0.1.0-rc.5），虽然还有诸多不完善，但它指明的方向——**以差值定义系统，用插件组装智慧**——或许就是下一代软件架构的范式。

## 结语

这篇文章从差值思维出发，连接了微积分、Git、可逆计算、道德经，最终回到 Agent 架构。

核心结论只有一句话：

> **Y = X + ΔY：一切系统，都是基础与差值的叠加。**

理解了这一点，你就理解了 DeepSeek Harness 的架构精髓，也理解了软件工程的未来方向。
