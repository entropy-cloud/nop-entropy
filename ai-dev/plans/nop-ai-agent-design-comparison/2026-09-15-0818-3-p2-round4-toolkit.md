# P2 round-4 toolkit 工具系统语义修复（nop-ai-toolkit）：UpdateTodosExecutor 全局表 / executeParallel 忽略 maxConcurrency / SkillExecutor load 空操作 / SSRF 传输层未接线

## Current Baseline

- 来源：deep-audit round 4 登记、roadmap `## Follow-up Backlog` 尚未勾选的 4 项 P2 项（全部经 live repo 复核，HEAD `9cbf684d88`，2026-09-15）：
  1. **`UpdateTodosExecutor` 进程级 static 全局 todo 表 + `getListKey` 恒返回常量**（nop-ai-toolkit `io.nop.ai.toolkit.tools.UpdateTodosExecutor`）：`:19` `static final Map<String, List<TodoItem>> todoLists` 进程级共享、`:54-56` `getListKey` 恒返回 `"default"`——所有 agent session/chat 共享一张表，A 会话 write 空列表会清掉所有人列表；多租户部署 = 会话间数据泄漏 + 破坏性跨会话写入。
  2. **`ToolManagerImpl.executeParallel` 读取 `maxConcurrency` 后从不使用**（nop-ai-toolkit `io.nop.ai.toolkit.manager.ToolManagerImpl`）：`:69-96` 所有并行工具调用同时提交无并发上限，`IToolManager` javadoc 将其作为真实契约；agent 发出大量并行调用时无界 fan-out 资源耗尽。
  3. **`SkillExecutor` "load" 动作空操作报成功**（nop-ai-toolkit `io.nop.ai.toolkit.tools.SkillExecutor`）：`:76-101` `handleLoad` 仅验证技能目录存在即返回 "Skill loaded successfully"，无内容/无状态变更，agent 误信技能已加载。
  4. **SSRF 传输层权威防护从未接线**（nop-ai-toolkit `io.nop.ai.toolkit.tools.ssrf`）：`SsrfGuardDnsResolver`（防 DNS rebinding/内部地址解析，`:34`）全仓仅测试引用；`HttpRequestExecutor`/`GraphqlQueryExecutor` 只做 pre-flight `SsrfAddressGuard.validateHost`（IP 字面量 + 黑名单），真实主机名（`*.internal`/rebinding 域）放行后由标准 client 解析直连内网；javadoc 自述 "authoritative enforcement lives in SsrfGuardDnsResolver at the transport level" 与实际装配矛盾。
- 归属模块：nop-ai-toolkit（全部 4 项，同一工具执行面）。
- 验证面：运行时行为修复，涉及 `./mvnw test -pl nop-ai/nop-ai-toolkit -am`；owner doc `ai-dev/design/nop-ai-agent/04-tool-invocation.md`、`nop-ai-tool-filesystem-design.md` 及 `docs-for-ai/03-modules/nop-ai.md`（bash opt-in 先例）需同步。

## Goals

- `UpdateTodosExecutor` 的 todo 表不再进程级全局共享——按 session/会话作用域隔离（多租户不泄漏、A 会话写空列表不清 B 会话），或显式裁定会话作用域契约。
- `ToolManagerImpl.executeParallel` 真正执行 `maxConcurrency` 并发上限——并行工具调用受控 fan-out，`IToolManager` javadoc 契约兑现。
- `SkillExecutor` "load" 动作有真实语义——实际加载技能内容/状态变更（或显式 fail-fast 声明不可加载），不再空操作报成功。
- SSRF 传输层权威防护接线——`SsrfGuardDnsResolver` 被 HTTP 工具执行路径在传输层消费（DNS 解析拦截 rebinding/内部地址），或显式裁定不可接线并消除 javadoc 矛盾。
- 每项配套回归测试（正确结果断言，非仅"不报错"）；owner docs 同步；`node ai-dev/tools/check-doc-links.mjs --strict` 0 error。

## Non-Goals

- 不新增 sandbox 实现（Host/Docker 沙箱既有 opt-in 装配语义不变，不重接 bash 默认装配）。
- 不处置本轮 roadmap 其余未勾选项（core/api call-path 契约、可靠性面、agent/gateway/shell/service/coder 等 P2/P3 项，另开计划）。
- 不运行 mvn 全量构建；不改 `IToolManager` 公共接口签名。
