### 抽查批次裁定（roadmap 1.3「C1 C3 C6 + 抽查」的操作化）

- **归档豁免**：审计 prompt 归档规则「每个维度一个文件」对本批次显式豁免一次，依据 = roadmap 1.3 的抽查裁定（Rules：工作项 plan 拥有实现细节）。文件名 `C2-C9-spot-checks.md`（内含 6 个维度节），closure audit 按本节结构验收。
- **文件结构**：文件内每维度一个 `## C{N}` 节（C2/C4/C5/C7/C8/C9 各一）；复核结论与最终保留项**按维度分套**（`## C{N} 复核结论` + `## C{N} 最终保留项`），与全维度文件同标准（13 字段/条目、≥10 行）。
- **派发装配**：共享前缀 + 6 个维度正文**全文**（不做裁剪版）+ F1–F11 缺陷族画像表 + 抽查 overlay——overlay 指令：按基线/补充 grep 圈定站点做定向核对；各维度正文的产出物清单降格为「仅覆盖抽查站点的清单表」，不要求全量盘点；覆盖声明节显式列出「已核对站点 + 圈定依据 + 未盘点面的声明」。
- **站点圈定**：C2/C4/C5 用附录 C 基线 grep；C7/C8/C9 用补充 grep（Phase 1 生成，写入基线文件）：C7 = `scheduleAtFixedRate|scheduleWithFixedDelay|new Timer|Timer\(|metric|gauge|ledger|history`；C8 = `IBlockingQueue|QueueOverflowPolicy|ArrayBlockingQueue|LinkedBlockingQueue|offer\(|put\(|capacity`；C9 = 每记录热路径调用点（`invoke\(|map\(|flatMap\(|filter\(|process\(` 沿 sql 展开管线与 flow 算子路径）+ owner doc 规模声明路径。
- **深挖与复核粒度**：均按**维度粒度**——深挖第 2 轮如触发，仅对抽查批次中有发现的具体维度续派（追加节按 `## 深挖第 N 轮追加（C{N}）` 组织）；复核按维度分套派发或单代理分节判定均可，判定引用编号规则不变。
- **拆分 fallback**：若单子代理输出超长或触发压缩退回，允许按维度拆为多个子代理（每维度一份产出，分节追加进同一文件，append-only）；Fraud-example 面在抽查批次中仅核对基线命中站点。

- {MODULE} 替换口径：{MODULE} = 单元标识 `nop-stream-orchestration-thin`（仅用于叙述与归档命名）；派发 prompt 中以该标识叙述审计对象，并**显式附 3 个模块路径**（`nop-stream/nop-stream-flow`、`nop-stream/nop-stream-sql`、`nop-stream/nop-stream-fraud-example`）与 2 个 owner doc 路径，不做字面路径替换。
