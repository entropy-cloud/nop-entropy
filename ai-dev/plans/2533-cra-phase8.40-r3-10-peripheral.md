## Purpose

关闭 R3-10 批的 6 项已确认 live 缺陷工单（P1×2：cra-index :314/:315 live 2026-11-05 回读均 open 且批次列=R3-10；P2×4：cra-index :475 P2-G90 束批次=R3-10 修裁决）。核心结果面有六：

①**W-01 JavaScriptWorker 生命周期族（P1，C1-002 族主；future-永不完成族第 6 例；三失效层修复验证须全覆盖）**——`JavaScriptWorker.execute`（live :98-103）检查 `closed`（:99）与入队（:102）非原子：调用方通过检查后被抢占，worker 完成 `run()` finally 终局序列（:310 `closed=true` → :311 `cancelAllTasks()` 排空 → :312 关 context → :314 `executeThread=null`）后调用方才入队——任务永久无消费者，`schedule`（:121-130）返回的 future 永不完成；消费链 `DynamicJsLoader.transformToSystemJs`（nop-web :127-131）以 `FutureHelper.syncGet`（nop-api-core :158-175）无显式超时等待——调用线程无限阻塞，停机期请求线程滞留阻碍优雅停机。失效层②（CL-001 吸收，路由侧）：`run()` 中 `init()`（:281）抛错即线程死亡，`JavaScriptService.invokeAsync`（:75-101）按 least-waiting 路由（:86-100）无存活检查——被路由到死 worker 的任务同样永久搁浅（复核修正：仅在各活队列非空且其为 least-waiting 时吸入）。失效层③（CL-002 吸收，容量侧）：`taskQueue` 无界 `LinkedBlockingQueue`（:54）无溢出策略。伴生面（CL-201）：FUNC_REINIT 分支（:142-144）先 `safeClose` 旧 context 再 `init()`，init 失败后 `globals` 悬挂指向已关闭 Context。批行 exit criteria 明文修复方向 = W-01 停机拒绝语义（R21 纪律对齐——搁浅 future 必须异常完成交付，禁止永久挂起）。

②**W-02 IDEA 插件调试会话 socket 通道从不关闭（P1，C6-001）**——`XLangDebugConnector.destroy`（live :49-51）仅 `clientFactory.destroy()`（工厂自有 timer/executor 线程资源），从不关闭通道：`connect()`（:53-55）不持有 proxy，平台通道级关闭契约 `IRpcProxy.proxy_destroy()` → `SimpleRpcClient.close()` → `SocketClient.close()` 在插件主源码零调用——每次调试会话确定性泄漏 1 fd，Disconnect 场景（debuggee 存活，双侧 `readTimeout=0`[:28]/`idleTimeout=0`）额外钉死 1 个 recv 池线程 + 1 条活连接；debuggee 被杀子场景经 autoReconnect 退化为执行器已 shutdown 语境下的无限重连僵尸循环（C6 复核精确化注记）。修复方向（批行明文）= socket 配对 close，参照 `TestRemoteDebugger.tearDown`（:140-146：clientFactory.destroy/server.stop/safeDestroy——动作齐全零断言的唯一配对参照），顺序为先关通道后关池。

③**W-03 ProjectFileHelper 静态 Map 以 Project 为键无移除（P2，C1-004 族主吸 C6-003 别名；cra-index :475「W-03=R22 成员」家族标注）**——`nopVfsPathCaches`（live :49 static CHM）唯一写入为 `getCachedSearchResult` computeIfAbsent（:174-175），全文件无任何 remove：关闭的项目对象图（Project 服务图 + 全量 VFS 路径集）被静态强引用永久滞留，IDE 进程级缓慢单调泄漏。修复方向 = 弱键/项目关闭钩子二选一（C6-003 建议最简闭合 = `NopProjectService.dispose()` 追加 remove）。

④**W-04 XLangDebugger 挂起交接非原子（P2，C1-001）**——`doSuspend`（:472-482）置 per-thread 标志（:478）→ 全局 `suspended=true`（:479）→ `monitorWait`（:481）；`monitorNotify`（:195-204）在锁外清 `suspended`（:197）后锁内 signal（:198-203）——命令线程的清标志落在 ：479 与 ：535（`monitorWait` 守卫读）之间时 signal 丢失，`monitorWait` 整块跳过，`thread.setSuspended(false)`（:549 finally）永不执行——幽灵挂起项/吞挂起（后果限调试会话，下次真实挂起自愈）。修复方向 = 标志复位无条件化或 doSuspend 与 monitorNotify 统一 monitorLock 临界区（恢复 signal-before-wait 锁内条件重查兜底语义）。

## Risks And Rollback

- **红① 概率 loop-捕获形态的必红可靠性风险（本批最大执行风险）**：搁浅窗口 = worker 终局序列时长（cancelAllTasks+GraalVM context safeClose，毫秒级）——提交轮次放大下命中可靠但非确定；如红跑未捕获（窗口未命中），按 2531 概率红先例升级放大（提交轮次/提交线程数/关闭轮次）留痕，禁静默改判；**orTimeout 假绿陷阱（裁定⑥ 强制输入）**：断言形态错误会把搁浅 future 的 TimeoutException 误读为「异常完成即绿」——红① 驱动器评审必查项；回滚 = execute 复查单点可逆，红① 防「复查存在但未接线」退化。

- **W-02 sink 的模块边界与验证盲区风险**：connector 物理迁移改变其包坐标——plugin 侧 import 改造为 Gradle 面，**本环境无法编译验证 plugin（Gradle+IntelliJ 平台依赖）**：plugin 侧 diff 极小化（import 两处零语义）+ 结构审查留痕 + 如执行环境 gradlew compileJava 可行则补验留痕、不可行则验证盲区如实登记（CL-301 通道③ 同源约束——禁伪验证）；如 draft review 认定迁移破坏模块边界——回退通道③（工单行登记+验证盲区声明）而非强行 sink；回滚 = 新文件迁回+import 还原，红② 保留为配对行为钉（迁移与否不影响其断言形态）。
