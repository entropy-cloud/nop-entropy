## Purpose

关闭 R4-02 批的 7 项已确认 live 缺陷工单（全 P2——cra-index :387 P2-G02 束行 + :388 P2-G03 束行 live 2026-11-07 回读批次=R4-02 修裁决；判级权威 = merge-adjudication §五 P2 表 7 行[含 FAM-2 族行]）。核心结果面有七：

①**W-01 StreamOpsHttpServer 提交端点无上界 readAllBytes（C5-004，族主吸 C8-008）**——`handleSubmit`（live :399）以 `new String(exchange.getRequestBody().readAllBytes(), UTF_8)`（:405）读取请求体：无 Content-Length 校验、无限量读取——单请求即可 ≈3× body 峰值物化（字节→String→JSON 解析树）击穿 coordinator 堆（连带你承载的全部作业协调面）；`JobSubmissionSpec`（runtime `ops/JobSubmissionSpec.java:26-28`[F3 订正——初稿误标 core/protocol；字段 jobId/pipelineFactoryClass/params 亲证一致]）仅 jobId/pipelineFactoryClass/params 三字段，1MB 量级上限即可闭合；http worker 池有界（`newFixedThreadPool(4)` :127——只限并发不限单体）；认证边界（loopback 零认证/非 loopback token）不改变「合法调用方单请求打爆堆」。修复方向 = **读取前上界预检 + 超限 typed 413 拒绝**（审计建议：Content-Length 预检或按限额 bounded copy——形态与限额值归 Phase 1 裁定；超限拒绝与既有结构化 400/409 错误面契约一致）。Phase 1 裁定项：预检形态（Content-Length vs bounded read vs 双检）+ 限额值与配置化 + chunked 无 CL 请求的处置 + typed 错误码落点。

②**W-02 timer mail 无去抖 + TaskMailbox 无界（C5-005，族主吸 C7-004/C8-004）**——`ProcessingTimeServiceDriver.run()`（live :118-132）每 tick(100ms) 检查 `hasProcessingTimeTimersDue` 即无条件 `mailbox.put(Mail.control(fireDueTimersOnTaskThread, ...))`（:123）：无「已 pending 即跳过」去抖；`TaskMailbox` 双 `ConcurrentLinkedQueue`（:40-41）无容量无溢出策略——任务线程在数据面背压点长时间不到达安全点时（慢 sink 是流的**正常**运行态），driver 以 10Hz 无限投递（同 runnable 每 tick 新建 Mail+CLQ 节点），≈864,000 封/天慢性堆增长且每封执行时 TreeMap 多为空（纯冗余）；本地/嵌入式模式无 liveness 兜底。修复方向 = **driver 侧 pending 去抖**（自持在途标志或查邮箱深度，同 runnable 在途期间跳过投递——审计建议①）或 **TaskMailbox 接入平台 `QueueOverflowPolicy`**（CONTROL 类满时丢重复+计数——审计建议②；形态归 Phase 1 裁定，预设① 最小改动）。Phase 1 裁定项：去抖载体与状态归属（driver AtomicBoolean vs mailbox 深度查询）+ 与 fire 幂等性的组合行为（fire 是幂等读 TreeMap——去抖不改变触发语义）+ 邮箱无界本体的处置边界（去抖后 10Hz 源已闭合，mailbox 上界是否仍需接入 QueueOverflowPolicy）。

## Risks And Rollback

- **W-01 上界误杀风险**：限额值过小可拒绝合法大 params 提交——限额值与配置化归裁定 A 定夺（JobSubmissionSpec 三字段 1MB 量级论证+sizing 依据在案）；回滚 = 预检分支单点可移除（恢复无上界读取），红① 防「预检存在但 chunked 路径绕过」退化。
- **W-02 去抖语义风险**：在途标志窗口内的 timer 触发延迟至下一 tick——fire 幂等性（读 TreeMap）与 100ms tick 粒度论证在案（延迟上界 = 1 tick，与既有 tick 采样语义同量级）；owner doc :24 fail-fast 语义零回退锚；回滚 = 去抖标志单点可移除，红② 防「标志存在但 put 未守卫」退化。
- **W-03 升级出口的恢复语义风险**：升级出口（failJob/注销）改变了「无限重试等待恢复」的既有语义——N 轮阈值与出口形态归裁定 A 定夺；abort 门控与恢复 CLEARED 路径为既有正确设计零改写（TestCheckpointAbortMarkerCleanup anti-hollow pin 零回退锚）；回滚 = 上界/出口分支单点可逆，红③ 防「上界存在但出口未接线」退化。
- **W-04 形态分叉风险**：三选一裁定决定 diff 形态与 owner doc 落账面——形态② 的验算如 estimatedItemSize 估算失准可误拒合法 plan（阈值与 fail-fast 边归裁定 B 定夺，对齐裁定② 参数纪律）；回滚 = 验算点单点可移除（恢复硬编码 defaultLocalBudget 附加），E2 钉防「验算存在但 Generator 未接线」退化。

- **W-06 清理时序风险**：submit 拒绝后立即 remove 与并发 cancelTask/位移逻辑的交错——条件 remove（remove(key, runningTask)）与 CAS release 为既有 build-failure 形态（并发安全先例）；deployTask 异常传播面调用方处置核对归裁定 A；回滚 = 两 catch 清理单点可逆，红④ 防「清理存在但指标前置未修」退化。
