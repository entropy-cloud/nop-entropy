关闭 R3-02 批的 10 项已确认缺陷（P1×3 + P2×7；cra-index P1 open 三行 :295/:296/:297 live 2026-11-01 回读全 open 且批次列=R3-02；P2-G74 行 :458 七成员随批收敛；5.2 单元 P1 台账三行全部在本批收敛）。核心结果面有十：

①**MA-01 DB 行协调原语 fencing 纪律族三子批（P1，C2-001 主 + C2-002/C2-004/C2-007/C2-102 吸收）**——nop-sys-dao 三类协调原语五站点以「非条件写或无 fencing 写」决出协调结果：过期锁行删除缺 holderId 条件（C2-001：竞争者 B 的删除按 lockName+lockGroup+version=0 命中并删掉竞争者 A 刚插入的新锁行——重建行 version 恒 0 使版本防护失效，A/B 双方各自认为持锁，互斥无声破坏；同文件 releaseLock/tryResetLease 两处已修且注释言明根因，本站点为 F3 漏网）；tryResetLease 成功不回写内存 version（C2-002：DB v+1 而内存实体仍 v——第二次续约起必然失败、isHoldingLock 恒假、releaseLock 删不掉；现无生产周期续约调用方为潜伏缺陷，携激活回升条款）；changeLeader 无 CAS fencing（C2-004：过期 leader 双 follower 同轮询周期抢占，`orm_disableVersionCheckError(true)` 后写覆盖先写——双节点以相同 epoch N+1 同时当选瞬态双主）；tryRenewLease 无条件续期（C2-007：stale leader 可延长对手租约）；事件认领一次性租约不续期 + 完成写无 fencing（C2-102：消费 > leaseTimeout(默认 10s) 时第二节点 CAS 接管，先完成方 `updateEntityDirectly` 直写覆盖接管方租约信息——双节点并发处理同一事件，队列单投递语义违约）。

②**I-01 mergedStore COW 发布（P1，C1-001）**——已发布 `mergedStore`（volatile）在读线程并发期间被原地结构修改：`genBizObjFiles` 恢复路径 `publishedMerged.merge(moduleStore)` 与 `genViewFile`/`genPageFile` `addToMergedStore` 对同一已发布实例做结构修改，底层 `ResourceTreeNode.children` 为普通 TreeMap 懒初始化无同步——VFS 请求线程并发遍历读到撕裂树（丢节点/未定义行为），违反类注释自声明的只读发布契约。

③**I-02 DurableSubscription cancel×subscribe 复合序列（P1，C1-002）**——cancel 的「remove→判空→remove 键」复合序列与 subscribe 的 `computeIfAbsent+add` 交错无互斥：T1 摘除 topic 键时把 T2 刚注册的订阅整个从 map 摘除（且 `getConsumers().remove(topic, new CoWA())` 因 list 非空失败，轮询集合仍含该 topic）——此后事件在 invokeDurableConsumers 处 warn 后置 PROCESSED 静默丢弃，订阅者孤儿化。

## Risks And Rollback

- **MA-01 条件写的行为面风险**：条件更新谓词选取错误（如 expireAt 时钟偏移）可能造成「该接管的不接管」——谓词以 DB 行自身字段为界（leaderEpoch/expireAt 旧值）不引入外部时钟依赖；tryResetLease 回写改变 EntityResourceLockState 消费面语义（kernel ResourceLock 透传方零改动核对为前置）；回滚 = 各子批 SQL 条件行单点可逆，红①四钉（互斥/续约/fencing/双 follower）防形态漂移。
- **MA-02 无锁化的可见性/锁序风险**：命中路径去 synchronized 后 miss DCL 的可见性依赖 volatile 引用（保留面核对为前置）；锁序若因 DCL 重入变化将打红 TestInMemoryCodeCacheDeadlock（零回退钉即防）；反向钉死改写若口径过松（纯删断言）将失去保护力——行为等价断言目标由裁定④锁定，禁纯删形态。
- **MA-03 removalListener 副作用风险**：Caffeine 驱逐回调线程执行 on-unload XPL 引入回调路径耗时/异常面——代价与预算论证为 Phase 1 放行前置（勘误 9 条款）；驱逐与手工 clearForTenant 的并发双路径幂等性须论证（clear 幂等先例 DynCodeGen.destroy :97-113 在案）；回滚 = listener 注册单点可逆，红⑤驱逐钉防漂移。
- **I-03 唯一索引的存量数据风险**：存量库若已有重复 moduleName 行，加唯一索引将失败——升级 DDL 须含重复行预检/清理路径（裁定⑧ DDL 落点条款）；唯一索引违反的错误转译若直接暴露 DB 异常将改变用户可见错误面（裁定⑧转译形态定夺）；再生成通道若产出生成物漂移将污染 diff——生成物一致性核对为组 D 显式项；回滚 = orm indexes 段单点可逆 + 再生成复原，红⑧钉防「索引存在但应用层检查被误删」退化。
- **I-04 删除失效的放大风险**：模块级删除触发全量 reload 若在删除事务内同步执行，将拉长管理操作耗时并引入删除-重载竞态窗——作用域定夺（裁定⑨）与异步化/同步化取舍为 Phase 1 前置；已删模型的在途请求行为语义（快速失败 vs 完成旧模型）须声明；回滚 = 钩子方法单点可逆，红⑨三面钉防漂移。
- **I-05 超时取值风险**：超时过短将把慢消费者误判失败（重复消费面——at-least-once 语义下可接受但放大）；leaseTimeout 同参形态与 MA-01 子批③续租窗口耦合（超时 > 续租窗口则 fencing 先于超时生效——协同矩阵论证）；回滚 = 等待点单点可逆，红⑩钉防退化。
- **红⑩挂死红的可复现性风险**：缺陷态为确定性悬挂（stub 消费者返回未完成 future 确定性构造，非竞态红），红证稳定；风险在测试自身超时设计（缺陷态断言必超时红——钉的失败模式是超时而非断言失败，须给足但有限 timeout 并在钉内注释失败模式语义[沿 2522 红④先例]）。
- **同文件多成员交叉风险**：SysDaoMessageService 承载 I-02/MA-06 sys 侧/I-05 三成员、InMemoryCodeCache 承载 I-01/MA-02 两成员——diff 分组登记防混（Phase 2 组 B/组 C 显式项），红钉逐成员独立可跑，防「A 成员修复回退时连带打红 B 成员钉」的归因混淆。
- **上游链环境噪声风险**：双通道命令触达上游闭包（nop-core/nop-kernel/nop-cluster-core 等），已知 flake 两面有本批起草期三联实录（勘误 5）——三联裁定执行并留痕，不得静默重跑或跳过。
