## Purpose

剖析平台骨架模块（nop-core / nop-xlang / nop-xdef / nop-dao / nop-graphql / NopIoC）如何协作支撑「可逆计算」在运行时的执行，产出一份分析文档，为 A4（GraphQL 引擎与服务层）和 A5（业务模块矩阵）提供核心引擎层面的参照。

## Current Baseline

**核心引擎模块已存在且可用：**

- `nop-kernel/` — 代码生成（nop-codegen）、XLang（nop-xlang）、核心 API（nop-api-core）、基础工具（nop-commons）、XDef（nop-xdefs）、核心资源/VFS（nop-core）
- `nop-core-framework/` — IoC（nop-ioc）、Config（nop-config）、Boot（nop-boot）、Plugin
- `nop-persistence/` — DAO（nop-dao）、ORM（nop-orm）、EQL（nop-orm-eql）、ORM 模型（nop-orm-model）
- `nop-service-framework/` — Biz（nop-biz）、GraphQL（nop-graphql-core / nop-graphql-orm）

**关键实现锚点（source-anchors.md）：**

- `IOC-001`: `ClassModelBuilder.java` — private 字段不会成为可靠注入点（与 Spring 的关键差异）
- `IOC-002`: `AppBeanContainerLoader.java` + `ModuleManager.java` — 模块通过 `/_module` 发现，app bean 按 `app.beans.xml` 加载（无注解扫描）
- `IOC-003`: 平台内置 bean 广泛使用 `nop*` 命名约定
- `EXT-002`: `XDslExtender.java` — Delta 展开与合并执行链
- `EXT-003`: `DeltaResourceStore.java` — VFS 分层资源解析
- `EXT-004`: `DslModelParser.java` + `INeedInit.java` — 模型解析与初始化链
- `VFS-001~006`: Delta 层式 VFS 解析全链路
- `DQL-001~006`: DQL/QueryBean 核心模型与 EQL 执行链
- `GQL-001~008`: GraphQL 自动暴露与 OrmFetcher 链
- `CFG-001`: `ConfigStarter.java` — 配置系统加载链
- `MOD-001~005`: 模块发现与管理机制

**已有的对比/分析资料（可复用）：**

- `docs/theory/lowcode-ioc.md` — 低代码 IoC 讨论
- `docs/theory/nop-graphql-design-innovation.md` — GraphQL 设计创新
- `docs/compare/` — 与 Spring 等框架的既有对比

**主要缺口（本 plan 要补齐）：**

- 缺一份把 core → xlang → xdef → dao → graphql → ioc 串成「运行时如何执行可逆计算」的引擎级综合剖析
- 缺 NopIoC 与 Spring 在工程层面的系统性差异（字段注入可见性、无注解扫描、beans.xml 发现、AOP 机制差异）
- 缺联网对标 Spring（Boot/Context）、Quarkus、Micronaut、Helidon 的 IoC / 核心抽象 / 启动模型对比

## Scope

### In Scope

- `nop-core`：核心抽象（`ICoreObject`、资源/VFS 模型、`JsonTool` / `ConvertHelper` / `StringHelper` 等统一入口）
- `nop-xlang`：DSL 解析与 Delta 合并执行链（`XDslExtender`、`DslModelParser`）、xpl 模板与 xlib 标签库的编译期元编程
- `nop-xdef`：元模型定义（`xdsl.xdef`、各领域 schema）、XDef 驱动的解析与校验
- `nop-dao` / `nop-orm`：ORM / EQL 执行模型、DQL/QueryBean 抽象、租户隔离机制
- `nop-graphql`：GraphQL 引擎核心（`IGraphQLEngine`、`OrmFetcherBuilder`、BizModel 自动暴露入口）。**边界说明**：本 plan 覆盖引擎机制（BizModel 如何注册为 GraphQL operation）；A4 覆盖 CRUD 约定（`CrudBizModel`、`@BizMutation`、xbiz、xmeta 字段可见性）。两者不重叠
- NopIoC：bean 发现（`/_module` + `beans.xml`）、字段注入可见性约束、配置注入（`@InjectValue` / `@cfg:`）、与 Spring 的关键差异
- 联网对标：Spring（Boot/Context）、Quarkus、Micronaut、Helidon 的 IoC / 核心抽象 / 启动模型

### Out Of Scope

- 可逆计算公理体系与理论证明（A1）
- codegen 模板与 `_gen/` 生成物的具体生成流程（A3）
- GraphQL API 自动暴露的完整链路与前端渲染（A4）
- 业务模块的功能矩阵与竞品对标（A5）
