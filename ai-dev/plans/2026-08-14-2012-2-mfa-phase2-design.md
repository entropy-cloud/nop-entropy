## Current Baseline

一期 MFA live 产物（W4-W8 已 closure audit 通过，2026-08-14 一期 milestone done）：

- 数据模型：`NopAuthMfaSetting`（userId PK / `mfaType` VARCHAR 列（`nop-auth/model/nop-auth.orm.xml:1060` 起，comment "totp/sms，空=未启用"）/ secret 加密 / status pending|enabled|disabled / bindToken / phone / lastVerifiedWindow）+ `NopAuthMfaRecoveryCode`（BCrypt codeHash）+ W8 两张 DB store 表（`NopAuthMfaChallenge`/`NopAuthSmsCode`），实体位于 `nop-auth/nop-auth-dao/.../entity/`
- **mfaType 非枚举**：字符串常量 `NopAuthConstants.MFA_TYPE_TOTP/MFA_TYPE_SMS`（`nop-auth/nop-auth-service/.../NopAuthConstants.java:42-43`）；白名单校验点至少含 `NopAuthUserBizModel.bindMfa`（:135 硬编码两值校验）与 `LoginServiceImpl`（:465 challenge 分支）——W14 因子扩展的枚举化裁决与白名单更新清单是本设计输入
- 验证器与存储：`TOTPAuthenticator`（RFC 6238 + 防重放 lastVerifiedWindow，`nop-service-framework/nop-biz-auth-core/.../totp/`）；`MfaChallengeStore`/`SmsCodeStore` 接口在 `nop-service-framework/nop-biz-auth-core/.../mfa/store/`，Db/Redis 实现在 `nop-auth/nop-auth-service/.../mfa/store/`，`MfaStoreProvider` collect-beans name-prefix 声明式装配（`nopMfaChallengeStore_`/`nopSmsCodeStore_`，Redis bean `ioc:condition` 条件激活）；默认 `store-type=db`
- 登录链路：`LoginServiceImpl`（`nop-auth/nop-auth-service/.../login/LoginServiceImpl.java`）两阶段改造已落地——`ERR_AUTH_MFA_REQUIRED`（:319 密码路径 / :350 SSO/信道路径）+ `completeLogin` 公共方法（含 resetLoginFailCount/onLoginSuccess 分界裁决 + 合成 LoginRequest）
- 用户自助/管理 API：`NopAuthUserBizModel`（`nop-auth/nop-auth-service/.../entity/NopAuthUserBizModel.java`）bindMfa(:133)/confirmMfa(:243)/unbindMfa/generateRecoveryCodes/getMfaStatus/resetUserMfa（requireAdmin 运行时校验 + NopAuthOpLog 审计）
- 配置与错误码：`NopAuthConfigs`（`nop.auth.mfa.*`：enabled/store-type/challenge-expire-seconds/max-attempts/totp-issuer/totp-window-skew/access-code-expire-seconds/bind-expire-seconds；`nop.auth.sms-code.*`：enabled/expire-seconds/send-interval-seconds/daily-limit/ip-daily-limit/max-attempts/template-id/allow-register）+ `NopAuthErrors` MFA/SMS 系列
- 邮件通道（二期复用）：`IEmailSender`（`nop-integration/nop-integration-api/.../email/IEmailSender.java`）+ `TencentEmailSender`（`nop-integration/nop-integration-email-tencent/.../TencentEmailSender.java`，已存在）
- 扫码适配：`ScanLoginResult` mfaRequired/challengeToken/mfaType/loginType 可选字段 + `loginByScanAsync` try/catch 捕获（W6）
- 占位文档：`ai-dev/design/nop-auth/02-mfa-phase2-design.md`（11 行，2026-08-14 创建，仅规划范围声明）

## Goals

- `02-mfa-phase2-design.md`（或按粒度裁决拆分后的多文件）产出四主题完整设计：每个主题小节含设计结论、使用契约、拒绝了什么、与一期契约（W4-W8）的兼容性确认
- 操作级 MFA 主题：会话内敏感操作二次验证——请求级钩子机制选型（拦截点在 BizModel/GraphQL 层的落点裁决）、敏感操作清单的声明模型、与登录级 `mfaVerify`/challenge 链路的复用边界（一期两阶段流程零回归）
- 角色级强制策略主题：策略模型（存储/继承/评估）、角色 → 强制因子映射、与一期"全局开关（`nop.auth.mfa.enabled`）+ 用户级启用（`NopAuthMfaSetting.status==enabled`）"的兼容矩阵（三者叠加时的判定顺序）
- 因子扩展主题：`MfaType` 枚举化裁决（live 为 VARCHAR 列 + 字符串常量，非枚举；术语与形态由本设计裁定）+ 白名单校验点更新清单（供 W14-impl 消费）；WebAuthn/FIDO2 挑战/断言模型与绑定/登录链路设计；邮件验证码走既有 `IEmailSender` 的接线设计；外部 MFA 服务（Authy/Duo）评估结论并入或显式 deferred
- 可信设备主题：设备指纹模型 + 会话策略（"记住此设备"对 MFA 拦截的豁免语义）+ 绑定/解绑入口
- 产出 W12-impl ~ W15-impl 的设计→实施映射，供后续 impl plan 引用
