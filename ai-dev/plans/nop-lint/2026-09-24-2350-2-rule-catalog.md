## Purpose

规则库 62 条已带 metadata（version/category/autoFixable/source），但没有一个机器生成的、防漂移的**规则目录**文档；版本策略仍是字段约束没有收口成文（**引用归源 P2**："minimal version stamp + CHANGELOG convention starts in Wave 2" 是 **roadmap item 42 原文**；design 01 §2 原文为中文注释——"Phase 1 起即必填的最小版本戳（语义/severity/id 变更必须升 version 并记入规则库 CHANGELOG）；完整 semver 策略 Phase 4 收口"——两处时点表述不得混用，本 item 收口以 design 01 原文为锚）。本 plan 交付：(1) 生成器 `ai-dev/tools/gen-lint-rule-catalog.mjs`——扫描规则树，按 metadata 生成 `nop-lint/docs/rule-catalog.md`（确定性输出，重新生成 diff 为零即门禁）；(2) 版本策略收口（design 01 §2 增注：version 语义 = 规则语义面变更时递增；CHANGELOG 约定 = 规则头注承载逐条变更记录）。

## Current Baseline（live 核对 2026-09-24）

- 62 个 `.rule.yml` 于 `nop-lint/nop-lint-nop/src/main/resources/_vfs/nop/lint/rules/<category>/`，全部带 `metadata.version: "1.0"`（**version=="1.0" 断言在 `TestNopRuleSuites` L205-206/L216-217**；TestProductionRuleCount 只断言 count+id 集——P1 归属修正）；3 条 XNode XML 规则（nop-orm-mandatory-default/nop-xbiz-auth-not-sole-guard/nop-orm-unique-key）id 无 category 前缀。
- **字段面（P4 修正）**：`id`/`severity`/`message` 是规则 yml **顶层字段**；metadata 仅 `category/autoFixable/version/source` 四键且 source 为标量字符串（62/62 验证；design 01 §2 示例的 metadata.severity 列表形态在真实规则中不存在——生成器按 live schema 取数）。
- `js-yaml` 在 ai-dev/tools 依赖中可用（check-lint-coverage-manifest.mjs 先例）。
- design 01 §2 有"minimal version stamp + CHANGELOG convention starts in Wave 2"措辞，未见收口成文。

## Goals

1. 生成器：扫描 rules 树（**扫描根钉死 = `nop-lint/nop-lint-nop/src/main/resources/_vfs/nop/lint/rules/`**，P9——排除 target/classes 副本）→ **按目录名分组（P3 钉死；非 metadata.category——live 的 metadata.category 有 9 值碎片：api/api-contract、exception/exception-handling、nop/vfs-usage 同目录拆散，按 metadata 分组会拆散同目录规则）**，组内按文件名字典序；表格列 = id / severity / version / autoFixable / message / source（P4 live schema）；metadata.category 与目录名不一致的行在 note 呈现碎片值（显式承认而非掩盖）；输出 `nop-lint/docs/rule-catalog.md`；**确定性**（两次生成 diff 零）。message 含 `|` 或换行时生成器 fail-closed 报错（P7）。
2. **防漂移门禁**：生成器 `--check` 模式——重新生成并与在档文档**全文全等 diff（P8）**，不一致退出 1（规则增删改后必须重新生成目录才能过门禁）；**内嵌 `self-test` 正控子命令（P6，对齐 check-lint-coverage-manifest.mjs 先例与 Rule #24）**——篡改在档目录一行/删一条规则行必须被 REJECTED。`check-lint-rule-catalog.mjs` 为概念名（P10：单文件交付，--check 即门禁）。
3. 版本策略收口：design 01 §2 增注（**P5 reconcile 四点**：(i) 原文"记入规则库 CHANGELOG"的**载体显式收口为各规则头注**——不建独立 CHANGELOG 文件，62 条规则头注已是逐条裁定记录；(ii) 触发枚举原样保留"语义/severity/id 变更必须升 version"；(iii) baseline fingerprint 的库级聚合追溯由**目录再生成 diff** 承接（每规则 version + 目录 diff），头注服务 @SuppressWarnings 的 per-rule 可追溯；(iv) 保留"完整 semver 策略 Phase 4 收口"指针不关闭）。

## Non-Goals

- 不生成 HTML/PDF 等富格式（markdown 单一面）
- 不为 catalog 建 CI 独立 job（`--check` 模式挂接现有门禁习惯即可）
- 不改任何规则文件（version 递增是未来语义变更时的动作）
