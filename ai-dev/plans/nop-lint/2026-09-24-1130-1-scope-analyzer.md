## Purpose

落地 design 05 §2 的 scope 分析 v1：JavaParser 之上的作用域分析内核（作用域层级/作用域内声明/引用→定义解析/遮蔽判定）经 `SCOPE` capability 与 xscript `scope` 绑定接入 deep 档——机制与 item 32 的 metrics 完全同构（白名单变体 + 穿透链 + ServiceLoader SPI + 四态门控 + demo 套件），item 34 的 L3/L4 面可继续复用。

## Goals

1. `ScopeAnalyzer`（nop-lint-java semantic 包，JavaParser AST，item 30/32 同型）：作用域层级（block/method/class/catch/loop-init/lambda/**switch-block 单一作用域**——case 仅作 scopeKind 标签，跨 case 可见是 Java 语义，R1 D2 修复）、作用域内变量声明集合、标识符 → 定义解析（含外层链回溯）、遮蔽判定。
2. core `ScopeResolver` 接口（语义包，TypeResolver/MetricsResolver 同构）：位置键查询 `definitionOf(filePath,line,col)` → **定义处的字节偏移**（resolver 内部本就先算 bytePos，返回 byte 避免 core 侧新增 UTF-16→byte 逆变换——R1 A1 裁定；无定义是合法答案返回 null/-1？裁定：返回 `OptionalLong` 或 -1 哨兵实现期定但**必须显式区分**"无定义"与故障——故障抛异常）；`declaredNames(filePath,line,col)`、`scopeKind(filePath,line,col)`、`shadows(filePath,line,col)`；具名文件要求与 metrics 相同。
3. xscript `scope` 绑定（`scope.definition(node)` → NodeWrapper|null、`scope.declaredVariables(node)` → 名称表、`scope.shadows(node)` → boolean、`scope.kind(node)` → 字符串）：白名单变体注册（requires 含 SCOPE 才编译可见）、穿透链、无 provider/未具名 → gate DEGRADE。
4. ServiceLoader SPI + **CheckRunner 经 Discovery 拾取、RuleTestRunner 显式构造参数**（metrics 先例原样）+ 阶梯 SCOPE 闭合记录（metricsOpen 分支同型）。
5. demo RuleTester 套件（`deep-suites/scope-shadow`：变量遮蔽 demo 规则，expect 钉死遮蔽行）+ 四态门控测试（复用 TestMetricsBinding 形态）。

- TS 作用域（TS 侧作用域归 item 34 后续或按证据立项；v1 Java 面）

## Key Decisions（执行前裁定，审查确认）

1. **AST 选型**：JavaParser（item 30/32 先例）——Java 作用域规则（块级/方法/类域/catch 单变量/lambda 参数/for-init）在真语法树上有唯一判定。
2. **绑定的节点回传机制（R2 N1 同步后口径，算法见 Decision 7）**：`scope.definition(node)` 返回 **CST 侧 NodeWrapper**——binding 收到 resolver 返回的定义字节偏移后，从匹配节点经 parent 链上溯到树根，贪心下探搜索最小包含该字节的具名 CST 节点（binding 持 SourceMap + 根可达）；null = 无定义（合法答案）。
3. **绑定函数面 v1**：definition / declaredVariables / shadows / kind 四个（design 05 §2 的 getScope/variables/resolveDefinition 三行的可消费化投影；walkUp 已由 CST 侧 `node.ancestor(kind)` 覆盖，不重复提供）；`scope.upper` 链经 definition+shadows 组合表达。
4. **门控与阶梯**：SCOPE 走 resolver 自带 isAvailable + 具名文件（metricsReady 同型 gate + scopeReady 分支）；阶梯闭合记录 SCOPE（open = resolver live），与 METRICS 分支并列。
5. **遮蔽判定口径（R1 E1 Blocker 修复后）**：可见性按作用域种类分立——**类字段 = 类体全域可见（与声明顺序无关）**；局部变量/参数 = 声明点之后。内层声明 D 与外层已声明变量同名且该外层变量按上述规则可见 → shadows=true。同作用域重复声明不是遮蔽（Java 编译错误）；嵌套块 local-local 同名同为编译错误但可解析——**输入不预设合法 Java**（demo fixtures 可用非法源，判定不依赖合法性）。方向特例入测试矩阵：lambda 参数/catch 参数/for-init 变量可遮蔽字段、不可遮蔽外层局部（编译错误形态照样判定）。

6. **定义解析实现路径（R1 D1 裁定 + R2 N3 复用边界）**：**位置感知词法作用域归约**（item 30 DefUseChain 先例：零依赖、unresolved 显式 null、无 symbol solver/L2 依赖）；单编译单元 + 同单元类字段；跨类/外部名 → null（合法"无定义"）。**复用边界注记**：DefUseChain 是方法内装置，其两处语义**不得随用**——类体屏障（ScopeAnalyzer 的类字段域是新增面，极性相反）、lambda 体扁平并入方法作用域（ScopeAnalyzer 的 lambda 必须是独立作用域，参数为其声明、parent=外层作用域）；复用仅限机制层（位置感知词法走法、祖先链包含判定）。
7. **穿透签名与阶梯（R1 C1/C2 裁定）**：继续加参不收敛（run 为包内静态单一调用者；item 34 落地后如超 12 参再裁 context 对象）；`engageLadder` 探针循环同步排除 SCOPE（与 METRICS 同型，防双路闭合）；`XScriptCompiler.compile` 第三参从布尔改为 `Set<LintCapability>`（resolved requires 传入，CompiledRule 已有 resolveRequires），XML 路径 2 参永不注册的 Decision 7 先例对 SCOPE 重申；拾取面 = **CheckRunner 经 Discovery、RuleTestRunner 显式构造参数**（metrics 先例原样，F1）；CST 定义回传搜索用**贪心下探**（root 起逐层选包含子节点，O(depth×分支)，F2）。
