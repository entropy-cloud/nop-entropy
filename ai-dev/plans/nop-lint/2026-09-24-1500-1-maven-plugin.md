## Purpose

新建 `nop-lint-maven-plugin` 模块：`nop-lint:check` goal 绑定 validate phase，把既有 `CheckRunner` 管线接入 Maven 构建生命周期（design 03 §2.1）。零新语义——CLI 已有能力（profile/fix/baseline/exit code）经 Mojo 参数暴露。

## Current Baseline

- `NopLintCli`/`CheckRunner`（nop-lint-core cli 包）已实现 check 全流程：TargetScanner/RuleSetLoader/profile/fix/baseline/exit codes 0/1/2（TestNopLintCliExitCodes 钉死）。
- 发行形态裁定（item 18）：classpath 装配需 nop-lint-java（语言绑定）+ nop-lint-nop（规则资源）+ nop-treesitter——Maven 插件同理把这些作为插件依赖。
- 仓库无 nop-lint-maven-plugin 模块；根 pom 的模块列表需要注册。
- Maven 插件先例：仓库 `nop-codegen` 等无 maven-plugin 模块先例可抄（需按 maven-plugin-plugin 标准骨架：@Mojo 注解 + help goal 生成）。

## Goals

1. 新模块 `nop-lint/nop-lint-maven-plugin`：`CheckMojo`（goal `check`，defaultPhase=VALIDATE），参数 = targets（默认 `${project.basedir}` 下的 src）、profile、failOnError、rulesPrefix、fix/baseline 族参数透传。
2. Mojo 内部直接装配 `CheckRunner`/`TargetScanner`/`CliOptions`（复用 cli 包——零新管线语义）；exit 语义映射 Maven 途径：failOnError=true 时 error 级违规抛 MojoFailureException（构建失败），false 时仅 warn 日志。
3. 依赖形态（R1 1.1 Blocker 裁定）：**插件依赖 = nop-lint-core + nop-lint-java + nop-lint-nop**（nop-treesitter 传递）——插件 realm 类加载器看不到用户工程依赖（discoverDefaults 的 ServiceLoader 与 VFS 规则扫描都在插件 realm），"用户工程自带"形态被拒绝（需 @RequiresDependencyResolution + 动态类路径装配，不在 scope）。
4. 生命周期（R1 1.2）：Mojo execute 内复刻 CLI 形态——`CoreInitialization.initializeTo(REGISTER_COMPONENT)` + finally destroy（每次 execute 一对；多模块 reactor 安全，开销与 CLI 同量级）。
5. targets 语义（R1 1.4）：显式 target 不存在 = 硬错误（CLI exit-2 同义）；**默认 target（src/）不存在 = warn 日志 + 静默跳过**（reactor 内无 src 模块开箱即绿的 Mojo 适配，design 偏离随增注落档）；新增 `<skip>` 参数（默认 false）。
6. exit/失败映射（R1 1.5 完整矩阵）：error 违规 → failOnError=true 时 MojoFailureException；**baseline-check 有 stale 条目 → 同样 MojoFailureException（item 27 只减不增门禁经 Maven 通道保持）**；--write-baseline → 恒成功；内部错误 → MojoExecutionException；failOnError=false → 全部降级为日志（warn/error 区分）。
7. 测试骨架（R1 1.3）：harness 可用则用之；**fallback = install 后 ProcessBuilder 真跑 `./mvnw -q nop-lint:check` + fixture pom**（端到端退出标准在两个分支都成立）。

## Non-Goals

- 不做 incremental/缓存构建（item 43）；不做多模块聚合报告聚合
- 机器可读输出格式归 CLI 通道（item 39）——Mojo 渲染用 ConsoleReporter(PrintStream 桥接) 的 warn 日志面（R1 1.9，39 的 Reporter 接口不回收本 item）
- 不做 IDE 面（item 41）
- rulesPrefix 参数 = RuleSetLoader 内部测试面的显式升格（CLI 无此参数——R1 1.10，与 design §2.1 rulesPath 示例的差异随增注落档）

## Key Decisions（执行前裁定，审查确认）

1. **复用边界**：Mojo 只做参数装配 + exit 映射，管线语义零复制——`CheckRunner` 是唯一执行体（hollow 防线：Mojo 单测断言 CheckRunner 被真实调用且诊断数流入构建结果）。
2. **failOnError 语义**：true + error 级诊断 → MojoFailureException；true + 内部错误 → MojoExecutionException（exit 2 对应）；false → 一律仅日志（warn/error 级区分）。
3. **targets 默认**：`src/` 目录（`new File(project.getBasedir(), "src")`）；多 target 暴露为 File 参数列表。
4. **测试骨架**：maven-plugin-testing-harness（org.apache.maven.plugin-testing）版本对齐仓库 Maven 4 wrapper；若 harness 与 Maven 4 不兼容（spike 裁定），fallback = Mojo 参数装配单测 + NopLintCli 集成冒烟复用（CLI 与 Mojo 共用 CheckRunner 的等价性论证）。
