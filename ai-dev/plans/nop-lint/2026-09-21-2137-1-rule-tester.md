# RuleTester：JUnit RuleTestRunner + `.expect` 夹具格式（roadmap item 10）

## Current Baseline

以下事实均已对照 live repo（2026-09-21）核实：

- 引擎 v1 已落地（plan `2026-09-21-1420-1`，item 9 done）：`LintEngine.lint(List<RuleDslModel>, languageId|LintLanguage, source|LintTree)` → `LintResult(diagnostics, stats)`；诊断值为 `Diagnostic(ruleId, severity, message, SourceRange)`（`io.nop.lint.core.engine`）。
- **已知对齐缺口**：`Diagnostic.range` 是 `io.nop.lint.core.node.SourceRange(startByte, endByte)`（UTF-8 字节区间，不含行号），而 design 03 §4.2 的 `.expect` 期望字段为 `line/endLine`（1-based 源码行号）——两者之间的换算语义必须显式裁定，否则夹具断言无法成立。
- 规则加载已就绪（item 8 done）：`RuleDslParser.loadRuleModel(resourcePath)` 经 `ResourceComponentManager`（VFS + xdef 结构校验 + x:extends）加载 `fileType: rule.yml`；现存 core 测试规则夹具位于 `nop-lint/nop-lint-core/src/test/resources/_vfs/test/lint/rules/*.rule.yml`。**规则文件必须位于 `_vfs/` 之下才能经 VFS 加载**，design 03 §4.1 的目录示意（`src/test/resources/rules/...`）与该机制不一致，需按本 plan 裁定修正。
- 语言发现已就绪（plan 1420-1 Phase 1）：ServiceLoader 发现 `LintLanguage`，nop-lint-java 注册 `JavaLanguage`，id 大小写归一，未知 id 抛 `NopLintException`。
- `nop-lint-nop` 模块当前仅含 `package-info` 与 bootstrap 测试——它是 item 11（规则与规则夹具）的落点；本 plan 交付的 `RuleTestRunner` 按 design 03 §4.3 位于 nop-lint-core，供 core 与 nop 两处测试复用。
- design 03 §4 契约要点：valid 夹具零诊断；invalid 夹具逐条断言（ruleId + line/endLine + messageContains）；JUnit 启动器随 `./mvnw test` 执行；CLI 包装（`nop-lint test`）与 Maven `test-rules` goal 属 item 39/37（Phase 4）。
- design 03 §4.1 的 `suppressed.java` 夹具示例与 §4.2 的 `fix` 期望字段分别依赖 item 17（抑制）与 item 25（autofix），均在本 plan 能力面之外——必须显式裁定，不得静默忽略（Minimum Rules #24）。
- roadmap 硬约束（design 03 §4 / 08 §3）：每个 Wave-2+ 规则必须带 RuleTester fixtures，无 fixture 视为未完成——item 11（本组 plan 3）的直接前置。
- 尚不存在任何 `RuleTestRunner` 或期望文件解析类。

## Goals

- nop-lint-core 新增 `RuleTestRunner`（JUnit 5 启动器）：扫描约定目录结构 → `RuleDslParser.loadRuleModel` 加载规则 → 对每个 `.java` 夹具运行 `LintEngine` → 断言 valid 零诊断、invalid 逐条命中 `.expect`。
- `.expect` 期望格式 v1 落地（design 03 §4.2 的 `diagnostics` 子集：line/endLine/ruleId/messageContains），`SourceRange` 字节区间 → 1-based 行号换算语义显式并有测试。
- 夹具目录约定落地为 VFS 兼容形态，design 03 §4.1 路径示意按裁定回写。
- 对 v1 不支持的期望面（`.expect` 的 `fix` 字段）fail-closed 并有测试。
- 完成后 roadmap item 10 具备翻 `done` 条件（item 11 与里程碑 M2 的前置）。

## Non-Goals

- 10 条核心规则本体与 3 条 ast-grep 规则吸收（item 11，本组 plan 3 承接）。
- 抑制判定与 `@SuppressWarnings` 夹具（item 17 承接）。
- autofix 期望的执行面（item 25）；本 plan 仅对 `fix` 期望字段做显式拒绝。
- CLI `nop-lint test` 包装与 Maven `test-rules` goal（items 39/37）。
- 性能口径：runner 属测试基建，不设 JMH 基准，不进 plan 05 perf doc 基线体系（裁定：测试代码不参与性能基线）。
