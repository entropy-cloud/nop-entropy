# tsc bridge（roadmap item 20）：常驻 Node 进程 + program 缓存 + tsconfig-hash 失效 + 降级回退

## Current Baseline

以下事实均已对照 live repo（2026-09-22）核实：

- 依赖满足：item 20 deps = item 19（`done`，plan "2026-09-22-1045-1-ts-tsx-language-adaptation"）——`nop-lint-js` 模块已交付 ServiceLoader 发现的 `TypeScriptLanguage`/`TsxLanguage` parse 级绑定（grammar blob + `$`-expando identity，见 `nop-lint-js/src/main/java/io/nop/lint/js/TypeScriptLanguage.java`）与 CLI 扩展表（`TargetScanner` 的 `ts→typescript`/`tsx→tsx`）。当前 TS 侧只有语法级检查能力，无任何类型面。
- 设计权威：design 06 §5.3（方案 A：常驻 Node 进程调 TypeScript Compiler API——`initProject(tsConfigPath)` 建 program、`getTypeAtLocation(file, line, col)` 取节点类型、`isTypeAssignableTo(from, to)` 查兼容性）+ design 11 §3（L2 tsc bridge：秒级 program 加载 + 常驻 Node 进程；缓存后每查询 <5ms；挂接 = 进程复用 + program 缓存 + tsconfig hash 失效；档位 standard+）、§4（类型缓存键 = 文件内容 hash + tsconfig hash；tsc program 缓存额外受 tsconfig `include`/`paths`/`references` 影响）、§5（降级阶梯第 2 级 = L2 tsc bridge 退化为 TS 语法规则 + 计数；**禁止用 L1 结果冒充 L2**；降级必须记录 `degraded`，绝不静默）。
- 档位/capability 面 live 现状：`LintCapability` 仅 L1/L2 两档（`LintCapability.java:12-23`，L2 javadoc 明示 "not provided by any v1 profile"，未知 requires token 解析为不可满足）；`LintProfile` FAST/STANDARD 的 `capabilities()` 均只含 L1（`LintProfile.java` 的 `V1_CAPABILITIES`）；`LintEngine` 逐 requires token 校验（`LintEngine.java:101-108`，不满足即 skip）；skip 计数走 `LintStats.rulesSkippedByProfile`（`LintStats.java:66,164`）。`requires` 字段已由 item 22 落地（`RuleDslModel.java:31,109`，含 typeOf⇢`requires:"L2"` 门）——声明 L2 的规则当前在所有档位被 skip 计数，本 plan 交付后开始真实运行。
- Node 生态现状：`ai-dev/tools/` 有 node_modules（`@ast-grep/cli`、`web-tree-sitter`、`tree-sitter-java`、`js-yaml`），**无 `typescript` 包**；nop-lint 内无任何 Java→Node 常驻进程先例（进程管理、协议、崩溃恢复均为新建面）。
- 姊妹项边界：item 26（Java 侧 L2 symbol solver）deps = 本项——本 plan 建立的 L2 provider 挂接模式是其先例；item 31 = 降级阶梯 v2 + deep 档；item 43 = 类型缓存磁盘工件化/CI warm-up（design 11 §4 的磁盘层）。本 plan 只落进程内缓存与 item 级 degrade-to-syntax 回退。
- 硬约束适用：零平台改动（`nop-xlang`/`nop-core` 是 Protected Area，本 plan 全部工作在 nop-lint 模块 + `ai-dev/tools` Node 侧）；不修改 nop-treesitter 既有类；profile 永不拿 L1 冒充 L2（roadmap 硬约束 + design 11 §5）；功能缺失必须显式失败/计数，不许静默跳过（guide Minimum Rules #24）。
- 验证覆盖缺口：mission `verify` 键 `test`（`./mvnw -pl nop-lint/nop-lint-core -am test -T 1C`）**不覆盖 nop-lint-js 模块**——本 plan 的 JS 侧 Java 测试须显式运行 `-pl nop-lint/nop-lint-js -am test` 并记录（先例 = plan 2137-3 对 nop-lint-nop 的处置）。

## Goals

- 常驻 Node bridge：JS helper 脚本（`ts.createProgram` + checker 类型查询）+ Java 进程管理器（spawn/握手/请求-响应复用/崩溃检测与重启/每查询 deadline）+ 显式环境契约（Node 或 typescript 缺失时 fail-visible，不静默降级为语法检查）。
- program 缓存 + tsconfig-hash 失效：hash 覆盖 tsconfig `include`/`paths`/`references`/`files`（design 11 §4）；tsconfig 或参与 hash 的输入变化 → program 重建；进程内类型查询缓存。
- L2 供给接入档位体系：STANDARD 档在 tsc 可用时真实提供 L2（惰性初始化——仅当 `requires: L2` 的规则真实需要查询时才启动进程，design 11 §3 惰性原则）；FAST 档不提供 L2 → 该类规则 `skippedByProfile` 计数；降级路径（Node 不可用/查询超时/进程不可恢复）→ 该规则按降级计数并标记 `degraded`，绝不以语法级结果顶替类型级结果。
- 端到端证明（Minimum Rules #22）：真实 Node + typescript 的 round-trip 集成测试 + 一条 `requires: L2` 的 TS demo 规则经 RuleTester 管线验证 available/skip/degraded 三态。
- owner docs 回写（design 06 §5.3、design 11 §3/§4/§5 增注与 live 一致）+ roadmap item 20 状态回写（draft review 通过置 `planned`，closure audit 通过置 `done`）。

## Non-Goals

- Java 侧 L2（nop-java-parser symbol solver，item 26）；降级阶梯 v2 与 deep 档（item 31）；L3/L4（items 33/34）。
- 类型缓存磁盘持久化与 CI warm-up 工件化（design 11 §4 磁盘层，roadmap item 43）；编辑器 watch 模式（item 41）；GraphQL 侧挂接（item 38）。
- TS L2 规则批量与 PMD/EP 对标规则（items 29/35）；autofix（item 25）。
- tsserver/LSP 模式（design 06 §5.3 方案 B，未选用）；编辑器集成（item 41）。
- mjs/ast-grep 门禁的切换或下线（item 28 manifest 决定）。

## Phase 2 — L2 供给接入引擎：档位门、惰性挂接、降级回退（Decision + Fix + Proof）

Status: completed
Targets: `nop-lint/nop-lint-core`（`engine/` 包：`LintProfile`/`LintEngine`/`LintStats`）、`nop-lint/nop-lint-js`（resolver 接线）

- Item Types: `Decision | Fix | Proof`

- [x] **Decision（L2 provider 注入位）**：`LintProfile.capabilities()` 现为 enum 静态集（v1 = L1），tsc 可用性是运行时事实——裁定 L2 供给的注入位（profile 静态声明 + 引擎级可用性探测 vs provider 注册机制），不得破坏"档位是运行参数、同一规则库三档共用"契约（design 11 §2）；结论回写 design 11 §2/§3 增注。（裁定：**能力上限声明 + 运行时就绪门**——`capabilities()` 是档位上限（fast=L1；standard=L1+L2），引擎另需注入 `TypeResolver` 且其无副作用探测通过 + 运行对象具名文件路径；上限内不就绪 → 降级出口，上限外 → skippedByProfile。契约保持：档位仍是运行参数，规则库共用。）
- [x] STANDARD 档接通 L2：tsc 可用（Node + typescript 就绪）时 `requires: L2` 规则真实执行；惰性初始化——首个真实类型查询发生时才 spawn Node 进程（design 11 §3），无 L2 命中的文件零 tsc 成本。（`TscTypeResolver` 适配 `NodeTscBridge`：探测零副作用，桥与 program 在首个真实查询时启动；`typeOf` 约束经 `TypeQuerySupport`（per-run：resolver + 文件路径 + 源字节，byte offset→0-based line/UTF-16 col 经 `SourcePositions`）消费。）

- [x] 接线验证（Minimum Rules #23）：`requires: L2` 的 TS 规则在 STANDARD 档运行时 resolver 被真实调用（查询计数或调用标志断言）；同一规则在 FAST 档 `skippedByProfile` 计数断言；降级路径计数断言。（`TestL2TypeGate`：`FakeResolver` 查询计数器断言 queries==1（STANDARD 命中/不命中）与 ==0（fast-skip/门控降级）。）
