# Suppression v1：内联注释 + @SuppressWarnings（roadmap item 17）

## Current Baseline

以下事实均已对照 live repo（2026-09-22）核实：

- 管线位置（design 03 §1.1）：抑制判定位于 xscript 之后、`Diagnostic` 输出之前——当前 `RuleSetRunner` 直接产出诊断（`engine/RuleSetRunner.java:74,103-104`），nop-lint 主源码树无任何抑制实现（全量文件清单核对：无 Suppression 相关类）。
- Design 09 §2 内联注释 DSL 六形态（行注释与块注释均可）：`nop-lint-disable-next-line <rules>`、`nop-lint-disable-line`、`nop-lint-disable <rules>`、`nop-lint-disable`（全规则）、`nop-lint-enable <rule>`、`nop-lint-enable-all`；§2.2 语义：诊断 range 与注释作用范围**有重叠即抑制**（含多行诊断）；`disable`/`enable` 须配对，文件结束仍处 disable → `unpaired-disable`（info）；未命中任何诊断的 disable → `unused-disable-directive`（warning）。
- Design 09 §3 `@SuppressWarnings`（Java）三种值形态：`"nop-lint:<rule-id>"`（推荐）、裸 rule id（兼容）、`"all"`；作用范围 = 注解所在的类/方法/字段/参数**声明节点**。PMD/ErrorProne 别名值（`"PMD.AvoidUsingVolatile"` 等）依赖 manifest（06 §7），归 item 29——本 plan Non-Goal。
- 档位口径（design 11 §2 fast 行）：抑制判定 v1 全量（内联注释 + @SuppressWarnings）**不按档位裁剪**，FAST/STANDARD 均启用。
- 交互规则（design 09 §6）：每个诊断独立判定；被抑制的诊断不产 fix（v1 `report({fix})` 已被 item 14 显式拒绝，无冲突面）；RuleTester fixtures 不受 baseline/exemptions 影响（两者属 v2/item 27）。
- RuleTester 现状（design 03 §4.1 增注 + `testing/RuleTestRunner.java:47,50`）：suite = `<rule-name>.rule.yml` + `valid/*.java`（零诊断）+ `invalid/*.java` + 同名 `.expect`，fail-closed；「suppressed.java 类抑制夹具不属于 RuleTester 契约（roadmap item 17）」——**本 plan 必须给出抑制夹具契约**。
- 元诊断归属：`unused-disable-directive`（warning）/ `unpaired-disable`（info）为引擎生成的固定 rule id，非 `.rule.yml` 规则（无加载面）；「可关闭」旋钮依赖豁免配置，归 item 27——本 plan Non-Goal。
- `@SuppressWarnings` 提取需 Java CST 导航（注解节点挂接声明节点）；实现载体（core 通用抑制 provider 接口 + `nop-lint-java`（现有 `JavaLanguage.java` 绑定）实现 vs 其他落点）执行时裁定。
- 前置已满足：item 9（LintEngine minimal）done 是本 item 唯一路标依赖。

## Goals

- 内联注释抑制按 design 09 §2 全量落地：六形态 + 行/块注释 + 重叠语义（含多行诊断）+ `enable`/`enable-all` 恢复 + `unpaired-disable`/`unused-disable-directive` 产出。
- `@SuppressWarnings` 按 design 09 §3 落地：三种值形态 × 声明节点范围（类/方法/字段/参数）。
- 单调判定语义（design 09 §1）：诊断命中任一层有效抑制即不输出；被抑制诊断不进 `LintResult`。
- 引擎接线：抑制判定落在 design 03 §1.1 管线位（xscript 后、输出前）；抑制计数进入 `LintStats`（计数域可观测，不静默）。
- RuleTester 抑制夹具契约（Decision）+ 夹具组；端到端：同一规则同一源码，无抑制 → 诊断；有抑制 → 零该规则诊断 + 元诊断按场景断言。
- roadmap item 17 状态回写（draft review 通过置 `planned`，closure audit 通过置 `done`）。

## Non-Goals

- v2 层：规则集 YAML exemptions 与 baseline 文件 + CI stale 检查（item 27；design 09 §4/§5）。
- `@SuppressWarnings` 的 PMD/ErrorProne 别名值识别（item 29，manifest 未建）。
- `unused-disable-directive` 的关闭旋钮 / 抑制配置面（item 27 exemptions 承载）。
- `--report-suppressed` 与 SARIF `suppressionKind` 标记（item 39 CLI 输出格式）。
- 非 Java 源（TS 随 item 19；XML/ORM/xbiz 随 item 21 XNode）。
- autofix 交互面（fix 本体 = item 25；本 plan 仅保持「被抑制不产 fix」的语义注记）。
