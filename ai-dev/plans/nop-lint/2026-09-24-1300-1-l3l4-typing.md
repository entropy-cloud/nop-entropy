## Purpose

落地 design 06 §4.6 的 L3/L4 规则消费面：L3 = 把 item 30 的数据流内核（DefUseChain/ConstantPropagation）以位置键 resolver + xscript 绑定暴露给规则；L4 = 新建 `SemanticAnalyzer`（§4.5 契约名：implementsInterface/isOverridable/isLoggerCall）并以同型机制暴露。至此 deep 档四个 deep-only capability（L3/L4/SCOPE/METRICS）全部有真实 provider 与消费通路，item 36 的数据流规则移植与 item 35 的规则批量可直接消费。

## Current Baseline

- L3 内核已存在（item 30）：`DataFlowAnalyzer`/`DefUseChain`（Record：definitionSites/useSites/isUsed）+ `ConstantPropagation`（Constant/NotConstant/Unknown 三态）——nop-lint-java，**未接引擎**（无 resolver/绑定，无 capability 通路）。
- L4 不存在：全仓无 SemanticAnalyzer；design 06 §4.5 三个契约名为实现目标。
- 机制先例（items 32/33，全部已验证）：`XScriptCompiler.compile(ruleId, script, Set<LintCapability>)` 白名单变体（**Set 参数机制无需再改、零 XLang 平台改动**；compiler 本体需新增 VAR_SEMANTIC/VAR_DATAFLOW 两常量与两个注册分支）；`LintEngine.resolverReady` 双态 gate（METRICS/SCOPE 分支）；`RuleSetRunner.run` 10 参穿透 + `engageLadder` 的 metricsOpen/scopeOpen 分支（探针循环已排除 METRICS/SCOPE）；`XScriptEngine.executeMatch` 7 参重载 + ScopeFunctions/MetricsFunctions 注入；`MetricsResolverDiscovery`/`ScopeResolverDiscovery` SPI；RuleTestRunner 5 参；demo 套件 + 四态测试形态。
- **参数收敛（主动裁定）**：item 33 Decision 7 裁定"item 34 落地后如超 12 参再裁 context 对象"——本 plan 加 2 参后 run 恰为 12（未超），但**主动收敛**（顺带消灭 resolverReady 第 3/4 个重载与 executeMatch 膨胀）；既有调用点清点：new LintEngine 46 处（7 参包私有 9 处必改、6 参 10 处若保留便捷构造零改动）、RuleSetRunner.run 17 处（15 处测试必改）、executeMatch 7 参生产调用点仅 1 处。
- item 26 的 `JavaTypeResolver`（symbol solver 接线先例：ParserConfiguration + JavaSymbolSolver + ReflectionTypeSolver，parse 前挂载）是 L4 类型层次查询的实现基础；`ASTMapping`/`JavaNodeIndex` 位置键桥接可用。
- `LintCapability.L3`/`L4` 已存在（item 31，isDeepAnalyzer=true，deep 上限含两者）；`AnalyzerAvailability` 探针接口仍无实现（METRICS/SCOPE 走 resolver 路）。

## Goals

1. **L4 `SemanticAnalyzer`**（nop-lint-java semantic 包，JavaParser + symbol solver，item 26 先例）：design 06 §4.5 三契约——`implementsInterface(type, interfaceName)`（类型层次，含超类链与泛型擦除面）、`isOverridable(method)`（final/static/private 修饰符 + 封闭类 final 性）、`isLoggerCall(call)`（接收者类型为 org.slf4j.Logger 或 java.util.logging.Logger + 方法名 ∈ log 族/debug/info/warn/error/trace/isXxxEnabled）。
2. **L3 `dataflow` 查询面**：`constantValue(declPos)` → String|null（ConstantPropagation，Unknown/NotConstant → null）、`useCount(declPos)` → long（DefUseChain.Record.useSites 大小）、`isSelfAssigned(declPos)` → boolean（Record.isSelfAssigned）——直接服务 item 36 的 CompileTimeConstant/UnusedLocalVariable/SelfAssignment 规则族。
3. core 双接口 + SPI：`SemanticResolver`/`DataflowResolver`（语义包，TypeResolver/MetricsResolver/ScopeResolver 同构：0-based line/UTF-16 col、具名文件、isAvailable 探针、合法空答案显式区分故障）+ 两个 Discovery。
4. xscript 双绑定：`semantic.implementsInterface(node, name)` / `semantic.isOverridable(node)` / `semantic.isLoggerCall(node)`（requires: L4）；`dataflow.constantValue(node)` / `dataflow.useCount(node)` / `dataflow.isSelfAssigned(node)`（requires: L3）——白名单变体自动支持（capability 集参数已就绪）。
5. **穿透收敛（Decision 1）**：新增 `DeepResolvers` context record（metrics/scope/semantic/dataflow 四 resolver + filePath），`RuleSetRunner.run` 与 `executeMatch` 改传单一 context；`LintEngine` 构造改 6 参（registry, profile, typeResolver, analyzers, DeepResolvers, clock——包私有）+ 便捷公开构造保持。阶梯闭合记录 L3/L4（open = resolver live，DeepResolvers 携带 open 态或 runner 判定）。
6. SPI + CheckRunner/RuleTestRunner 拾取 + demo 套件（`deep-suites/semantic-l4` + `deep-suites/dataflow-l3` 各一）+ 四态绑定测试。

## Non-Goals

- 不落生产 L3/L4 规则（item 36 移植 ESLint 数据流规则与 PMD/EP P0/P1 批量；item 35 规则批量）
- 不做 CFG/路径敏感分析（design 05 §3 为 Phase 3 更后面，无 item 依赖）
- 不做 TS 侧 L3/L4（无消费方）
- AnalyzerAvailability 探针接口保留（接口与现测试不动）；但 **L3/L4 门控从探针路迁到 resolver 路是行为迁移**（R1 C-1 认领）：现行 gate 的 deepAnalyzers 分支（L3/L4 走探针）将改为 resolverReady 判定——TestDeepProfileGate 3 例（deepWithLiveProbeRunsTheRule/deepCapabilitiesAreCaseInsensitiveTokens/l2PlusDeepRuleNeedsBothPathsLive）与 TestBudgetDegradeLadder 5 例（L3 探针驱动阶梯 + ProgrammedClock 读钟序列）为**行为级改写**并逐个列出，非"零改动"。

## Key Decisions（执行前裁定，审查确认）

1. **穿透收敛（R1 C-1/C-2/C-3 修复后口径）**：`DeepResolvers` record **只携四 resolver**（metrics/scope/semantic/dataflow，engine 构造期，可静态复用）——**不含 filePath**（filePath 是 per-lint-call 参数：CheckRunner 单 engine 多文件、unnamed lint=null）；lint() 内按调用合并 per-call context（record wither 或独立 RunContext）传 run/executeMatch。公开构造保留 2/3/4 参与现有 6 参（内部包 DeepResolvers，既有 6 参调用点零改动）；新增 DeepResolvers 全量公开构造（CheckRunner/RuleTestRunner 的 L3/L4 Discovery 拾取用）；包私有 test seam 改 (registry, profile, typeResolver, analyzers, DeepResolvers, clock)。`resolverReady` 按各 resolver 独立判定；阶梯闭合记录由 runner 从 per-call context 判 open（探针循环排除 L3/L4/SCOPE/METRICS 四者）。**L3/L4 门控行为迁移**：gate 的 deepAnalyzers 探针分支改为 resolverReady——TestDeepProfileGate 3 例 + TestBudgetDegradeLadder 5 例行为级改写（逐个列出），探针路仅余接口留存。
2. **L4 实现路径（R1 A-1 口径收窄）**：symbol solver（item 26 先例；ParserConfiguration 挂载无全局静态，多 parser 实例不冲突）。**L4 v1 可答面 = JDK 类型层次 + 同 CU 层次（含传递链与 superinterface）+ 纯 AST 修饰符面**；ReflectionTypeSolver 装不下被 lint 的任意用户类——用户类跨文件层次 = UnsolvedSymbol = 异常（skip-and-count，不冒充 false，与 metrics"零不合法"同类；异常翻译复刻 JavaTypeResolver 三形态）。isOverridable 纯 AST 无需 solver。同一文件多 resolver 各自 parse+缓存（deep run 内至多四份）——共享 parse 缓存为后手（owner-doc 增注）。
3. **L3 实现路径（R1 B-1 修复后）**：item 30 内核直用，但位置键适配层**按声明节点 identity 取 Record**——ConstantPropagation 的 byName 表对同名遮蔽声明会静默答错（后声明覆盖前声明），适配层必须以定位到的声明节点 == Record.declarationNode() 匹配（必要时为 ConstantPropagation 增按节点查询入口）；**方法屏障**：上溯定位时同时校验存在 MethodDeclaration/ConstructorDeclaration 祖先，字段/方法外声明 = 抛异常（v1 明确不答字段——item 36 计划须知道此口径）；Unknown/NotConstant → null（合法"非常量"）。Phase 1 测试补同名遮蔽用例。
4. **绑定语义（R1 D-1/D-2 补口径）**：constantValue 返回 String|null（null=合法非常量）；useCount 返回 long；implementsInterface/isOverridable/isLoggerCall 返回 boolean（solver 不可答则异常）。`semantic.implementsInterface(node, name)`：node = 类/接口声明节点或 `new X(...)` 表达式（位置键取解析类型）；第二参比较目标归一**复用 JavaTypeResolver 的 resolveExpectedType 口径**（FQN 直比 → CU imports → java.lang. 兜底）；层次命中判定用 **erased qualified name**（ResolvedReferenceType.getTypeDeclaration().getQualifiedName()——describe() 含泛型参数会假阴性）；**接口 extends（superinterface 链）计入**。
5. **Logger 判定口径（R1 A-2 注记）**：接收者解析类型 FQN ∈ {org.slf4j.Logger, java.util.logging.Logger, org.apache.logging.log4j.Logger} + 方法名 ∈ {trace,debug,info,warn,error,log} 或 `is*Enabled`——v1 白名单。**log4j 分支 classpath 条件化**（log4j-api 不在 lint 模块依赖链，ReflectionTypeSolver 下必异常）：demo/测试夹具用 slf4j 或 JUL；log4j 命中面待 ClassLoaderTypeSolver 后手。
