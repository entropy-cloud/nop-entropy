# Minimal CLI：`nop-lint check` + console 输出（roadmap item 18）

## Current Baseline

以下事实均已对照 live repo（2026-09-22）核实：

- Wave 3 仅剩 item 18：items 14（xscript v1，plan 2137-2）、15（deadline executor，plan 0128-1）、16（EditCalculator/增量解析，plan 0128-2）、17（suppression v1，plan 0128-3）全部 `done`。item 18 是 M3（dogfoodable）的最后一个 unlock 项；items 28/39/41 也依赖 18。
- 提前决策（design 08 §0 关键决策表）：最小 CLI（`nop-lint check` + console 输出）从 Phase 4 提前到 Wave 3——"Phase 1–2 交付的规则需要真实执行面 dogfood，避免双份维护、单侧生效窗口"。
- 引擎入口已齐备：`LintEngine.lint(List<RuleDslModel>, String languageId, String source)`（`engine/LintEngine.java:53`，languageId 经 registry 大小写归一、未知 id fail-closed）、`(..., LintLanguage, String)`（:60）、`(..., LintTree)`（:69）。单文件管线内已串齐 deadline 安装（`LintDeadlineExecutor.install()`，管线中段）与抑制判定（`SuppressionFilter`，管线尾，`LintStats.suppressedDiagnostics` 计数）——CLI 只做装配，不重复实现管线语义。
- 语言发现：`LanguageRegistry.discoverDefaults()` 经 JDK ServiceLoader 发现 `LintLanguage` provider（`engine/LanguageRegistry.java:45`）；`nop-lint-java` 经 `META-INF/services/io.nop.lint.core.lang.LintLanguage` 注册 `JavaLanguage`（`JavaLanguageDiscoveryTest` 已覆盖发现回归）。
- 规则资产：7 条生产规则位于 `nop-lint-nop/src/main/resources/_vfs/nop/lint/rules/`（exception/no-empty-catch、exception/no-raw-exception、api/bizmodel-dao-access、api/bizmodel-safe-api、api/ibiz-missing-annotation、api/ibiz-missing-context、nop/no-vfs-violation），经 `RuleDslParser.loadRuleModel` VFS + xdef 管线加载；nop-lint-nop 主资源在 classpath 上即可被发现，nop-lint-core 无需编译期依赖 nop-lint-nop。
- 输出模型：`Diagnostic(ruleId, severity, message, SourceRange)`（`engine/Diagnostic.java:12`）、`LintResult(diagnostics, stats)`（`engine/LintResult.java:11`）、`LintStats` 计数域（loaded/executed/kindFiltered/skippedByProfile 含 skippedRuleIds/suppressed/xscript 四计数/disabledRuleIds）——console 摘要可直接消费，无需新增计数域。
- 档位：`LintProfile.FAST` / `STANDARD`（`engine/LintProfile.java:24,30`；FAST 的 xscript 预算上限 20ms，:40）。
- CLI 契约基准（design 03 §2.4）：`console` 为默认输出格式；退出码 `0` 无违规 / `1` 存在 error 级违规（或超 `--max-warnings`）/ `2` 内部错误（解析失败/规则崩溃）；sarif/checkstyle-xml/json/junit-xml 输出格式为 Phase 4（item 39）。
- 现状缺口：nop-lint 组三个模块（core/java/nop）均无 main 类或 check 入口；本 item 交付前 nop-lint 没有任何 CLI 执行面。
- 前置已满足：item 18 唯一路标依赖为 item 9（LintEngine minimal，done）。

## Goals

- `nop-lint check` 最小命令行：目标路径（文件/目录）→ 按扩展名过滤 → ServiceLoader 语言绑定 → 生产规则加载（classpath VFS）→ `LintEngine.lint` 逐文件执行 → 结果聚合。
- console 输出（design 03 §2.4 默认格式）：诊断行（文件 + 1-based 行号 + ruleId + severity + message）+ 汇总段（文件数、各 severity 诊断数、`LintStats` 关键计数——含 `skippedByProfile`/`suppressedDiagnostics`/`disabledRuleIds`，延续"不静默跳过"硬约束的可观测口径）。
- 退出码 0/1/2 按 design 03 §2.4 落地；内部错误（不支持的输入、解析失败、规则崩溃）显式报错退出 2，不吞异常。
- 端到端 dogfood 证明：CLI 在本仓库真实 Java 源的有界切片上以 7 条生产规则完成一次真实检查（M3 dogfooding 缺口的执行面证据；仓库级 CI 切换不在本 plan）。
- roadmap item 18 状态回写（draft review 通过置 `planned`，closure audit 通过置 `done`）。

## Non-Goals

- CLI 完整化（match/check/test 子命令、`--fix-dry-run`、baseline、sarif/checkstyle-xml/json/junit-xml 输出）= item 39（design 03 §2.4）。
- `nop-lint-maven-plugin`（item 37）、GraphQL API（item 38）、编辑器集成（item 41）。
- 仓库级 CI 门禁切换与 checkstyle/pmd 迁移（item 40 / M3 之后的迁移期，design 06 §8）；本 plan 仅交付执行面 + 有界 dogfood 证明。
- baseline 文件与 exemptions（item 27）；autofix（item 25）。
- 多文件并行聚合（design 03 §1.3 parallelFiles）与增量解析接线（编辑器场景，item 41）——v1 逐文件全量 parse。
- 非 Java 语言的实际检查面（TS 随 item 19；XML 随 item 21）——CLI 的语言发现机制语言无关，但 v1 dogfood 仅 Java。
