# Suppression v2（roadmap item 27）：ruleset 豁免 + baseline 文件 + CI 陈旧检查

## Current Baseline

以下事实均已对照 live repo（2026-09-24）核实：

- 依赖满足：item 27 deps = item 17（`done`，plan "2026-09-22-0128-3-suppression-v1"——内联注释 + @SuppressWarnings 双层抑制、pairing 元诊断、unused-disable-directive 元诊断已落地）。管线位 `SuppressionFilter.evaluate`（`LintEngine.lint` 尾部）稳定，`SuppressionOutcome(emitted/suppressed/meta)` 三分类与 `suppressedDiagnostics` 计数已存在。
- **ruleset 面现状**：`lint-ruleset.xdef` 不存在（design 10 §3 是 Phase 2 草案，本 plan 新建）；`RuleSetLoader` 只扫 `*.rule.yml` 单文件，无 ruleset 文件概念；`lint.register-model.xml` 现注册 `rule.yml` 与 `rule.json` 两个 fileType（ruleset 后缀需新注册）。平台先例核实：跨文件 `xdef:ref` + key-attr 组合已有（`table-validator.xdef`），无 bean-class 节点经 `DslXNodeToJsonTransformer` 物化为 `DynamicObject` 后可直接进 `RuleDslParser.parseRuleModel`——内联规则体解析路径成立；`xdef:name` 必须合法 var name（design 10 §2 既有裁定），新 xdef 用 `LintRuleset`（草案的 `lint-ruleset` 值落地即失败，不照抄）。
- **baseline 面现状**：零实现——无 fingerprint、无 baseline 文件模型、无 write/check API、CLI 无参数。design 09 §5 定格式（version/entries: rule/file/fingerprint/count）与生命周期（生成→匹配→收紧→清零）；design 09 §5.3："实际命中数 < baseline 记录数 → 报 stale，要求重新生成（基线只减不增；新增条目 CI 失败）"。
- **design 09 §4 豁免语义**：ruleset YAML `exemptions` 列表，每条 `rule`（规则 id）+ `files`（glob 列表）+ `reason`（必填，文档化）+ 可选 `ranges`（规则自定义语义范围键，v1 解析保存但引擎不做 ranges 匹配——v1 裁定只落地 files glob 面）。多值属性按 design 10 §2 既有裁定走 csv-set（xdef 单 string 属性、模型层按逗号拆分），不用重复子标签（duplicate-prop 崩溃）。
- **design 09 §6 交互约束**：RuleTester fixtures 不受 baseline/exemptions 影响（只测内联抑制）——豁免/baseline 必须落在 CheckRunner/CLI 层，不得进 `LintEngine`/`SuppressionFilter`/`RuleTestRunner`（RuleTestRunner 直连 parser+engine，给定该落点下天然不触达）。此项为架构红线。
- **fingerprint 裁定**（修订 design 09 §5.1 字面并回写增注）：design 原文"规则id+节点文本+range 的内容哈希（抗行号漂移）"字面含 range 会破坏抗漂移；裁定 fingerprint = sha256(ruleId 的 UTF-8 字节 + 0x0A + SourceRange 字节切片)——**直接对源码字节切片哈希**（SourceRange 本就是字节偏移，不经过 String 换算，多字节内容天然正确），内容寻址、行号漂移免疫；同文件同文本多重出现以 `(rule, file, fingerprint)` 全键 + `count` 字段 multi-set 对账（逐次消费）。
- **CLI/summary 现状**：`CheckRunner.lintFile` 顺序 = `summary.accumulate(result)`（severity 计数）→ `FileFindings`；退出码来自 `summary.hasErrorDiagnostics()`——**豁免/baseline 过滤必须发生在 severity 累计之前**（先过滤诊断列表再构造 LintResult 累计），否则被抑制的 error 照样置退出码 1（空壳路径，审查 B3 钉死）。`CliOptions` 已有 `--fix`/`--fix-dry-run` 互斥先例。
- **fix 交互裁定**（修订 design 09 §6 并回写增注）：CLI 层过滤发生在 FixApplier 消费诊断**之前**——被豁免/被 baseline 命中的诊断不进 fix 流，"被抑制的诊断不产 fix" 语义延伸覆盖 CLI 层过滤。**fix 多 pass 组合裁定**（审查 NEW-1）：每个文件先以**原始内容的首轮 lint** 一次性算出 baseline/exemption 决策集（命中的 `(rule,file,fingerprint)` 全键集合），该决策集作为**无状态谓词**作用于后续所有 fix pass 的候选过滤与 report lint；multi-set 消费账本只在原始内容 lint 上推进一次（count 扣减以原始出现次数封顶）——避免"pass 2 重 lint 后同指纹因 count 耗尽被判未命中而误进 fix 候选"的合同违约。`--write-baseline` 与 `--fix` **互斥 fail-closed**（审查 NEW-2：pre-fix/post-fix 生成语义分歧，不裁定默认）；`--baseline`/`--baseline-check` 与 `--fix` 允许组合（决策谓词全程生效）。
- 硬约束适用：零平台改动（新 xdef 属 nop-lint 模块内资源）；Wave-2+ 新能力带测试（Minimum Rules #25）；豁免 reason 必填 fail-closed（#24 无静默豁免）；"基线只减不增"是 CI 硬门禁不可降级（#13）——其执行机构 = `--baseline-check` 模式下 stale → 退出码 1（见 Goals 模式差异矩阵）。

## Goals

- **模式差异矩阵**（CLI 三开关，互斥 fail-closed；设计 09 §5.3 的 v1 落地口径）：

  | 行为 | `--baseline <file>`（apply，本地/报告去重） | `--baseline-check <file>`（收紧，CI 硬门禁） | `--write-baseline <file>`（生成） |
  |------|------|------|------|
  | 命中基线的诊断 | 抑制 + `baselineSuppressed` 计数 | 抑制 + 计数 | —（写文件） |
  | 未命中（新增/超出基线）的诊断 | 照报（severity 照常计数） | 照报 | — |
  | stale 条目（零命中或 count 未用满） | ConsoleReporter stale 独立清单段（run 级记录，**不是 Diagnostic**——不进诊断流、不进 warningCount） | **同一清单段 + 退出码 1（#13 的执行机构）** | — |
  | 退出码 | 既有三态（残留 error → 1） | `hasErrorDiagnostics() || 有 stale` → 1 | 成功 → 0，内部错误 → 2 |

  设计 09 §5.3 "新增条目 CI 失败" 的 v1 口径：新增违规照报、按既有 severity 退出码（warning 级新违规不 fail，`--max-warnings` 归 item 39）；基线收缩的强制机构 = `--baseline-check` stale → exit 1。此口径作为 design 09 §5 增注回写。
- ruleset 面：`/nop/lint/schema/lint-ruleset.xdef`（`xdef:name="LintRuleset"`；id + rules（key-attr=id，xdef:ref lint-rule.xdef）+ exemptions（rule/reason 必填 string 属性 + files/ranges csv-set string 属性））+ `RuleSetModel`/解析（XDSL 管线，`lint.register-model.xml` 注册 `ruleset.yml` fileType）+ `RuleSetLoader` 扩展（`*.ruleset.yml` 与 `*.rule.yml` 并存加载）。
- 豁免面：exemption（rule + files glob + reason 必填）在 CheckRunner 层过滤——glob 用 `FileSystem.getPathMatcher`；**路径基准裁定**：匹配输入 = `TargetScanner` 报告的目标路径 `normalize()` 后的正斜杠形式，两侧（glob 与文件）同口径归一；baseline `file` 字段同口径存储/匹配——baseline 是调用根相对的（CI 固定从仓库根运行），跨调用根不匹配是已记录的 v1 限制（写入 design 09 §5 增注）。exemption.rule 指向规则集运行中不存在的规则 id = 加载失败（fail-closed，消息列出已知 id——防手误豁免静默无效）；**校验时序**：在整个前缀的全部 rule id 集（ruleset 内联 ∪ 全部 `*.rule.yml`）收集完毕后统一校验，逐 ruleset 加载即校验会因扫描顺序误杀后加载文件中的规则。被豁免诊断计数 `exemptedDiagnostics`（全 plan 统一此名），ConsoleReporter 汇总行可见。
- baseline 面：`BaselineEntry`/`BaselineFile` 模型（version=1）；读写用平台 YAML 工具族——**已钉死入口**：`io.nop.core.lang.json.JsonTool.parseBeanFromYaml(String, Type)` 与 `JsonTool.serializeToYaml(Object)`（nop-core，nop-lint 自家 `ExpectParser` 已在用；`DslJsonResourceLoader` 实在 nop-xlang，本 plan 的同族入口就是 JsonTool）——禁止手写 YAML 字符串拼接（转义是已知 bug 温床）；损坏文件/未知 version fail-closed。`BaselineEngine`：write（过滤后诊断 → baseline）、apply（`(rule,file,fingerprint)` 全键 multi-set 消费，count 耗尽后同指纹诊断 = 未命中）、check（未消费 entry = stale 列表）。
- CLI 接线：三开关进 `CliOptions`（三开关互斥 + `--write-baseline`×`--fix` 互斥，其余 `--baseline*`×`--fix` 组合允许，均 fail-closed）；RunSummary 增加 `baselineSuppressed`/`exempted` 计数；ConsoleReporter 增加 baseline 计数行 + stale 条目独立清单段（stale 不伪装成文件级诊断——条目指向的文件可能不在本次扫描）。
- **退出码数据流裁定**（审查 B3）：过滤（豁免 → baseline）发生在 `summary.accumulate` **之前**——CheckRunner 先对 LintResult.diagnostics 过滤，再用过滤后列表构造累计入参，severity 计数与退出码只反映过滤后残留；Phase 3 e2e 显式断言豁免/baseline 场景退出码 0。
- RuleTester 隔离红线（design 09 §6）：`LintEngine`/`SuppressionFilter`/`RuleTestRunner` 零改动，豁免/baseline 只存在于 CheckRunner/CLI 层；回归断言钉死。
- 端到端证明：临时目录 + fixture ruleset（含 exemptions）+ 真实文件全生命周期 write → apply → check。
- owner docs 回写：design 09 §4（files glob v1 + ranges v1 不匹配 + exemption.rule fail-closed 裁定）、§5（fingerprint 裁定 + 路径基准 + 模式差异矩阵 + §5.3 v1 口径 + fix 交互增注）、design 10 §3（LintRuleset 落地形态 + csv-set 裁定）+ roadmap item 27 状态回写 + item 39 范围注记（baseline 参数面提前交付，item 39 清单核销时对齐）。

## Non-Goals

- `ranges` 豁免的引擎匹配语义（v1 只解析保存；规则自定义语义随需要另行裁定，design 09 §4 原文"规则自定义 key"）。
- `--report-suppressed` 的 SARIF suppressionKind 标记（SARIF 输出本身是 item 39）。
- Maven goal 的 baseline 子命令（item 37 需复用 CheckRunner 过滤逻辑——复用面在 roadmap item 37 立项时裁定，本 plan 不预留抽象）；编辑器侧 baseline（item 41）。
- 规则集 `options`/`settings` 共享配置注入（ruleset xdef 中不声明该字段，避免空壳；需要时另行裁定）。
- baseline 的自动缩域建议/交互式重生成（只做 write/apply/check 三原语）；`--write-baseline` 不做覆盖确认（baseline 是生成物，覆盖即重生成路径，行为写入文档）。
