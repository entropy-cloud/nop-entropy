## Purpose

把生产规则库从 18 条扩至 **48 条**（首批 20 余量 1 + 反模式 8 + 迁移吸收 21），每条带 RuleTester fixtures（Wave-2+ 硬约束），并把 count 门禁（`TestProductionRuleCount`）钉到 48。本 plan 的**枚举清单即首个交付物**（roadmap Wave 5 明文要求），Phase 1 逐条 spike 校验可行性后冻结。

## Current Baseline

- 生产规则 18 条（exception 4 + api 4 + quality 4 + security 2 + nop 4 XNode/XML——TestProductionRuleCount EXPECTED_IDS 枚举断言钉死）；全部带 RuleTester 套件（TestNopRuleSuites 真实管线）。
- 机制面（全部可用）：pattern/kind/any/all/not/关系（inside/has/follows/precedes/stopBy）/约束（sameText/differentText/regex/inList/typeOf/notExists/withinDepth）/xscript 绑定（node/captures/report/declType/**metrics/scope/semantic/dataflow**——items 32–34）/autofix 模板/XNode XML 规则。
- item 29 路由遗留：query-limit-required（未落地，首批 20 的第 20 条）、xpl-escaping（deferred，XML text 无 contains——本 plan 不翻案）。
- deep 档 provider 全通（items 32–34）：`requires: METRICS/SCOPE/L4/L3` 规则在 CLI 之外的装配（RuleTestRunner 显式构造）可真实运行；demo 套件形态 = deep-suites/。

## Goals

1. **枚举清单（本 plan §Execution Plan 前置表）**：30 条新规则的 id/category/机制/manifest 锚点，Phase 1 逐条 spike 后冻结。
2. 落地 30 条生产规则于 `nop-lint-nop/src/main/resources/_vfs/nop/lint/rules/`，每条 1 个 suite（valid ≥1 + invalid ≥1 + `.expect` 钉死）。
3. deep 规则（metrics/dataflow/semantic family）的 suite 走 `deep-suites/` + 显式 provider 构造（items 32–34 形态），其余走默认 suites + TestNopRuleSuites。
4. `TestProductionRuleCount` 与 `TestNopRuleSuites` 期望集更新到 48；count 门禁断言钉死。deep 套件组织（R1 F7）：family 三个测试类（metrics/L3/L4）类内循环 + deep-suites 发现数断言（7 条）。
5. 数量口径（R1 F8 修正）：48 = 18 现有 + 30 新增；首批 20 中进入 48 的为 17 条（16 已落地 + query-limit-required；errorcode/import-order 路由 item 28/maintain-mjs，xpl-escaping deferred）。fixture 口径统一 = valid 1 + invalid 1–2（现有先例）。

## Non-Goals

- xpl-escaping 翻案（维持 deferred）；errorcode-param-consistency（item 28 路由不变）
- autofix 模板批量补齐（现有规则不动；新规则 autoFixable=false 为主，除非 pattern 天然可模板）
- manifest tier 3 全量（~190 条池是 manifest 口径，非 48+ 口径——design 02 §106）
- ESLint 数据流规则移植与 PMD/EP P0/P1 批量的主体（item 36；本 plan 只吸收其中零成本可实现的条目，item 36 不重复计）
