## Purpose

新建 `nop-lint-graphql` 模块：暴露 `lint__checkSource`/`lint__checkFile`/`lint__listRules` 三个 GraphQL query（design 03 §2.3 契约），fast 档运行，安全与资源边界按设计执行。

## Current Baseline

- 平台 GraphQL 面：`io.nop.graphql`（BizModel action 自动暴露——GraphQL service 形态为 `XService`/`@GraphQL` 注解面？实现期 spike 平台服务注册形态：仓库内 graphql 服务先例见 nop-service-framework 各 biz 模块的 biz model）。
- `LintEngine`（fast 档）/`LanguageRegistry.discoverDefaults`/`RuleSetLoader` 全部就绪；`Diagnostic`/`LintStats` 不可变值面可直接序列化。
- 设计安全边界（§2.3）：入参只接受规则 id（不接受裸 pattern）；source 上限 1MB 可配；并发/超限返回明确错误码；写操作不暴露。
- 平台已有 GraphQL 测试形态（nop-graphql-core 测试先例：TestGraphQLXXX 直接调用 executor）。

## Goals

1. 新模块 `nop-lint/nop-lint-graphql`：`NopLintGraphQLService`（**BizModel 形态**：`@BizModel("Lint")` + `@BizQuery` 方法——平台无注解扫描，须 `_vfs/**/beans/*.beans.xml` 显式注册 + 资源 `_vfs/nop/lint/` 布局，R1 2.1）暴露三 query：
   - `lint__checkSource(source, language, rules?)` → 诊断列表（fast 档、规则 id 过滤）
   - `lint__checkFile(path, rules?)` → 同上（VFS/磁盘路径边界裁定见 Decision 2）
   - `lint__listRules(language?)` → 规则元数据（id/category/severity/message/autoFixable）
2. 安全边界（R1 2.3 具体化）：source ≤1MB（配置键 `nop.lint.graphql.max-source-size`，R1 2.6）；**checkFile 路径边界算法钉死：VFS 路径为默认受支持面；裸磁盘路径必须 `toRealPath()` 后落在工作目录前缀内（symlink 逃逸由 toRealPath 消解），拒绝 `..` 与越界——平台无现成守卫，手写并测试**；fast 档固定。
3. 返回面 DTO（诊断/统计）与平台序列化兼容（DynamicObject/DataBean 形态 spike）。

## Non-Goals

- 不暴露 baseline 写/fix 应用（design：写操作仅 CLI/Maven 通道）
- 不做并发配额全量（v1：单请求 source 上限 + 平台自身并发面；显式限流归 item 43 调优）
- 不做 deep 档暴露

## Key Decisions（执行前裁定，审查确认）

1. **服务注册形态（R2 m2 定案，免 spike）**：BizModel action 形态，直接引仓库全链路先例 `nop-treesitter` 的 `TreeSitterBizModel`——`@BizModel("TreeSitter")` + `@BizQuery` + `@Name` 参数 + 尾随 `IServiceContext` + setter 注入；beans 资源 `_vfs/nop/<mod>/beans/app-<mod>.beans.xml`；pom 依赖仅 `nop-graphql-core` + `nop-ioc` 面。本模块照此形态：`@BizModel("Lint")` + beans 资源 `app-lint.beans.xml`（模块 resources 的 VFS 布局 `nop/lint/beans/` 目录）+ `_module` 空标记文件。
2. **checkFile 路径边界**：只允许解析到工作目录（app.home/user.dir）内的路径，越界抛明确错误码（防任意文件读）；VFS 路径优先。
3. **source 上限**：常量 1MB（可配 via `nop.lint.graphql.max-source-size`，平台配置 API 读取——`AppConfig.varRef`/`IConfigReference` 先例），超限抛 `NopLintException` 明确错误（不静默截断；**错误面 = message-mode 异常，测试断言消息内容**——R2 m5，design "错误码"措辞随增注落档）。
5. **checkFile 路径文法（R2 F1 补钉——VFS 面安全边界）**：入参路径三分法——(a) 一切带 namespace 前缀的路径（`file:`/`cls:`/`res:`/`json:` 等，判别 = `:` 出现在首段）**显式拒绝**（`FileNamespaceHandler` 对 `file:/任意绝对路径` 不设防，默认无 allowlist 配置——VFS 面放行 namespace 等于任意文件读）；(b) 以 `/` 开头的纯 VFS 绝对路径 → 经 VFS 解析，且解析结果必须仍是 VFS 内资源（拒绝逃逸）；(c) 其余（相对/绝对磁盘路径）→ `toRealPath()` 后必须落在工作目录前缀内。**checkFile 读入内容同受 max-source-size 约束**（大文件 OOM 面）。三类各有测试。
6. **engine/规则集生命周期（R2 F2 补钉）**：singleton `nopLintEngine` 语义——服务 bean 持有 `LintEngine(registry, LintProfile.FAST)`（最小两参构造）+ **规则集启动时加载一次**（`RuleSetLoader` 默认前缀，缓存 `LoadedRuleSet`；理由：fast 档 <100ms 预算下每次请求重扫重析 62 个 YAML 占主导；规则变更需重启，v1 接受并写入增注）。请求路径零加载开销。
4. **规则过滤**：`rules` 参数为可选 id 列表，白名单语义（加载的规则集内过滤），未知 id fail-closed 报错；**未知 language 参数同样 fail-closed**（R1 2.2）；字段命名钉平台形态 **`Lint__checkSource`/`Lint__checkFile`/`Lint__listRules`**（BizObj__method 惯例，R1 2.5——design §2.3 小写 lint__ 的差异随增注落档）；**返回面仅 diagnostics + stats，不暴露 fixes**（R1 2.4 Non-Goal：fast 档 fix 载体不跨服务暴露）；**运行时模块集声明**：挂载本模块的应用需同时部署 nop-lint-java/nop-lint-nop（语言发现 + 规则库，缺一 fail-closed——R1 2.2）；**listRules 元数据口径（R2 m4）**：severity 取顶层 `getSeverity()`（诊断载荷权威槽位，非 metadata.severity 可选枚举）、metadata 为 null 时字段给安全默认（category=""、autoFixable=false）——不 NPE。
