# xscript 引擎 v1：编译白名单 + node/captures/report 契约（roadmap item 14）

## Current Baseline

以下事实均已对照 live repo（2026-09-21）核实：

- 引擎 v1 已落地（item 9 done）：`CompiledRule` 形态矩阵 v1 把**含 `xscript` 字段的规则编译期 fail-closed**（英文消息含规则 id 与原因）——本 plan 用真实执行替换该拒绝路径；regex 匹配器的拒绝路径不变（语义归 item 22）。
- nop-lint-core 已依赖 nop-xlang（pom 实测），零新模块依赖即可使用 XLang 执行体系。
- XLang 执行体系（design 07 §1）：表达式编译一次 → `IExecutableExpression`，每 match 新建子 `IEvalScope` 绑定上下文；语法要点（design 07 §6 已按 XLang 校对）：lambda 箭头 `=>`（不识别 `->`）、反引号字符串是普通字面量（无 `${}` 插值）、正则走 `String.matches()`。
- API 契约（design 07 §2.1–§2.3）：v1 绑定 `node`/`captures`/`report` 三对象；`typeAnalyzer`（L2，item 26）与 `scopeAnalyzer`（Phase 3，item 33）不在本 plan。NodeWrapper 方法表 8 方法（kind/text/child/children/ancestor/descendant/siblings/range），其衬底是 `LintNode` 现有 API（`kind()/text()/childByField()/children()/parent()/range()` 等，均已存在）。
- L1 消费契约已就绪（item 12 done，design 06 §5.2 已修订）：`io.nop.lint.core.type.DeclTypeResolver.resolveDeclType(LintNode)` → 书写类型文本或 null——item 14 是其首个注入消费方（roadmap item 12 plan 收口时显式移交）。
- 安全模型（design 07 §3）：编译期白名单 scope（只注册 `node`/`captures`/`report` 与少量内置全局，不注册 import/Class/Resource 类访问器）；单 match 诊断数上限（默认 100）；调用深度上限 32；脚本异常 → 跳过该 match + internal warning（不杀规则/文件/run）；连续失败阈值（50）→ 禁用规则并上报；可观测计数进 LintStats。
- **deadline 不在本 plan**：路线 A（`EvalExprProvider.registerGlobalExecutor` 全局包装）属 item 15（deps: 14，紧随本 plan）。`xscriptTimeoutMs` 已被 `RuleDslModel` 携带（默认 100）但 v1 不强制——残留风险（脚本内死循环可挂起执行）必须显式登记，不得静默。
- 设计硬边界：nop-xlang/nop-core 是 Protected Area，**零平台改动**；白名单必须经 XLang 现有公开编译入口实现，不得触碰平台内部。
- `report({fix})` 的 autofix 面属 item 25——v1 对 fix 子字段显式拒绝。
- Wave 3 剩余 items 15/17/18 均以本 plan 为前置（deps: 14 或 9+dogfooding）；API 类规则（item 11 的 4 条）的检测实现路径依赖本 plan 的 xscript 能力。

## Goals

- 规则 `xscript` 字段真实可执行：matcher（pattern/any/kind）命中后逐 match 执行脚本；脚本不调用 `report()` 则该 match 无诊断（xscript 可作过滤器）；可多次 `report()` 产出多条诊断。
- 编译期白名单：违禁构造（import/类定义/静态反射调用/文件网络访问全局函数）编译失败 → 规则 fail-closed（英文消息含规则 id），杜绝沙箱静默放行。
- NodeWrapper/captures/report 运行时绑定落地（design 07 §2.2/§2.3 语义）；L1 `DeclTypeResolver` 按消费契约注入 xscript 上下文。
- 资源与错误语义落地：诊断数上限、脚本异常跳过 + 计数、连续失败禁用规则，全部可观测（LintStats/日志）。
- 端到端：`.rule.yml`（pattern + xscript）→ `LintEngine.lint` → `Diagnostic` 一条测试走通。
- 完成后 roadmap item 14 具备翻 `done` 条件（items 15/17/18 与 item 11 API 规则的前置）。

## Non-Goals

- deadline executor 与 `xscriptTimeoutMs` 强制（item 15，路线 A）；fast 档 20ms 收紧（design 11 §7）。
- `typeAnalyzer`（L2，item 26）与 `scopeAnalyzer`（Phase 3，item 33）绑定。
- `report({fix})` 执行面（item 25）——v1 显式拒绝该子字段。
- regex 匹配器执行（item 22 口径）——维持编译期 fail-closed 现状。
- nop-xlang / nop-core / nop-xdef 平台改动（Protected Area，硬边界）。
- 抑制判定（item 17）、多文件与增量解析（item 16）、CLI（item 18）。

## Phase 3 — 引擎集成、资源语义与端到端收口

Status: planned

- Item Types: `Fix | Decision | Proof`

- [ ] 引擎管线集成：xscript 规则 = matcher 命中 → 逐 match 执行脚本 → 收集 `report()` 诊断；无 report 则该 match 无诊断（过滤语义，与 pattern-only 规则并行共存）；管线顺序维持 design 03 §1.1。

- [ ] **Decision（timeout 残留登记）**：`xscriptTimeoutMs` v1 携带不强制（item 15 承接路线 A deadline）；"无 deadline 下脚本死循环可挂起"的残留风险在本 plan Closure 与日志显式登记（watch-only residual，触发条件 = item 15 落地即消除）。
