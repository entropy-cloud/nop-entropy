## Purpose

按设计 §5.3.2 落地 WebAuthn/FIDO2 因子：新 ORM 实体 `NopAuthMfaCredential`（1:N 用户多硬件凭证行，credentialId 唯一 + signCount 克隆检测）；引入成熟 WebAuthn 库（封装于 nop-auth-service `WebAuthnAuthenticator`，不自研协议栈——设计 §5.4 拒绝）；注册/认证/解绑三 ceremony（复用 `MfaChallengeStore` 场景化 payload 承载 cryptoChallenge，create 时一次写入）；`MFA_TYPE_WEBAUTHN` 常量 + §5.3.0 白名单校验点逐处变更（含 `sendMfaCode` 按 mfaType 分派重构 + `ERR_AUTH_MFA_CODE_UNSUPPORTED`）；`mfaVerify` 断言验证（`MfaVerifyRequest` 可选 assertion 字段）经 `MfaFactorVerifier` 收敛（登录级/操作级/解绑共用）；credential 管理 API + `mfa-type.dict.yaml` + `nop.auth.mfa.webauthn.*` 配置组。不绑定 webauthn 的用户全流程无感知（一期零回归红线）。

## 规模裁定（设计 §八 拆分提示的 plan-first 裁定，起草时执行）

本 plan 触碰面估算约 20-28 文件（nop-auth 12+ 含 ORM/DDL 三方言、nop-biz-auth-api 消息 2、nop-biz-auth-core dict 1、测试 ~8），超 roadmap 单 plan 参考规模（5-15 文件）。**裁定不拆分**：W14-impl 是设计 §八 指派给单一工作项的完整交付面——"webauthn 用户完成登录"这一用户可用功能在 Phase 2 末端才第一次成立（库封装 → 注册 ceremony → 认证 ceremony 三段缺一即空壳：只有实体与常量 = 不可绑定；只有注册无认证 = 绑定后无法登录）；三 ceremony 共享同一 challenge payload 契约与 `WebAuthnAuthenticator` 封装，拆分到两个 plan 会把"payload 一次写入契约"切成两处维护。执行中若单 Phase 严重超载，按 guide 拆分规则另行 plan-first 裁定。

## Goals

- **库选型（Phase 1 Decision）**：POC 评估候选库（基线候选 = Yubico `java-webauthn-server` 家族：Apache-2.0、W3C Level 2 注册/断言验证、依赖面小）；POC 核对项：Maven 可解析、传递依赖无冲突、attestation=none 直接信任 + origin/rpId 强校验能力、COSE 公钥验证。POC 失败 → 评估次选候选；全部失败 → **plan blocked 升级人工裁定（不得自研协议栈**——设计 §5.4 明确拒绝）。依赖只引入 `nop-auth-service`。
- `NopAuthMfaCredential` ORM 实体（sid seq 主键、userId 索引、credentialId base64url 唯一约束、publicKey COSE、signCount、transports、name、status enabled|disabled、lastUsedAt + 通用审计字段；model-first → codegen → `_create_` 再生成 + 三方言 `_add_` 增量，禁手编 `_gen/`）。
- `MFA_TYPE_WEBAUTHN` 常量 + factorLevel 表核对（`"webauthn"`→3 已在表）+ `mfa-type.dict.yaml` 新增（含全部既有+新因子显示条目）+ ORM mfaType 列 comment 更新（"totp/sms/email/webauthn"——email 条目随 W15 常量落地再核对本 dict；本 plan dict 先落 totp/sms/webauthn，W15 补 email 行时同步）。
- 白名单 #1-#10 逐处变更（§5.3.0 表 W14 列）：#2 白名单扩容 webauthn + 错误消息动态拼接合法值；#3 分派扩展（webauthn → 注册 ceremony 发起）；#8 `sendMfaCode` 重构为按 challenge.mfaType 分派（sms 现行为/totp/webauthn → 新错误码 `ERR_AUTH_MFA_CODE_UNSUPPORTED`——email 分支 W15 接入，本 plan 预留分派骨架）；#6 `mfaVerify` webauthn 断言分支（`MfaVerifyRequest` 可选 assertion 字段，向后兼容）；#9/#10 comment + codegen 再生。
- `WebAuthnAuthenticator`（nop-auth-service）：封装库——attestation 验证（clientData.challenge 匹配 payload.cryptoChallenge / origin / rpId / 格式；attestation=none 直接信任）、断言验证（公钥验签 + challenge 匹配 + origin/rpId + signCount 单调递增；count=0 认证器跳过单调校验 + 审计）、creationOptions/requestOptions 构造（excludeCredentials/allowCredentials）。
- 注册 ceremony：`bindMfa(webauthn)`（pending setting secret=null + scene=webauthn-register challenge payload={sessionId, cryptoChallenge} 一次写入 → 返回 challengeToken + creationOptions；**受限会话内同样受 W13 proof 前置**——验证 webauthn 路径继承）+ `confirmWebauthnRegistration(challengeToken, attestationResponse)` 新端点（需登录态 + sessionId 绑定校验；attestation 验证失败 incrFailCount + MFA_FAIL 不消费；credentialId 唯一冲突=重复注册拒绝；成功 credential 落库 + setting enabled + 恢复码生成 + consume）。
- 认证 ceremony：`checkMfaRequired` webauthn 类型 challenge 创建时 payload 含 cryptoChallenge（一期异常表达不变）；`webauthnAuthOptions(challengeToken)` 通用 options 读取端点（scene=login 公开可访问；非 login 需登录态 + payload.sessionId==当前会话；challenge 只读不更新）；`mfaVerify` webauthn 分支（按 assertion.credentialId 查 enabled credential → 验断言 → signCount 严格递增则更新 → consume → completeLogin 一期出口不变）。
- 解绑 ceremony：`webauthnBeginVerify()` 新端点（需登录态，scene=webauthn-unbind challenge + requestOptions）+ `unbindMfa` 可选 challengeToken+assertion 扩展（webauthn 用户断言验证等价保持"验证当前因子"语义；其他 mfaType 一期 `verifyFactorForBind` 路径原样，向后兼容）。
- 操作级联动：`MfaVerifyOperationRequest` 可选 assertion 字段 + `mfaVerifyOperation` webauthn 分支（经 `MfaFactorVerifier` 统一载体——code 或 assertion；操作级链路零结构变更）。
- credential 管理 API：`listWebauthnCredentials`/`removeWebauthnCredential`/`renameWebauthnCredential`（W6 并入先例）；移除最后一把 enabled credential 拒绝（`ERR_AUTH_MFA_LAST_CREDENTIAL`——整体解绑走 unbindMfa ceremony）。
- 配置组 `nop.auth.mfa.webauthn.*`（rp-id/rp-name/origins；origins 不匹配 = 验证拒绝 fail-closed）+ 新错误码（`ERR_AUTH_MFA_CODE_UNSUPPORTED`/`ERR_AUTH_MFA_LAST_CREDENTIAL`；不触碰一期编码）+ 审计事件（注册/认证/解绑/credential 移除经 `IAuditService.saveAudit`）。
- E2E：绑定状态机全链（bindMfa(webauthn)→confirm→登录拦截→options→mfaVerify(assertion)→completeLogin）；操作级票流；解绑 ceremony；防重放（challenge 一次性重放拒绝/signCount 回退拒绝/count=0 跳过审计/origin 不匹配拒绝）；credential 管理负例（重复注册/最后一把移除/禁用单把后登录用另一把）；一期 totp/sms 用户零回归（既有套件断言零修改）。
- 文档：`docs-for-ai/03-modules/nop-auth.md` WebAuthn 章节 + 设计 §5.3 回写（选型结论与执行期裁定标注）+ roadmap。

## Non-Goals

- 邮件验证码、可信设备（W15——本 plan 的 sendMfaCode 分派骨架预留 email 位但不实现 EmailCodeStore）。
- WebAuthn attestation 完整信任链验证（设计 §七.1 deferred——attestation=none + origin/rpId 强校验即本 plan 语义）。
- signCount=0 认证器克隆检测增强（设计 §七.7 watch-only——跳过单调校验 + 审计即本 plan 语义）。
- 外部 MFA 服务 Authy/Duo（设计 §5.3.4 deferred，out-of-scope）。
- 多因子并存（mfaType 多值/因子集合——设计 §5.4 拒绝；webauthn 是单值因子类型之一）。
- 前端 WebAuthn 交互（navigator.credentials 调用层——设计 §七.5 deferred，前端业务层）。
- A2-audit；`@MfaRequired` 新动作标注（W12 首批五动作 + C1b 凭证库四动作已定，webauthn 管理动作是否标注属 A2-audit 评估）。
- W12/W13 已交付面的重构（MfaFactorVerifier/场景化 store/操作级票/受限会话 proof 仅消费与扩展分支，不改造结构）。
