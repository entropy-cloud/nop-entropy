# Subtree arena (compact int32 indices, slot reuse, symbol interning)

## Current Baseline

- `nop-treesitter/` scaffolded: `pom.xml` (JDK 17, `nop-commons`, slf4j, junit-jupiter), registered in root `pom.xml` `<modules>`; `TreeSitterBootstrap` + `TreeSitterBootstrapTest` (2 tests) green on `./mvnw -pl nop-treesitter -am test -T 1C` (commit `0d5971af6a`).
- No `io.nop.treesitter.subtree` package exists; no arena, no symbol interning, no per-node value type.
- Read-only reference: gotreesitter `~/sources/treesitter/gotreesitter/arena.go` (MIT, translate don't copy, never modify). Roadmap ARENA-01..04 define the deliverable set.
- Roadmap item 3 is `todo`; the stages table names this plan as its owner.
- Sibling plans in this group: `2026-09-07-1713-1-ts2java-extractor.md` (independent, parallel) and `2026-09-07-1713-3-lr1-parser-json-corpus.md` (consumes this plan's arena API).

## Goals

- `Subtree` value representation with int fields only — no per-node heap object on the hot path.
- `SubtreeArena` backed by parallel `int[]` arrays with `allocate` / `free` / `get` operations, free-list slot reuse, and geometric growth.
- `SymbolTable` interning (`String ↔ int`) for named tokens.
- 12 focused unit tests (allocate / reuse / grow / intern / equality / parent-arity) plus an integration proof that a nested tree can be built and navigated purely through the public arena API — the exact surface the LR(1) parser plan consumes.

## Non-Goals

- No inline-small-node optimization (roadmap item 5).
- No compact external-node metadata (roadmap item 7).
- No parser / lexer integration (roadmap item 4 — sibling plan `...-3-lr1-parser-json-corpus`).
- No performance benchmarking beyond a smoke profile note (roadmap item 13).
