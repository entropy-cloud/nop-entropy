## Goals

- **ER-01**: ERROR node creation and propagation: invalid tokens are skipped into `ERROR_REPEAT` composites (consecutive skips merge into one ERROR node), recover-to-previous-state wraps the popped span in an ERROR node, EOF-in-error wraps the remainder — arena-stored with builtin symbol ids and rendered as `(ERROR ...)` in both sexp forms.
- **ER-02**: missing-token injection: zero-width `MISSING <token>` leaves with the C selection rule (insertable token must lead to a state that reduces on the current lookahead), rendered as `(MISSING ";")` for anonymous tokens and `(MISSING name)` for named tokens.
- **ER-03**: extra-token recovery = strategy-2 skipping with cost-based pruning so the surviving tree is the C-runtime's choice among recovery variants (subtree-level error cost per `error_costs.h`, participating in both `selectTree` and the parse-termination condition — not just condense pruning).
- **ER-04**: ≥ 10 focused tests with intentionally broken inputs (unclosed braces/brackets/strings, premature EOF, mid-token garbage, nested-broken JSON, Java/TS/JS broken sources), each asserting the exact upstream-shaped tree (ERROR/MISSING placement), plus the JS adjudicated section now passing byte-exact and removed from the adjudication list.
- Regression: all existing corpus suites stay green with identical counts outside the de-adjudicated JS section.

## Scope

### In Scope

- `SubtreeArena`: `missing` column (boolean per id) + accessors; builtin symbol ids for ERROR and ERROR_REPEAT (reserved above the chain-container id; `Language.symbolName` stays grammar-only — the renderer special-cases builtins by id).
- **Lexer error mode** (required by ER-04's mid-token-garbage cases, which no lex mode can tokenize): when lexing fails in the current state's mode, retry with the error state's lex mode; on repeated failure, skip one character and emit a builtin-ERROR leaf carrying the lookahead char (C `ts_subtree_new_error`, error cost 500 + 1/char + 30/line). The dispatch must special-case the builtin error symbols: `tableCell(state, error-symbol)` returns "no actions" (C `ts_language_table_entry`), which hands control back to the recovery path instead of throwing the current out-of-range `TreeSitterException`.
- `GLRParser`: **three-state** version model (active / halted / paused — C `stack.c` `version_status`); pause on missing table cell with lookahead retained (replaces halt); recovery entry (RECOVER action group or all-versions-paused), aligned with C `condense` semantics: condense prunes by error cost but **never silently drops paused versions**, the MAX_VERSION_COUNT truncation respects the same cost ordering, and when no active version remains exactly **one** best paused version is resumed into recovery (parser.c best-paused-version selection, paused cost +500 in the comparison) — not "each". Recovery itself: strategy 1 (on-demand GSS summary walk, head-outward = pop-depth ascending, pop-and-wrap in ERROR), strategy 2 (skip token into ERROR_REPEAT at ERROR_STATE=0, consecutive-skip merging), missing-token insertion (before entering error state), potential-reductions pass, subtree-level error-cost accounting, EOF wrap-and-accept.
- **Subtree-level error cost**: a per-node side column (like the existing dynamic-precedence column) accumulating error cost through reduce, so `selectTree` (error cost first, then dynamic precedence/structure) and `run()`'s termination condition can compare a finished tree's error cost against in-flight versions (C `ts_parser__select_tree` compares `ts_subtree_error_cost` first; main loop continues while a cheaper version may exist).
- `TSTree`: `snapshot` deep-copy carries the `missing` flag (regression-tested); rendering: ERROR / ERROR_REPEAT → `(ERROR ...)` (children inline, indented form); missing leaf → `(MISSING ";")` anonymous / `(MISSING name)` named — in `toSExpression` and `toSexpString`, matching upstream `ts_node_string` conventions used by the corpus expectations.
- Tests: ER-04 set; the JS corpus adjudication list drops to empty and the count assertion updates to 116/116; corpus runners for JSON/Java/TS/TSX unchanged-green; one incremental-parse test against an ERROR tree (changed ranges over broken sources) to pin the item 9 invariant under error nodes; adjudicated rewrites of the two pre-recovery behavior tests listed in Current Baseline.

### Out Of Scope

- Error recovery for grammars not shipped in this repo; query-engine ERROR predicates; platform integration (item 12).

Status: completed

- Item Types: `Fix | Decision | Proof`

- [x] `Decision`: three-state version pausing model — `Version` status gains `paused` (distinct from halted; lookahead retained). `advance` on a missing table cell pauses instead of halting; RECOVER action groups also **pause** (the error-state row's only content is RECOVER) — recovery itself starts from the condense/resume path, not inline at the action dispatch. C `ts_parser__condense_stack` alignment: condense prunes by error cost but paused versions are only ever removed by that same comparison (never as a class), MAX_VERSION_COUNT truncation follows the cost ordering, and when the best version under the +500-penalized paused comparison is a paused version (even if worse active versions remain), exactly one best paused version is resumed into recovery — C `has_unpaused_version` resume loop in `ts_parser__condense_stack`, parser.c:1881-1900. The reduce-side version-overflow removal (`GLRParser` reduce's `> MAX+OVERFLOW` branch) must also not silently drop paused versions (C reserves `+ halted_version_count` headroom at parser.c:955-965) — paused versions leave only via the same error-cost comparison.
- [x] Recovery entry sequence per C `ts_parser__handle_error` (parser.c:1476-1568), **in C's actual order**: (1) `ts_parser__do_all_potential_reductions` on the paused version (parser.c:1485); (2) missing-token insertion loop (1495-1548); (3) NULL-push of the version into ERROR_STATE (empty-link push; `popCount` already models NO_LINK) + merge (1550-1556); (4) `ts_stack_record_summary` **now** — computed on demand by walking the version's GSS links, head-outward, pop-depth from 0 ascending, max depth 16, skipping entries at ERROR_STATE or at the current position (1559); (5) **unconditional** strategy-1 `ts_parser__recover` — first successful recover-to-state breaks (1568); (6) strategy 2 runs **in addition even after a successful strategy 1** (parser.c:1363-1391, "in addition, try strategy 2") — gated only by version count / external-scanner-state / cost limits. The two strategies coexisting is why real recovery trees contain both a recovered structure and skip-ERROR nodes. The implementation phase must cross-check each step against parser.c:1476-1568 line-by-line and record deviations in the daily log.
- [x] Missing-token insertion (inner loop of C `ts_parser__handle_error`): for each token `t` in `1..tokenCount` with `nextState(state,t) ∉ {0,state}` (nextState via `tableCell(state,t)` shift target; extra-shift stays in state → skipped by the `== state` guard) where the target state has a REDUCE for the lookahead's leaf symbol — push a zero-width missing leaf (arena missing column; padding = current position; error cost 110), run the potential-reductions pass, and keep the **first** candidate for which the resulting version can shift the real lookahead (C `did_insert_missing_token` semantics: success breaks the loop; not "keep if reductions progressed").
- [x] Lexer error mode: on lex failure, retry with the error state's lex mode; on failure again, skip one character and emit a builtin-ERROR leaf (symbol = builtin error id, carries lookahead char; error cost 500 + SKIPPED_CHAR/line terms per C `ts_subtree_new_error`). `tableCell(state, builtin-error-symbol)` (and ERROR_REPEAT) returns "no actions" so the dispatch loop hands the token back to recovery handling instead of throwing (C `ts_language_table_entry`). The GLRParser lexer-exception call site (currently halt) is rewired into this path; the typed parse error remains only for genuinely unrecoverable exhaustion.
- [x] Strategy 2 skip: wrap the lookahead in an ERROR node — consecutive skips merge (pop the top ERROR_REPEAT and re-wrap both), push at ERROR_STATE=0 (NULL-subtree/empty-link push path needed for entering the error state; `popCount` already models NO_LINK), continue with the next token; these strategy-2 wrappers are non-extra. EOF in error state: push an empty-children ERROR wrapper (C writes the target state as 1) and accept.
- [x] Strategy 1 recover-to-state: iterate the summary **head-outward (smallest pop-depth first)** — the C summary array is built from the stack top outward, and `ts_parser__recover` iterates it in that order with `better_version_exists` breaking on first hit; "deepest-first" would be the reverse. For each earlier state where the lookahead has table actions and that does not collide with an existing version at the same (state, position): pop the span (using `pop_error` nesting when the span top is already an ERROR subtree), wrap it in an ERROR node with **extra=true** (C parser.c:1271 — note the extra flag differs between strategy 1 and strategy 2; it controls trailing-extras absorption on later reduces), fork a version there.
- [x] Subtree-level error-cost accounting: per-node cost side column; constants per `error_costs.h` (missing leaf 110; lexer ERROR leaf 500 + skipped char/line; skipped subtree 100; recovery-event 500); `selectTree` compares error cost **first** (then the existing dynamic-precedence/structure rules); `run()` termination gains the C gate — keep parsing while an in-flight version's error cost undercuts the best finished tree (parser.c:2207-2215 region); `condense`/version comparison uses the same costs (in-error vs not, then cost, then dynamic precedence).

- [x] Focused recovery tests on JSON (smallest grammar): unclosed array/object/string, garbage token, missing comma/colon → exact upstream trees. **Expected-tree provenance**: the only upstream-provided error expectations in the repo are the JS corpus section (kept as the anchor for Phase 3); JSON/Java/TS expected trees are derived from the vendored upstream grammar + the C runtime semantics implemented in this phase, with the derivation (input → which recovery strategy fires and why) recorded in a comment per test, and cross-checked at closure by re-deriving at least two of them independently in the audit.
