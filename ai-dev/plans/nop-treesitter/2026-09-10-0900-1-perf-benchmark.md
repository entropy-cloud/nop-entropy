# Performance benchmark: JMH suites, C-reference comparison, memory profile, tuning log (M4, part 2)

> Plan Status: active
> Last Reviewed: 2026-09-10
> Source: ai-dev/backlog/nop-treesitter-roadmap.md item 13; nop-benchmark JMH pattern (jmh 1.33, annprocess provided)

## Purpose

Establish measurable performance characteristics of the pure-Java tree-sitter runtime (PERF-01..05): reproducible JMH benchmarks for JSON and Java parsing, a C-runtime comparison harness for the roadmap's "within 3x of C" target, a memory profile, and a tuning log.

## Current Baseline

- Items 2-12 `done`; 381 tests green; checkstyle 0; hollow scan 0.
- In-repo JMH precedent: `nop-benchmark/pom.xml` uses `jmh-core` 1.33 (compile) + `jmh-generator-annprocess` 1.33 (provided), benchmarks in `src/main/java` with a `main()` runner (`TestReflection`). JMH benchmarks in test scope work with the same annotation processor auto-discovery (processor on the test-compile classpath).
- C reference: `~/sources/treesitter/tree-sitter` (lib/src/lib.c) + vendored-equivalent grammars at `~/sources/treesitter/grammars/` — machine-local, read-only; the item 11 oracle (`_tmp/ts-oracle/tsoracle`) already builds from them with a `cc` one-liner pattern proven in this repo.
- `TSParser.parse(Language, String|byte[])` + `TSTree.toSexpString(false)` are the hot path; `SubtreeArena.size()` exposes allocated node count for the arena profile.

## Goals

- **PERF-01/02**: JMH benchmarks in `src/test/java/io/nop/treesitter/bench/` — JSON parse at 10 KB / 100 KB / 1 MB deterministically generated sources; ops/s + gc.alloc.rate.norm recorded.
- **PERF-03**: Java parse benchmark — single ~10 KB file and a 25-file synthetic project per op.
- **PERF-04**: memory profile — JMH GC profiler results plus arena node-count growth across input sizes, recorded in the tuning log.
- **PERF-05**: `nop-treesitter/docs/perf-tuning.md` — methodology, numbers from this machine, C comparison, what worked / what didn't.
- Roadmap target verdict: Java-vs-C throughput ratio on JSON and Java stated with evidence; if the 3x target is missed, the measured gap and its cause are documented (the target is a measurement outcome, not a gate to hide).

## Non-Goals

- Performance optimization work itself (any tuning beyond what items 2-12 already shipped is out of scope; findings become recorded candidates).
- Committing benchmark inputs (all fixtures are generated deterministically at setup).
- CI integration of the full benchmark run (minutes-long; only a smoke test runs in the suite).

## Scope

### In Scope

- `nop-treesitter/pom.xml`: test-scope `jmh-core` + `jmh-generator-annprocess` (version property 1.33).
- `src/test/java/io/nop/treesitter/bench/`: `BenchSources` (seeded deterministic generators for the three JSON sizes and the Java file/project), `JsonParseBenchmark`, `JavaParseBenchmark` (`@Benchmark` methods returning the sexp length through a `Blackhole`), `TreeSitterBenchmarkRunner` (main: warmup 3 × 1 s, 5 × 1 s, gc profiler, text results to `_tmp/`), `TreeSitterBenchmarkSmokeTest` (fork=0, 1+1 tiny iterations — proves every benchmark method executes; runs in the normal suite).
- `bench/run-c-reference.sh`: builds the C reference harness from `~/sources/treesitter/tree-sitter` + `~/sources/treesitter/grammars/{tree-sitter-json,tree-sitter-java}` into `_tmp/ts-bench/` (clear error + non-zero exit when the reference checkout is absent — no silent skip), times the same generated inputs via a small C main loop, prints ops/s.
- `nop-treesitter/docs/perf-tuning.md` (PERF-05).

### Out Of Scope

- Everything else in the module; incremental-parse benchmarks (mechanism covered by item 9's equivalence tests; can be a follow-up).
