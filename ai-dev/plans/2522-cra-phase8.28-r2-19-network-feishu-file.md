## Purpose

关闭 R2-19 批的 7 项已确认缺陷（P1×7；cra-index open 七行 :276/:277/:278/:287/:289/:289/:291 附近 live 2026-11-01 回读全 open 且批次列=R2-19；B1-07/B1-08 暂计转正随本批落账，对称条款「消费面回撤即转条件化 P2」成文；C10 缺保护 15 条中 3 条与本批成员对应、随批承载 3 条半边口径[勘误 5]）。核心结果面有六：①**FeishuClient send 有界化**（C3-015，MA-04 主，←C6-024 升格对齐吸收成员 + CL-005/CL-006 线索并入）——WS 全部写（心跳/握手/ACK）经 `sendBinary(...).get()` 无超时跑在单线程 scheduler（心跳+重连唯一承载线程）上，半开连接即心跳/重连整体死锁且 `connected` 恒 true 无告警面（F5 挂死不可见）。②**重连单飞/世代守卫**（C1-009，MA-05 主，B1-07 转正，←C3-017 吸收成员）——onClose/onError 双入口双调度 + `started` 跨代复用 + stop→start 重启窗口陈旧回调 → 双活/三活 WS（消息双份投递 + ACK 双发协议违约 + fd/线程泄漏）。③**stop×reconnect 竞态**（C6-021，MA-06 主，B1-08 转正，←C3-016 吸收成员）——stop「检查后建立」窗口无世代复核：stop 后新建 WS 孤儿连接无人关闭、listener 复活 connected（优雅停机语义违约）。②③同文件相邻但修复点互异**不并族、两单同批实施**（merge-adjudication MA-06 注记 + family-clustering :519 明文）。④**OkHttp future 完成保障**（C3-001，future 族第 4 例）——fetchAsync/uploadAsync onResponse 无 try/catch 兜底：`body().string()` 中途断连 IOException 被 OkHttp `signalledCallback` 吞掉，future 永不完成，同步调用方永久阻塞。⑤**verifyAndRename 强制**（C3-005，错误以成功交付族第 4 例）——默认 DownloadOptions + 无校验头源时 `expected==null` 分支跳过 rename：下载报成功但目标文件永不产生（.part 滞留）。⑥**SftpClient 全链超时 + BASE64_FORM 流关闭**（C3-024/C6-005）——jsch 默认 timeout=0 无限挂起（SftpConfig 无 timeout 配置面）+ 三实现 BASE64 上传 `IoHelper.readBytes` 不关流确定性 fd 泄漏。批末 roadmap 8.28 → done，cra-index 七行收敛（B1-07/08 转正注记随行）+ C10 三条成员面注记。

## Risks And Rollback

- **裁定②③世代令牌引入的行为面风险**：重连单飞+世代守卫改变「双终态回调自由双调度」与「stop 后建立连接存活」现状——消费方 FeishuConnector 在停机期的可观测行为从「可能孤儿连接」变为「确定性关闭」，重连从「可能双活」变为「恰好一在飞」；前提(a) 复核结论若推翻双终态序列前提，红②主判据降级为触发(b) 单形态（工单存在性不受影响——merge-adjudication §二 MA-05 明文）；回滚 = 守卫行 revert 单点可逆，连接计数钉防形态漂移。
- **裁定①超时预算的行为面风险**：send 有界化引入「大帧慢链路误杀」可能（预算取值不当将健康慢发送误判超时→close→重连循环）——预算缺省对齐 15s 量级并配置化（裁定①定夺）；心跳 send 超时与重连风暴的耦合（超时 close→onError→重连→再超时的循环上界由 reconnectAttempt 退避 RECONNECT_MAX_DELAY_MS=30s 既有机制承载）；`TestFeishuClient` 值捕获钉防行为漂移。
- **裁定⑤⑥ PA 张力的授权风险**：nop-http-api FileDownloadSink 单文件触碰若 draft review 推翻预设（裁定备选 impl 侧形态胜出），Phase 2 组 B 的 C3-005 落点随裁定改写——两案均在裁定⑤⑥一次定夺，无第三形态；回写义务（batch-proposal :299）仅在预设成立时执行。
- **E3 盲区的验证完备性风险**：批次验证命令实触 3/7 载体——补充焦点腿为强制项（Phase 2/3 双登记），若执行期遗漏将造成 feishu/sftp 四成员零验证收口（closure audit 专项核对项）；两模块基线 70 tests 在案为焦点腿绿色参照。
- **红①红④挂死红的可复现性风险**：缺陷态为确定性挂死（latch 挂起/半关闭断连均确定性构造，非竞态红），红证稳定；风险在测试自身超时设计（缺陷态断言必超时红——钉的失败模式是超时而非断言失败，须给足但有限 timeout 并在钉内注释失败模式语义）。
- **上游链环境噪声风险**：`./mvnw test -pl nop-network -am` 触达上游闭包（nop-core/nop-kernel/nop-commons 等），nop-core `TestResourceCacheInvalidationChain` 负载 flake 有 2517–2521 五批先例（勘误 8）——三联裁定执行并留痕；feishu/sftp 焦点腿上游闭包含 nop-core 同面。
