## Current Baseline

- **SHA256 缺口（confirmed live gap）**：`HttpPluginResourceResolver.java:27` Javadoc 声称"下载文件的完整性有SHA256校验码保证"，代码未实现：`resolvePluginResource`（`:52-60`）缓存命中直接返回（无重验）；`download`（`:62-87`）HTTP 下载后直接 move，无任何校验。
- **设计规格（05 §五/§六）**：hash 来源优先级 = 响应 header（`X-Checksum-Sha256`）/ `{url}.sha256` 文件 / 配置显式预期；校验时机 = 下载后 move 前（临时文件上）；失败 = fail-fast（删临时文件 + 抛异常，**绝不使用未通过校验的 jar**）；缓存重验 = 重算 hash 与 `.sha256` 比对（可配置跳过）。
- **可用基础设施**：`IHttpResponse extends IHttpHeaders` 提供 `getHeader(name)`（`nop-http-api/.../IHttpHeaders.java:21`）；`httpClient.download(...)` 返回 `IHttpResponse`（`IHttpClient.java:67`）；`FileHelper.calculateMD5(File)`（`nop-kernel/nop-commons/.../FileHelper.java:676-690`）是文件摘要实现先例；`HashHelper.sha256(byte[], byte[])`（`nop-kernel/nop-commons/.../crypto/HashHelper.java:86`）只接受 byte[]——文件摘要 helper 放 resolver 私有静态方法（**不新增 nop-commons 公共 API**，避免公共面 + 独立测试负担，见 Phase 1）。
- **错误码**：`PluginManagerErrors` 已有 `ERR_PLUGIN_*` 系列（最新 `ERR_PLUGIN_RELOAD_NOT_SUPPORTED`，`PluginManagerErrors.java:151`）；无 SHA256 相关错误码——需新增。

## Execution Plan

### Phase 1 - HttpPluginResourceResolver SHA256 校验补齐

Status: completed
Targets: `HttpPluginResourceResolver.java`、`PluginManagerErrors.java`、`TestHttpPluginResourceResolver`（新）

- Item Types: `Fix | Decision`

- [x] **`Decision`：无 hash 来源的行为**——header / `.sha256` 请求 / 配置均无预期 hash → **显式失败**（`ERR_PLUGIN_CHECKSUM_NOT_AVAILABLE`，fail-fast；理由：Javadoc 已声明校验保证、"绝不使用未通过校验的 jar"（05 §五）、No Silent No-Op 规则——不允许静默降级为无校验下载）。
- [x] **`Decision`：配置预期 hash 的载体**——设计 05 §五.2 "调用方在 plugin id 元数据中携带预期 hash"，但 `ArtifactCoordinates`（nop-api-core 公共 API）无 hash 字段，新增字段属公共 API 变更（设计 §八 拒绝 API 面扩大），且 resolver 接口 `resolvePluginResource(coordinates)` 无额外元数据通道 → 载体裁定为 **resolver 级 expected-hash map**：`HttpPluginResourceResolver` 新增 setter 注入 `Map<String,String>`（key = `groupId:artifactId:version`，value = hex hash；宿主应用经 beans.xml 配置）；优先级 header → `.sha256` 请求 → 该 map（覆盖设计 §五.2 来源 2 的语义）；**执行时在 05 §五.2 追加修订注解**（设计为权威来源，冲突必须同步）。
- [x] **`Decision`：缓存篡改语义**——缓存重验发现 `.sha256` 不匹配 → **fail-fast 抛 `ERR_PLUGIN_SHA256_MISMATCH`**（篡改应报警而非静默重下载，与"绝不使用未通过校验的 jar"一致）；设计 05 §四"不匹配 → 重新下载"表述与本裁定冲突，**执行时在 05 §四 追加修订注解**（设计为权威来源，冲突必须同步）。
- [x] **`Decision`：缓存重验与遗留缓存**——缓存 jar 且 `.sha256` 存在 → 重算比对（fail-fast，见上）；缓存 jar 但 `.sha256` 缺失（pre-W7 遗留）→ **重新下载并校验**（不静默使用未校验缓存）；跳过配置 `nop.plugin.skip-cache-verify=true` 时**同时跳过重验与遗留重下载**（启动优化逃生门，05 §五.5；配置读取沿用 `@InjectValue` setter 模式，与 cacheDir/serviceUrl 一致）。
- [x] `Fix`：新增错误码 `ERR_PLUGIN_SHA256_MISMATCH`（参数：pluginId、期望 hash、实际 hash）与 `ERR_PLUGIN_CHECKSUM_NOT_AVAILABLE`（参数：pluginId、url）。
- [x] `Fix`：`download` 补校验链路——hash 获取（响应 header → `.sha256` 请求 → 配置 map）→ 临时文件重算 SHA256（resolver 私有静态方法，不新增 nop-commons API）→ 比对（**大小写不敏感，归一为小写 hex**）→ **通过才 move + 写 `{jar}.sha256`**（内容 = 小写 hex；`.sha256` 响应体解析：trim + 首个空白分隔 token；写失败 → 删除已 move 的 jar + 抛异常，保持缓存一致性）；`download` 前 `FileHelper.assureParent(jarFile)` 建 Maven 风格子目录；**遗留缓存重下载路径 move 前须先删旧 jar**（`FileHelper.moveFile` 无 REPLACE_EXISTING 语义，目标存在会返回 false → `ERR_PLUGIN_DOWNLOAD_RENAME_FILE_FAIL`）。
- [x] `Fix`：`resolvePluginResource` 缓存命中路径补重验（含跳过配置；遗留缓存走重下载）。
- [x] `Fix`（测试）：新增 `TestHttpPluginResourceResolver`（**手写 IHttpClient stub**——manager 测试 scope 无 mock 框架，仅 junit-jupiter；stub 覆写 `downloadAsync`/`fetchAsync`（`download`/`fetch` 为 default 包装方法）+ `DefaultHttpResponse`（`io.nop.http.api.support` 已有，setter 可构造）；临时 cacheDir + 显式 service-url 模板）——成功落盘 + `.sha256` 写出、校验失败（临时文件已删 + 错误码/参数断言）、header 来源、`.sha256` 文件来源、配置 map 来源、缓存命中重验通过 / 篡改失败、跳过配置生效、无 hash 来源显式失败、遗留缓存重下载、`.sha256` 写失败清理。
- [x] `Proof`：编译验证 `./mvnw compile -pl :nop-plugin-api,:nop-plugin-manager,:nop-plugin-support -am -T 1C` 通过。

## Risks And Rollback

- **无 hash 来源 fail-fast 的兼容影响**：存量部署若服务端不提供 hash，所有新下载将显式失败——这是 Javadoc 已声明契约的兑现（非新破坏）；部署方需补 hash 源（header / `.sha256` / 配置 map）。执行时在 docs 中写明该要求。
- **W6 未完成风险**：Phase 2 复核项与 Phase 3 变更检测章节依赖 W6 落地；W6 未 completed 时先执行独立项（Phase 1 全部、Phase 2 审计与非 HMR 项），复核/接线章节后置并记录。
- **缓存重验性能**：重验读全文件计算 hash，大 jar 有 IO 开销——`nop.plugin.skip-cache-verify` 配置提供逃生门（设计 05 §五.5 允许）。
- **测试隔离**：resolver 测试用临时 cacheDir（JUnit temp dir 或项目 `_tmp/`），不写全局 `/nop/plugin` 默认目录；全局配置注入测试中注意恢复原值（W5 已有先例）；`download()` 首次落盘需先 `FileHelper.assureParent(jarFile)`（Maven 风格子目录可能不存在——现有代码无建目录逻辑，E2E 测试会首跑即暴露）。
