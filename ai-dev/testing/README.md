# ai-dev/testing — 手工测试与验收记录

> Status: active
> 受众：开发 nop-entropy 平台本身的 AI / 开发者（不是业务应用使用者）

## 定位

本目录记录**手工测试 / 平台自测**过程中发现的现象与验收结论，作为缺陷修复与回归的输入。
与 `bugs/` 的分工：

| 目录 | 内容 | 时机 |
|------|------|------|
| `testing/` | 手工测试发现的现象、复现步骤、预期/实际、验收结论（**问题发现阶段**，可能尚未定位根因） | 测试过程中随时记录 |
| `bugs/` | 已定位根因的缺陷修复笔记（问题→诊断→根因→修复→测试） | 根因明确、修复落地后 |

一个 `testing/` 条目在根因明确后可**升级**为 `bugs/` 记录，并在本目录条目标注对应 bug 笔记/commit。

## 文件命名

按日期归档到 `{year}-{month}/` 子目录，文件名以 `YYYY-MM-DD-` 前缀加简短主题：

```
ai-dev/testing/
  2026-10/
    2026-10-17-flux-manual-test-findings.md
```

## 条目结构

每个条目至少包含：

- **测试环境**：应用、渲染模式、构建/commit、数据
- **发现清单**：逐条给出 —— 现象 / 复现步骤 / 预期 / 实际 / 疑似范围 / 状态

状态取值：`open`（未处理）/ `investigating`（定位中）/ `fixed`（已修，附 commit）/ `verified`（已复测确认）/ `wontfix`（不修，说明理由）。
