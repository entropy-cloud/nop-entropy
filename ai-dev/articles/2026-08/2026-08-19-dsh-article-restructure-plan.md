## 四、新增小节的写作要点

**1.1（答疑问②）**：先引[19]的三境界划分（注明转引），指出它回答了"为什么 DSH 的插件化不同"的前半；再补作者的第四刀——从前两境到第三境的本质跃迁是**插件成为差量**：npm 包无生命周期与逆（装了≠活着）；Spring 组件有生命周期但 deactivate 与 activate 分离、卸载无结构保证（VSCode 同病，87/100 需重启，[1, §1.2.1]）；Pi 的 Extension 无依赖注入、不可卸载、加载序即优先级（[17]）；Cordis 插件=带逆、带坐标、带依赖声明的差量单元。"一切皆插件"的统一不是把 Agent Loop 和 Memory 捏成同一种东西（答疑问①），而是把它们统一为**施加在同一坐标系上的差量**——统一在代数结构，不在功能形态。

**1.2**：用[18]的数字量化"一切皆插件"（内核/框架族/包组三级），vendor 策略三层理由压缩为一段；收在"Base 不是空集而是最小幺元"——为 1.3 的问题③埋线。

**1.3（回答占位处的三个数学问题）**：
- 加号如何精确定义？→ 运行时结构空间：effect 的 twisted composition ⊕（旧§三）；scope 链：分层遮蔽 nearest-wins（[17] ToolLayer.view() 四步算法作实例）；事件：注册序。三处都不是普通加法。
- 顺序等价吗？→ 不等价（serial/bail/waterfall 的 dispatch mode、LIFO 逆序、遮蔽近者优先）；但代数设计让"不该依赖顺序的地方不依赖"（结合律、服务单写者）。
- 无 Base 能定义吗？→ dsh：插件间不直接组合，都组合到运行时坐标上（星型拓扑），kernel 是事实幺元；Nop：差量链 Δn⊕…⊕Δ1⊕Base，差量可先于 Base 组合成新差量（结合律保证良定义）。**链型与星型的对照**是本文可打出的一记原创观察，直通 3.1 坐标系。
- 节末抛出："要让'+'真正成为数学，还需要坐标系——这是第三篇的推论一。"
