## 二、背景与动机

R2-20 批 6 项（P1×6）覆盖连接生命周期三类资源面：**会话属主域**（MA-01 = C1-008+C3-018+C6-020 三登记一工单：`removeConnection` :44 无条件清订阅 + `addConnection` :36 接管删除，在「迟到 close」与「CONNACK 先于注册」双窗口下抹掉新连接已登记订阅——设备重连后下行路由静默失效，客户端自认仍订阅不重发 SUBSCRIBE、QoS0 无错误可见；`findConnections` :73-74 永失配 + `sendAsync` success(null) 半个成功形态）、**下载收尾线程域**（MA-03 = C3-004 主+C6-006 吸收：下载完成回调线程内嵌套同步 `get(30s)×2` 复用同一 client——[R1 Major-F1 勘误后机制] HC5 `ioThreadCount` 缺省 = `Runtime.availableProcessors()` 非审计所记 1，多核缺省下嵌套请求由其他 dispatch 线程服务、不构成缺省全停摆；生产影响 = 每次下载占用一个 reactor 回调线程 60s（30s×2 双探测）+ C6-006 超时后内层不取消在途请求滞留池；全停摆为 `ioThreadCount=1` 配置面[CL-021]形态）、**工厂生命周期域**（MA-07 = C1-001 主+←C6-014：init 挂在 newInstance 非幂等——logBody 拦截器共享列表 :113-115 每连接 prepend 无界累积 + timer/executor :121-128 检查-创建竞态双建泄漏单线程定时器 + destroy :137 先置位竞态使 newInstance :170 在已销毁 executor 上投递）、**资源清理三单**（C6-017：doStart bind 两抛出点 :189/:195 零清理，每次「启动失败→再启动」净增 2×CPU 个非 daemon I/O 线程 + selector/fd 泄漏；C6-018：「session 已连、channel 未开」失败 SSH 会话无人 disconnect，R2-19 的 connect(ms) 超时路径即触发前提；C6-019：sendEmail 每次 `createClient` :169 新建 SesClient 从不 shutdown，HTTP 连接池随发送次数无界累积，对照 Yunpian 兄弟 finally close 同族偏差）。本文档一次裁定 6 成员 + 测试缝（裁定⑦），使实施只有一种合法形态；B1-06 终裁落账口径、C10 三条半边集与 vertx-mqtt 部署包络确认申报随批承载（条款见四、五）。

## 三、核心设计契约

### 3.1 裁定①：removeConnection 属主校验 + acceptEndpoint 先注册后 accept（MA-01，三登记一处闭合）

- **属主校验形态（预设，一次定夺）**：`removeConnection` 改 compute 单点定夺——`sessions.compute(conn.getClientId(), (k, cur) -> { if (cur == conn) { subscriptions.remove(k); return null; } return cur; })`。原子性论证：CHM compute 持该 key bin 锁，属主判定（cur == conn）、会话删除（返回 null）与订阅清空（subscriptions.remove）三者同一临界内完成；并发交错下任意 `addConnection` 的 `sessions.put`（:34）要么整体先于该 compute（cur 已为新连接 → 非属主 → 订阅不清）、要么整体后于（新连接注册在其后，其 SUBSCRIBE 更后 → 不受影响）——窗口②（旧连接迟到 close 无条件清新连接订阅，:44）确定性消除。该方法与既有 :43 两参守卫同法对齐（merge-adjudication MA-01 修复点「对齐 `sessions.remove(key, value)` 两参守卫」明文），且将「两参条件删 + 条件清订阅」收敛为单临界（两参 remove 后再独立清订阅仍留窄缝，见备选拒绝）。

## 六、拒绝了什么

| 被拒方案 | 拒绝理由 |
|----------|---------|
| ① removeConnection 用 get-校验-remove 两步形态 | get 判属主与 subscriptions.remove 之间的 TOCTOU 窗口内「A 判属主→B addConnection+SUBSCRIBE 落表→A 补清」交错复开窗口②窄缝；compute 单临界一次定夺无此缝且与 :43 两参守卫同法 |
| ① addConnection 补属主语义（接管清订阅也条件化） | 超出 merge-adjudication MA-01 修复点登记（removeConnection 属主校验 + acceptEndpoint 顺序），未申报扩张禁令[R1 Major-F2]明文禁止；窗口①消除由 reorder 的次序不变式达成，addConnection 接管清旧订阅语义在次序不变式下恢复正确 |
| ① accept() 留在构造函数内 + 仅靠属主校验 | 窗口①为 C6-020 独立登记面，属主校验只封窗口②；构造内 CONNACK 使「SUBSCRIBE 早于注册」经真实路径可达，顺序调整是唯一消除形态（merge-adjudication 修复点明文） |
| ② 非阻塞链式 whenCompose 重构收尾段 | 三实现回调形态互异（reactor FutureCallback/jdk whenComplete/okhttp onResponse），逐实现异步化 diff 面远大于缺陷本体；阻塞等待仍须保留（rename 依赖探测结果），收益仅 worker 线程不占，代价三份异步链审查面——与「三实现同 diff」可审查性纪律冲突 |
| ② 专用卸载池 | 新增线程面 + 生命周期归属无解（谁创建谁销毁）；globalWorker 平台共享池同族先例在案（JdkHttpClient :447-449）且任务 60s 有界 |
| ② promise.complete 提前至 rename 之前（卸载段与完成解耦） | R11 族纪律（成功信号与产物落地原子性，file-transfer-design §3.3）——成功信号后 rename 失败即错误以成功交付；2522 裁定⑤已裁定 rename 无条件强制 |
| ② CL-021 新增配置项/调整 createReactorConfig 缺省 | Non-Goals 明文不预置新配置面；卸载后 reactor 线程无阻塞点、=1 自死锁主触发面随修复消除——独立配置项留 CL 轨 |
| ③ 纯 AtomicBoolean CAS 快速返回幂等 | CAS 失败方立即返回时胜出方可能未完成 timer 创建——newInstance 以 null timer 续跑，「init 返回即就绪」不变式破坏；synchronized 临界 + 早退语义完备且 newInstance 非热路径 |
| ③ init 重复调用抛错（照抄 SimpleRpcServer Guard 兄弟） | start 重复调用是调用方错误（抛错正确）；init 是newInstance 每次调用的懒初始化、重复调用属正常流——早退是唯一正确语义（对照不对称性登记 §3.3） |
| ③ 世代令牌用 AtomicLong 计数（照抄 feishu lifecycleGeneration） | rpc 工厂单程生命周期（无 stop→restart 变迁），布尔终态世代充分；多变迁计数为连接生命周期语义，不同族照抄引入无消费点的复杂度（C6-015 重启语义若立项由 R4-27 演进） |
| ④ try-finally + success 标志统一清理 | 两抛出点语义不同（sync 抛出 vs 异步失败复检），finally 共享须条件化 success 布尔；提取清单方法与 doStop 对照性、可读性更优且两抛出点显式覆盖 |
| ④ 清理点重读 this.workerGroup 判定所有权 | 注入方可能在创建与失败窗口之间 setWorkerGroup——所有权以创建时刻快照判定，重读即竞态判错（误关外部共享组） |
| ⑤ disconnectQuietly 提取公共 helper | 单一调用点两行内联；close() 既有守卫形态（isConnected 检查）面向正常关闭语义，构造失败窗 session 恒已连无需复用——提取即无消费扩张 |
| ⑤ 行为级红⑤（loopback 构造 session.connect 成功 + channel.connect 失败） | 须完整 SSH KEX 服务端（session.connect 含密钥交换），手写实现超零新依赖纪律；jsch Session/Channel 不可跨包子类化（2522 R2 Major-3 亲证）使注入假体不可达——源码级伴随钉为已裁定等价证据形态 |
| ⑥ bean 级 SesClient 单例（OssFileServiceClientFactory 形态） | 「逐次解析、每次新建」为登记家族契约（凭证轮换下次发送即生效），bean 级缓存改变轮换可见性属设计层扩张；连接池复用收益不属本缺陷登记面——finally 配对为最小契约面变更 |
| ⑥ finally 内 shutdown 预包 try-catch-ignore | 对齐 Yunpian 兄弟裸调形态；SDK shutdown 异常语义以核实义务承接（§3.6），证实可抛时既定降级形态生效——禁预置双形态 |
| 红② mockwebserver/嵌入 SSH 服务端新依赖 | loopback HttpServer 挂起 handler 零新依赖且 2505/2522 基建先例在案（红②预设）；SSH 服务端同 ⑤ 被拒形态 |
