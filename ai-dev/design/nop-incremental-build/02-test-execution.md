## 一、设计结论

1. **默认形态 = 每模块一个 fork 子 JVM**。同 JVM 执行在本仓不安全：测试扩展在 `afterAll` 触发全局 `CoreInitialization.destroy()`（连带反射缓存与全局缓存注册表清理），【实测】834 处在测试源码中自行调用同一方法，`BeanContainer` 存在全局注册写入。这些都是 Surefire `forkCount=4` + `reuseForks=true` 原本要控制的隔离面。
2. **cwd 必须等于模块 basedir**【实测】。`dev:` VFS 根优先取配置项，为空才回落到惰性缓存的进程当前目录；且 `user.dir` 系统属性在 JVM 生命周期内**不可用于纠正**。因此只能靠子进程的工作目录设置。
3. **每模块独立且定序的 classpath，禁止跨模块合并**【实测】。【实测】25 个 reactor 模块各带 `bootstrap.yaml`；lint 子系统在主与测试资源中放了**同名不同内容**的服务注册文件；多个模块各存一份同名 suite 目录。合并即污染，且同名资源 first-match 生效。
4. **快照录制模式硬禁用**。真实开关是两个系统属性加一个编译期注解，**不存在**统一的"快照模式开关"；更危险的是配置值在首次访问时被**静态缓存**且每次启动复用同一份缓存 map，而系统属性设置是单向不可撤销的——常驻 JVM 内一旦注入录制开关，该进程之后**永久**处于录制状态并持续改写工作树。
5. **禁止 JUnit JVM 内并行**。【实测】全仓 0 个并行配置文件、无任何执行属性，即 CI 侧并行全关。服务擅自开启会产生"本地绿 CI 红"。允许的并行上限是与根 pom 等价的 fork 级并行。

## 二、为什么不能用同 JVM

| 维度 | 同 JVM 执行 | 每模块 fork 子 JVM（采用） |
|------|------------|--------------------------|
| 全局静态态 | 全局容器销毁跨类交错、`BeanContainer` 全局注册互相污染；本仓测试文档已记录容器测试在类间交错时整类失败 | 与 `reuseForks=true` 语义对齐（fork 内串行、fork 间隔离） |
| 堆与元空间 | 无上限、无 OOM 隔离，无法复现 `argLine` | 逐模块复制 effective-pom 的 `argLine` |
| cwd | 只能改进程级当前目录（部分路径可修，直接读 `user.dir` 的测试修不了） | 子进程工作目录直接设为模块 basedir |
| 进程级副作用 | 测试里的进程退出、多 JVM spawn 场景不可控 | 只杀子进程 |
| 静态属性 | 跨请求、跨类泄漏且不可回滚（快照开关即典型） | 每批次全新 JVM |
| 延迟 | 最低 | 增加数百毫秒 JVM 启动；相对秒级构建骨架仍是数量级收益 |

次选方案（同 JVM + 每测试类重启一次全局容器）不采用：无法限堆、无法隔离进程级退出、无法修 cwd。

## 三、执行上下文

每次测试执行是一个自包含的子进程上下文，必须具备：

| 维度 | 契约 |
|------|------|
| 工作目录 | 该模块的 basedir（**硬性**，执行前自检，不符即失败而非降级） |
| classpath | 该模块测试输出目录 → 该模块主输出目录 → 依赖（含物化后的 intra-project 目录），顺序固定并落盘 |
| JVM 选项 | 该模块 effective-pom 的 `argLine` 原文（含堆限制、GC、JVM 模块开关等逐模块差异） |
| 系统属性 | 该模块 `systemPropertyVariables` + 服务注入的属性，并记录优先级 |
| 环境变量 | 需在**服务进程启动时**注入（子进程继承）；不能在执行期动态设置 |
| skip 标记 | 该模块 `skipTests=true` 时整体跳过 |

### 3.1 配置优先级陷阱

【实测】本仓配置优先级是**环境变量 > 系统属性 > 配置文件**。因此：

- 服务进程的环境变量会**静默覆盖**注入的系统属性。若服务继承了一个 `nop.` 前缀环境变量，注入的 surefire 系统属性将失效。
- 服务必须在启动时**审计自身环境变量**，发现 `nop.` 前缀变量即拒绝启动或要求显式确认，而不是默默让注入失效。

### 3.2 数据库依赖的裁定

【实测】容器测试的扩展在类级**强制**使用内存 H2（每次运行一个唯一实例名），且测试基类的运行期判定会让测试配置**覆盖一切外部来源**。因此：

- 向 surefire 系统属性注入数据源配置，对容器测试类**无效**——这是事实，不是缺陷。
- 需要外部数据库的测试必须显式声明（外部环境依赖标记）；服务在缺少该环境时记为**跳过**（非失败），并单独统计。
- 需要容器的测试（CDC 连接器测试、消息中间件端到端测试、多 JVM 集群测试）同此规则。这些测试在本仓中已有若干处人工禁用标记，服务不得把它们当作"应跑"的回归面。

## 四、测试类路径约束

【实测】测试基类由 class 文件位置反推目录结构，并**惰性断言**目录名必须是 `target`（断言在首次调用目录推导方法时触发，不在构造器内）。由此产生三条硬约束：

1. 测试输出目录必须以**真实目录条目**出现在 classpath 上。JAR 化或把多模块测试输出聚合到单一目录，会让基类的全部目录推导失败。
2. 来自测试产物包的测试类布局非标准，会触发该断言。【实测】本仓 8 个以上模块消费此类产物。
3. **禁止为每个模块建 child-first 隔离类加载器**：基类用宿主加载器定位自身 class 文件，若父加载器持有公共类而测试类在子加载器，资源定位返回空并直接抛异常，测试基类整体无法构造。

## 五、快照与录制安全

### 5.1 真实开关

| 开关 | 载体 | 后果 |
|------|------|---------|
| `nop.autotest.force-save-output` | 系统属性（可由注解处理器从注解转换而来） | 写测试数据输出目录并按方法抛错——**污染工作树** |
| `nop.autotest.disable-snapshot` | 系统属性 | 整类**静默不校验** → **假绿**，比文件污染更危险 |
| `@NopTestConfig(snapshotTest = RECORDING)` | 编译期注解 | 录制模式 |
| 方法级快照保存开关 | 注解 | 单方法录制 |

初版设计假设存在统一的"快照模式开关"并靠注入属性控制，方向恰好搞反了：真正的首要风险不是"误进录制污染文件"，而是**静默退化为不校验**。

### 5.2 硬禁用规则（伪代码，语义契约）

```
执行前静态扫描选中类的编译后字节码或源码：
    若存在 @NopTestConfig(snapshotTest = RECORDING)
    或 方法级快照保存开关为开启
    → 拒绝执行该测试，返回结构化错误（错误码 + 建议动作），绝不静默切换

每次批次执行前：
    显式置 disable-snapshot = false、force-save-output = false

每次批次执行后：
    校验工作树洁净（覆盖测试数据目录与运行产物目录，含嵌入本机绝对路径的子目录名）
    若被写入 → 中止该模块后续批次，报告"测试数据被污染"并给出被改文件列表
```

录制能力**不对外暴露端点**（G9）。录制只能手工走构建工具在干净进程中进行。子进程隔离使这条约束天然可实现。

## 六、测试发现的现实约束

| 机制 | 选择器行为 | 裁定 |
|------|-----------|------|
| 普通测试方法 | 类级与方法级选择器均可用 | 方法级优先（类级会拉入全部方法，违背增量前提） |
| 参数化测试 | 方法级选择器可选中，展开为多个调用 | 反馈主键必须是 JUnit 唯一标识，**不能**用"类#方法" |
| 变体测试（自定义参数源） | 同参数化；变体集合由磁盘数据决定，且**发现期即写工作树** | 整类全跑；执行后按 §5.2 校验洁净 |
| 动态测试 | 成员运行时决定，方法级选择器无法收敛 | 整类全跑 |
| suite 家族（运行时扫描目录发现成员） | 成员由运行时扫描决定 | 整类全跑 |
| markdown/模型驱动的用例 | 由被测模型文件决定用例集合 | 整类全跑；模型变更即全量测试 |
| 旧版 JUnit 引擎 | reactor 内无此类测试 | 无需对应引擎 |

**硬约束**：凡测试成员由运行时或磁盘数据决定的，整类全跑。符号索引无法把影响收敛到单个这类用例——这写在选择算法里容易被误当成可优化项，实际它是**发现机制**问题。

【实测】变体测试全仓仅 1 个使用者；动态测试分布在若干模块（agent 调度、流处理、语言查询、lint 规则套件等）。

## 七、超时

三层缺一不可：

| 层 | 作用 | 初值 |
|----|------|------|
| 执行层截止时间 | 单个测试方法、单个模块批次的上限 | 方法 30s / 批次 120s（可配） |
| 子进程看门狗 | 进程挂死时强制终止。Surefire 的进程超时配置在本仓处于注释状态，需自行实现 | 批次上限 + 宽限 |
| 测试自身注解 | 只对声明它的类生效，且无法打断不可中断代码——**不能替代前两层** | 由被测代码自行声明 |

超时动作必须是**终止子进程 + 从队列摘除 + 标记为超时中止**。否则一个挂死测试会堵死整条队列，而常驻服务的队列不会随构建生命周期一起消失。

## 八、反馈契约

| 项 | 契约要求 |
|---|---|
| 主键 | JUnit 唯一标识 |
| 定位 | 模块、类名、方法名 |
| 显示名 | 变体名体现在显示名里（测试基类依赖它解析变体） |
| 状态 | 成功 / 失败 / 跳过 / 超时中止 / 外部环境缺失跳过 |
| 异常 | 类型 + 消息 + **过滤框架与测试基建帧后的首个用户栈帧** |
| 标准输出摘录 | 关键信息走日志而非异常消息（快照完成通知走错误码，过滤掉） |
| 是否需重跑 | 失败于快照非确定性、时钟、端口竞争等情况时置真 |
| 是否写过测试数据 | 配合 §5.2 的写后校验 |
| 耗时 | 单测试与模块批次两级 |
