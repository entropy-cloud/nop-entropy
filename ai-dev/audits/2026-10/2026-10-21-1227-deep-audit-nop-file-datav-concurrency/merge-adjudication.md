## §七 结构性发现

1. **限额/上界惯例不对称**：模块已有四个显式行上界配置（export/report/alert/chatbi），唯主查询路径（getDashboardData/getPanelData）与会话/历史读路径缺位——修复方向是"补齐惯例"而非新造机制。
2. **afterCommit 先例未普及**：AR-2 已建立事务内副作用后置范式（submitExecutionAfterCommit），但调度器 register/unregister（CL-019）未复用——同一模块内范式一致性是低成本高收益修复面。
3. **测试范式健康但覆盖偏功能面**：fake clock/decorator seam/时序锚点三件套质量高（C10 时序敏感 0），但竞态/失败清理/资源守恒面 0 覆盖——保护力缺口集中在"坏路径"而非"好路径"。
4. **Protected Area 记录**：nop-file-api（3f/492）本轮审计只读，未发现需改 api 叶的缺陷；CL-014 修复面在 nop-file-dao impl 叶（plan-first 内可实施）。
