## 规则摘要

1. **三态判定**：
   - `同一缺陷`（合并）：同一代码位点 + 同一根因 + 同一失效后果。合并后保留最高严重度；登记主 ID 与被并 ID（被并 ID 不消失，标注「并入 X」）。
   - `同族相邻`（不合并，登记关联）：同根因模式或同代码区，但不同位点/不同后果。互列关联 ID，各自保留。
   - `不同缺陷`：无实质关联。
2. 已知交叉项 8 组必裁；其余 74 条做自主同族扫描补登（同族相邻组 ≤5，宁缺毋滥）。
3. 跨单元关联单列，不合并；CL-001~007 不计入 74，单列。
4. 统计自洽：合并后有效发现数 = 74 − 并入数；给出严重度分布；每条 P1 合并变动单独说明。

- **路径A（回调异常落点 → result 永不完成）→ 并入 C8-012**：与 M2 同位点同根因同后果（C1-003 原文第 13 字段自认「其 future 永不完成侧面属 C3 维度形态，供承接」）。
- **pause/resume TOCTOU 面（路径B）→ 并入 C3-013**：与 C3-013 同位点（RetryEngineImpl:111-155 pause/resume、:499-527 handleExecution*、store updateRecord）、同根因（运维写与执行链写无状态条件 CAS，相遇仅靠乐观锁仲裁且败方异常落点未设计）。

**机制勘误（承重，裁定人独立核验 live code）**：C1-003 与 C3-013 对同一写路径给出相反的存储语义（C1：版本条件更新 0 行抛错；C3：updateDirectly 无版本谓词静默覆盖）。裁定人核验：`nop-retry.orm.xml:183` `versionProp="version"`；`JdbcEntityPersistDriver.java:289` 实体 UPDATE 由 `GenSqlHelper.genUpdateSql` 生成且 **L346-352 追加 `AND version=?`**；`EntityPersisterImpl.checkUpdateResult`（:508-524）0 行且未 disable 版本错误时抛 `ERR_ORM_UPDATE_ENTITY_NOT_FOUND`。**结论：C1-003 的「乐观锁冲突异常」机制正确；C3-013 的「SUSPENDED 被静默翻回 PENDING / COMPLETED 被翻成 SUSPENDED → resume 重放副作用」后果链不可达（败方写必然 0 行抛错，不可能静默覆盖）**。C3-013 复核所述「无版本谓词」系仅看 session 层（OrmSessionImpl:534-547 flushUpdate 不做版本校验）而未下钻 SQL 生成层。

**裁定后 C3-013（主 ID）重述与降级**：缺陷 = 「pause/resume 与在途链终态写相遇时，败方以 ORM 乐观锁异常失败且异常落点未设计——链侧败方导致该轮重试计数丢失/记录停 SUSPENDED、调用方 future 异常或挂起（后者归 C8-012 面）；运维侧败方收到裸 ORM 错误」。原 P2 判级所依赖的静默覆盖/双执行后果不可达；残余后果有界（无数据损坏、无双执行、无永久丢失，resume 可恢复），且高频后果面已被 C8-012/C3-006 计数。**终裁降为 P3（条件化：运维竞争窗口），修复方向=条件状态更新（WHERE status=期望态）+ 败方显式语义**。
