## 二、缺陷族结构（7 族，MA-01 起；覆盖 21 条 = 主登记 7 + 吸收 14）

### MA-01 AttemptCancelToken.appendOnCancel check-then-act（三登记单工单）
- **根因**: `appendOnCancel` 为 check-then-add，cancel 完成后注册的钩子永久失联（丢失取消传播）。
- **成员**: C2-008（P3，live 外部面——掩蔽论证最精确，站内主登记）+ C1-003（P3，live 外部面；模块内面被 L238 同线程前置检查掩蔽）+ C3-002（P3 并入，live 外部面；upSub 勘误后后果链更强——该窗口 up.cancel 为 no-op 且不中断 HTTP fetch）。
- **修复点**: appendOnCancel 改 add 后二次复核 cancelled 补跑（或对齐平台 ICancelToken 实现）——原语一处修复覆盖三登记。
- **族严重度**: **P3**（站级；外部面后果由 WI 3.1 MA-01 族承载）。
- **跨单元**: 与 WI 3.1 MA-01 修复批次对齐；MA-01 侧不得假设本原语无竞态。

### MA-02 ChannelMessageServiceImpl owned fan-out 池生命周期/发布/关闭族（六条单工单）
- **根因**: 自建池生命周期闭环断链（无 destroy-method、close 全仓零调用）+ DCL 缺 volatile 不安全发布 + close 与惰性创建/派发无共享锁、close 不退订 bridge 消费者（复活池）+ 在途派发撞 shutdownNow 的 REE 逃逸——同一站点（ChannelMessageServiceImpl）同一治理 diff。
- **成员（主登记 C4-001，裁定 5）**: C4-001（P2 条件化，孤儿池——终判最严，工单面命名）+ C1-004（P3 条件化，DCL/close 竞态）+ C2-006（P3 条件化，三职责单监视器）+ C4-003（P3 条件化，close 不完整/复活池/REE）+ C4-006（P3 条件化，DCL 缺 volatile 一行）+ C6-003（P3 条件化，close/派发竞态「半个派发」面）；CL-002（线索，destroy-method 缺失）随案并入。
- **修复点**: beans.xml 补 `destroy-method="close"` + `ownedFanOutExecutor` 声明 volatile + close 同锁 + close 先退订 subscribedTopics + runAsync 提交 REE 防御 + closed 态守卫（单 diff 站点集中）。
- **族严重度**: **P2 条件化**（**激活回升条款：投产接线（dispatchInbound/destroy-method 接线）即回升 P1**）。
- **跨单元**: 池生命周期挂靠 bean 治理模式与 WI 3.1 MA-04（spawn 编排池）对齐；orTimeout 站点（L351/L418）随 WI 2.3 CL-022 移交面核对（非缺陷）。

### MA-03 会话映射「半个成功」链（链主工单，四条）
- **根因**: findByChannel miss → execute → saveMapping（无条件 insert）跨回调非原子且 error≡miss——新引擎会话已建而映射落败/竞争落败 → 引擎会话孤儿化，无补偿无清理（非并发场景 A + 并发场景 B）。
- **成员（链主 C6-004，P2 条件化保持链内相对序）**: C6-004（P2 条件化，链主——覆盖面最全）+ C1-005（P3，渠道栈休眠 annotate）+ C2-005（P3 条件化，并发面 + WARN 吞 UK 冲突）+ C3-006（P3，休眠 annotate）。
- **修复点**: saveMapping 改 upsert（UK 命中换绑）+ findByChannel 区分 miss/error + 遗弃登记 fail-loud 指标 + 同 chat 首会话按 chatId 串行化（链内单修复落点）。
- **族严重度**: **P2 条件化**（**激活回升条款：投产接线即回升 P1**）。CL-015 随案驳回（见 §八——影子行面不成立，upsert 修复顺带消除其机制）。
- **跨单元**: 引擎侧孤儿最终驻留由 WI 3.1 MA-03（F4 session put-only 族）承载——回收批次对齐，零站点重复。

### MA-04 fan-out 派发治理：无界队列 × 非协作挂死（工单族）
- **根因**: `newFixedThreadPool` 无界队列 + 30s 超时仅中断协作型 listener（注释自认）——非协作挂死 listener 永久占满小容量池，队列单调增长、派发截止契约整体失效且无背压信号。
- **成员**: C4-002（P2 条件化，主登记）+ C7-004（P2 条件化，吸收——同站点同根同失效链，增量仅日志放大/队列驻留细节）；CL-004/CL-006（线索）随案并入。
- **修复点**: 有界队列 + QueueOverflowPolicy 显式拒绝策略 + listener 连续超时熔断/摘除（评估平台 IThreadPoolExecutor 替代自建池）。
- **族严重度**: **P2 条件化**（**激活回升条款：投产接线即回升 P1**）。
- **显式边界**: **C8-002 为同站点第三失效面，保留独立工单、本族同批派发，不被吸收**（裁定 2）。
- **跨单元**: 判级与 WI 3.1 MA-11 同族对齐；orTimeout 站点随 WI 2.3 CL-022 移交面对齐。

### MA-05 终态回调异常护栏缺失 → future 永不完成（工单族）
- **根因**: adapter/interceptor 三回调体（whenComplete 从属 stage）无护栏，异常吞入无人消费的从属 stage → 非流式 future 永不完成、流式订阅失去终态信号（不可检测挂死；C7-001 的 release 下溢触发器与 F5 不可检测表述并入为验收要点）。
- **成员**: C3-004（P2，live，主登记）+ C7-001（P2，live，吸收——同站点同机制，行号重合，判级一致）。
- **修复点**: 三回调体统一 try/catch(Throwable) + completeExceptionally/deliverError 兜底；catch NopException 放宽（同 diff 含 interceptor 孪生站点）。
- **族严重度**: **P2**（live 面，无休眠条款）。
- **跨单元**: 与 WI 1.7 C6-001 / WI 3.2 MA-01（future 永不完成族）批次对齐。

### MA-06 FeishuConnector.getCapabilities 惰性初始化不安全发布（双登记单工单）
- **根因**: RESERVED SPI 惰性初始化无锁无 volatile——unsafe publication；当前零生产消费方（grep 证实）。
- **成员**: C2-007（P3，主登记——时序登记在先）+ C1-006（P3）。
- **修复点**: capabilities 改 volatile + 饿汉/预构建（SPI 接入时回升）。
- **族严重度**: **P3**（**激活回升条款：SPI 消费方接入即回升**）。

### MA-07 FailoverStreamFlow 取消 × 装配窗口并发计数泄漏（工单族）
- **根因**: 取消落在 cancelled 检查后、acquire/装配前的交错窗口内，新 attempt 的 ConcurrencyRegistry acquire 无任何 release 回滚路径（onSubscribe 取消分支仅 `subscription.cancel(); return;`）——静默永久 +1，饱和误判链成立。
- **成员**: C2-001（P1，live，主登记——release 五路径穷举）+ C1-008（P3，live，吸收——同站点同根，onSubscribe 补 `releaseAttempt(state)` 一行闭合两条）。
- **修复点**: onSubscribe 取消分支补 releaseAttempt（一行）；结构性选项（取消复查 + acquire + 装配纳入监视器）同批评估。
- **族严重度**: **P1**（live 面，无休眠条款）。
- **跨单元**: 与 WI 3.1 MA-01（远端形态取消传播）轴同构零重复——修复批次对齐，且 MA-01 侧不得假设 AttemptCancelToken 原语无竞态（与 MA-01 联动）。
