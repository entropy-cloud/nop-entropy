# 审计报告：MA1.3 — nop-ai-toolkit / nop-ai-tools / nop-ai-skills（模块职责与文件边界）

**审计 ID**：ARM-MA1.3  
**日期**：2026-07-31  
**范围**：nop-ai-toolkit / nop-ai-tools / nop-ai-skills  
**维度**：D02 — 模块职责与文件边界  

---

## 摘要

审计 nop-ai 模块组的 toolkit 邻接模块（toolkit/tools/skills），覆盖 D02 维度（模块职责 + 文件边界）。

**总发现数**：14（P1=2, P2=8, P3=4）

| 严重度 | 数量 | 关键主题 |
|--------|------|---------|
| P1 | 2 | 废弃 API 持续使用；skills 子模块零 IoC 注册 |
| P2 | 8 | 超大文件、配置笔误、硬编码回退、死代码、传递依赖耦合、重复抽象、stub 实现 |
| P3 | 4 | 文件持久化、模块职责混合、跨技能耦合、无条件 bean 注册 |

---

## 发现明细

### [P1-MA1-003] FileToolBizModel 持续使用已废弃的 IFileOperator 接口

- **模块**: `nop-ai/nop-ai-tools`
- **文件**: `nop-ai-tools/src/main/java/io/nop/ai/tools/file/FileToolBizModel.java:46`
- **严重程度**: **P1**
- **现状**: FileToolBizModel 的 7 个文件操作（readFiles/saveFile/glob/grep 等）全部通过已标记 `@Deprecated` 的 `IFileOperator` 接口路由，而 `nop-ai-toolkit` 已有替换接口 `IToolFileSystem` 并提供 `LocalToolFileSystem` 实现。IToolFileSystem 包含路径沙箱等增强功能，但未被使用。
- **风险**: 修复和增强将流向 IToolFileSystem 而 FileToolBizModel 留在废弃路径；IToolFileSystem 的路径沙箱对 tools 层无效。
- **建议**: 重构 FileToolBizModel 委托 IToolFileSystem（可通过 IToolExecuteContext.getFileSystem() 获取）。
- **信心水平**: 高

### [P1-MA1-010] nop-ai-skills 子模块零 IoC Bean 注册

- **模块**: `nop-ai/nop-ai-skills`（全部 3 个子模块）
- **文件**: 全模块无 beans.xml
- **严重程度**: **P1**
- **现状**: 无论 `nop-ai-code-analyzer`（18 个 Java 文件，含 590 行 CodeFileInfo 等）、`nop-ai-deepwiki`、还是 `nop-ai-translate`，均无 `_vfs/nop/ai/beans/` 目录和 beans.xml 文件。这意味着 18 个 Java 类（JavaCodeFileInfoParser、FileLanguageStats、GitIgnoreFile、MavenProject 等）对 Nop IoC 完全不可见，只能通过手动实例化使用。
- **风险**: 依赖模块需手动实例化这些类，绕过 IoC 的生命周期和配置注入；deepwiki/translate 模块无法使用 IoC 托管的 code-analyzer。
- **建议**: 添加 `_vfs/nop/ai/beans/code-analyzer.beans.xml` 注册核心服务为 IoC bean。
- **信心水平**: 高

### [P2-MA1-004] CodeFileInfo.java 承载过多职责（590 行）

- **模块**: `nop-ai/nop-ai-skills` → `nop-ai-code-analyzer`
- **文件**: `nop-ai-skills/nop-ai-code-analyzer/src/main/java/io/nop/ai/code_analyzer/code/CodeFileInfo.java`
- **严重程度**: **P2**
- **现状**: 单个文件包含 6 个顶级或嵌套类型：CodeFileInfo（数据 bean）、AccessModifier（枚举）、CodeSymbol（基类）、CodeClassInfo、CodeFunctionInfo、CodeCallInfo、CodeVariableInfo。此外还包含 `intern()` 工具方法和 `collectUsedFns()` 递归遍历逻辑。
- **风险**: 数据模型变更与 interning 逻辑紧耦合，测试困难。
- **建议**: 提取为独立文件：CodeSymbol.java、CodeClassInfo.java、CodeFunctionInfo.java、CodeCallInfo.java、CodeVariableInfo.java。将 interning 逻辑移到工具类。
- **信心水平**: 高

### [P2-MA1-005] FileLanguageStats.java 承载过多职责（511 行）

- **模块**: `nop-ai/nop-ai-skills` → `nop-ai-code-analyzer`
- **文件**: `nop-ai-skills/nop-ai-code-analyzer/src/main/java/io/nop/ai/code_analyzer/stats/FileLanguageStats.java`
- **严重程度**: **P2**
- **现状**: 单个文件包含语言映射、文件系统遍历、注释检测、统计聚合等 4 个不同的关注点。
- **风险**: 新增语言支持需修改此类；注释检测逻辑与文件遍历紧耦合。
- **建议**: 拆分为 LanguageMapper、FileTreeWalker、CodeLineAnalyzer、LanguageStatsAggregator。
- **信心水平**: 高

### [P2-MA1-006] nop-ai-tools beans.xml 包含 Schema 命名空间拼写错误

- **模块**: `nop-ai/nop-ai-tools`
- **文件**: `nop-ai-tools/src/main/resources/_vfs/nop/ai/beans/ai-tools-defaults.beans.xml:1`
- **严重程度**: **P2**
- **现状**: `xmlns:x="/nop/schema/xdsl.xef"` 将 `.xdef` 误写为 `.xef`。
- **风险**: 若 Nop schema 解析器回退处理，schema 验证将被绕过；严格模式下可能加载失败。
- **建议**: 更正为 `xmlns:x="/nop/schema/xdsl.xdef"`。
- **信心水平**: 高

### [P2-MA1-007] SkillExecutor 硬编码回退技能

- **模块**: `nop-ai/nop-ai-toolkit`
- **文件**: `nop-ai-toolkit/src/main/java/io/nop/ai/toolkit/tools/SkillExecutor.java:127-133`
- **严重程度**: **P2**
- **现状**: VFS 技能发现返回空列表时（或异常被静默吞掉），返回 5 个硬编码技能名（log-analysis、translator 等），但无对应实现且 `catch` 块为空。
- **风险**: 用户看到幻影技能但无法加载；静默吞异常隐藏配置问题。
- **建议**: 删除硬编码回退；VFS 无技能时返回空列表。
- **信心水平**: 高

### [P2-MA1-008] SearchEngineExecutor 在 beans.xml 中被注释掉但代码存在

- **模块**: `nop-ai/nop-ai-toolkit`
- **文件**: `nop-ai-toolkit/src/main/resources/_vfs/nop/ai/beans/ai-tools-defaults.beans.xml:26`
- **严重程度**: **P2**
- **现状**: SearchEngineExecutor（138 行）及其 `search-engine.tool.xml` 均存在，但 bean 注册被注释掉。pom.xml 中声明了 `nop-search-api` 依赖。
- **风险**: 死代码；若取消注释，ISearchEngine bean 可能不可用导致运行时失败。
- **建议**: 删除注释代码或使用条件激活；或让 SearchEngineExecutor 在缺少 ISearchEngine 时优雅降级。
- **信心水平**: 高

### [P2-MA1-009] GraphQLToolProvider 产生硬传递依赖到 nop-graphql-core

- **模块**: `nop-ai/nop-ai-tools`
- **文件**: `nop-ai-tools/src/main/java/io/nop/ai/tools/graphql/GraphQLToolProvider.java`
- **严重程度**: **P2**
- **现状**: pom.xml 仅声明 nop-biz/nop-ai-core/nop-ai-coder，但 GraphQLToolProvider 直接使用 nop-graphql-core 的 import（通过 nop-biz 传递获得）。
- **风险**: nop-biz 依赖结构调整时破坏编译；非 GraphQL 环境中模块不可用。
- **建议**: 将 graphql 包提取到独立模块，或将 nop-graphql-core 设为 `<optional>true</optional>`。
- **信心水平**: 高

### [P2-MA1-011] AskOracleExecutor 是存根实现

- **模块**: `nop-ai/nop-ai-toolkit`
- **文件**: `nop-ai-toolkit/src/main/java/io/nop/ai/toolkit/tools/AskOracleExecutor.java:42-49`
- **严重程度**: **P2**
- **现状**: 读取 `ORACLE_ENDPOINT` 环境变量但从不使用；始终返回第一个选项的 key。`timeoutMs` 被解析但不使用。
- **风险**: 用户期望 AI 驱动决策但获得确定性结果；参数 `ORACLE_ENDPOINT` 和 `timeoutMs` 具有误导性。
- **建议**: 实现实际 oracle 调用，或标记工具为实验性/不稳定。
- **信心水平**: 高

### [P2-MA1-012] nop-ai-toolkit 中存在重复的文件系统抽象（IToolFileSystem vs IFileOperator）

- **模块**: `nop-ai/nop-ai-toolkit` + `nop-ai/nop-ai-core`
- **文件**: `IToolFileSystem.java`（toolkit） vs `IFileOperator.java`（core，@Deprecated）
- **严重程度**: **P2**
- **现状**: 两套并行的文件系统抽象接口，IToolFileSystem 是预期替代但 IFileOperator 仍被 FileToolBizModel 使用。
- **风险**: 行为不一致（一个有路径沙箱，一个没有）；开发者需选择使用哪个接口。
- **建议**: 标记 IFileOperator 为 `@Deprecated(forRemoval=true)` 并迁移 FileToolBizModel。
- **信心水平**: 高

### [P3-MA1-013] SequentialThinkingBizModel 使用文件持久化而非 Nop ORM/DAO

- **模块**: `nop-ai/nop-ai-tools`
- **文件**: `nop-ai-tools/src/main/java/io/nop/ai/tools/sequential_thinking/service/ThoughtStorage.java`
- **严重程度**: **P3**
- **现状**: ThoughtStorage 使用 JSON 文件持久化（默认路径 ~/.mcp_sequential_thinking/），每次操作进行全量读/写。
- **风险**: 无事务保证；无集群支持；文件读写非原子操作。
- **建议**: 若该 BizModel 仅是会话级，文件持久化可接受；若需生产级可用，迁移至 Nop ORM 实体。
- **信心水平**: 中

### [P3-MA1-014] nop-ai-code-analyzer 模块包含混合职责（Maven + 代码分析 + Git）

- **模块**: `nop-ai/nop-ai-skills` → `nop-ai-code-analyzer`
- **文件**: 模块目录结构
- **严重程度**: **P3**
- **现状**: 模块包含 5 个不同职责的包（code/、git/、maven/、project/、stats/），其中 Maven 包有 9 个文件，且依赖 nop-shell。
- **风险**: 依赖链使模块消费者必须接受 nop-shell 传递依赖。
- **建议**: 拆分为 nop-ai-maven-analyzer 和 nop-ai-code-analyzer-core。
- **信心水平**: 中

### [P3-MA1-015] nop-ai-deepwiki 依赖 nop-ai-tools 产生跨技能耦合

- **模块**: `nop-ai/nop-ai-skills` → `nop-ai-deepwiki`
- **文件**: `nop-ai-skills/nop-ai-deepwiki/pom.xml:22-28`
- **严重程度**: **P3**
- **现状**: deepwiki（零 Java 文件）声明对 nop-ai-tools 和 nop-ai-code-analyzer 的编译依赖。
- **风险**: 若 nop-ai-tools 或 code-analyzer API 变更，deepwiki 可能破裂。
- **建议**: 若 deepwiki 仅运行时调用工具，将依赖改为 `<scope>runtime</scope>`。
- **信心水平**: 中

### [P3-MA1-016] GraphQLToolSetFactoryBean 无条件注册

- **模块**: `nop-ai/nop-ai-tools`
- **文件**: `nop-ai-tools/src/main/resources/_vfs/nop/ai/beans/ai-tools-defaults.beans.xml:11`
- **严重程度**: **P3**
- **现状**: `nopGraphQLToolSet` bean 始终实例化且 @Inject IGraphQLEngine，在非 Web 环境中导致启动失败。
- **风险**: 阻止 nop-ai-tools 在非 GraphQL 上下文中使用。
- **建议**: 添加条件激活 `ioc:condition="!missing-bean:IGraphQLEngine"`。
- **信心水平**: 高
