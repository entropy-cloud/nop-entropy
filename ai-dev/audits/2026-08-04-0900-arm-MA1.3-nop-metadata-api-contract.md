## 四、发现清单（本审计新增）

### 发现 1 — NopMetaSearch.xmeta 引用不存在的 `io.nop.metadata.core.dto.SearchHitDTO`（P1，contract drift）

- **文件**：`nop-metadata-service/src/main/resources/_vfs/nop/metadata/NopMetaSearch/NopMetaSearch.xmeta:7`
- **证据**：
  ```xml
  <prop name="items" ...>
      <schema type="List&lt;io.nop.metadata.core.dto.SearchHitDTO&gt;"/>
  </prop>
  ```
- **严重程度**：P1
- **现状**：DTO 迁移（c3162d4da，plan-2026-07-23-0838）将 `SearchHitDTO` 从 core 迁至 `io.nop.metadata.api.dto.SearchHitDTO`，但该手写 xmeta 未同步更新；`nop-metadata-core` 现仅含 2 个常量文件，`io.nop.metadata.core.dto` 包**不存在**（全仓 `grep "io.nop.metadata.core.dto"` 仅命中本 xmeta 与其 target 产物副本）。BizModel 实际返回 `io.nop.metadata.api.dto.SearchHitDTO`（`NopMetaSearchBizModel.java:10,86-88`）。
- **风险**：GraphQL schema 对 `NopMetaSearch.items` 的类型解析指向缺失类——查询选择该字段时 schema 类型构建失败或字段类型退化（现有测试均直连 service 不经过 GraphQL schema，故绿色基线未暴露）；前端 selection/类型生成对 `items` 失效。
- **建议**：xmeta schema type 改为 `io.nop.metadata.api.dto.SearchHitDTO`（一行修复，MR1 批量修复时执行并补 GraphQL 字段选择回归测试）。
- **归属**：**MR1**（MA1 范围 P1 修复清单；本项为 plan 范围内唯一新增 live contract drift，不可降级 deferred）
- **引入时点**：c3162d4da（2026-07-23 DTO 迁移未同步 xmeta）
