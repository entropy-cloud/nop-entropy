### P1-MA5-001: DefaultAiChatService.getSession() unconditionally returned null

- **Severity**: P1
- **Sources**: MA5.1 P1-02, MA5.2 F-007, MA5.3 P1-MA5.3-02 (confirmatory)
- **File**: `nop-ai/nop-ai-core/src/main/java/io/nop/ai/core/service/DefaultAiChatService.java:619-621`
- **Original claim**: `getSession()` always returns `null`
- **arm-index status**: `fixed` (审计中修改为 throw UnsupportedOperationException)

**Current code** (line 619-621):
```java
@Override
public IAiChatSession getSession(String sessionId) {
    throw new UnsupportedOperationException("Deprecated: use IChatService instead");
}
```

**Verdict**: FIXED

**Evidence**: The method no longer returns null. It was modified to throw `UnsupportedOperationException` with a clear message pointing to `IChatService`. This was already noted by MA5.3 during its audit window (the MA5.3 report at P1-MA5.3-02 says "throws UnsupportedOperationException" vs MA5.1/MA5.2 which reported "returns null"). The arm-index attribution is correct — the fix happened during the audit cycle itself, likely between MA5.1 and MA5.3 runs. This satisfies the MA5.1 recommendation ("改为抛 UnsupportedOperationException").

### P1-MA5.3-001: ChatServiceImpl(IChatService) has no IoC bean definition

- **Severity**: P1
- **Source**: MA5.3 P1-MA5.3-01
- **File**: `nop-ai/nop-ai-core/src/main/java/io/nop/ai/core/service/ChatServiceImpl.java:60`
- **Original claim**: `ChatServiceImpl` implements the new `IChatService` API but is not registered as a bean in any `beans.xml`
- **arm-index status**: `open` (MR2)

**Searches performed** (all 12 main beans.xml files in nop-ai):
- `grep "ChatServiceImpl" *.xml` → 0 results
- `grep "IChatService" *.xml` → 0 results

**Current beans.xml** (`ai-defaults.beans.xml`, the relevant file):
```xml
<bean id="nopAiChatService" class="io.nop.ai.core.service.DefaultAiChatService" ioc:default="true"/>
```
No bean for `ChatServiceImpl` or `IChatService` exists anywhere.

**Verdict**: STILL_OPEN

**Evidence**: `ChatServiceImpl` at `nop-ai/nop-ai-core/src/main/java/io/nop/ai/core/service/ChatServiceImpl.java:60` implements `IChatService` and has `@Inject` for `IChatLogger` and `IHttpClient`, yet no `beans.xml` in the entire nop-ai module tree registers it. The only chat service bean remains `nopAiChatService` → `DefaultAiChatService`. Any code that does `BeanContainer.getBeanByType(IChatService.class)` will get `NoBeanOfTypeException`. MR2 has not been processed.

### P1-MA5.3-002: DefaultAiChatService @Deprecated but is the only registered chat service bean

- **Severity**: P1
- **Source**: MA5.3 P1-MA5.3-02
- **File**: `nop-ai/nop-ai-core/src/main/java/io/nop/ai/core/service/DefaultAiChatService.java:74`
- **Original claim**: `DefaultAiChatService` is annotated `@Deprecated` (documentation says "被ChatServiceImpl替代") but it is the only registered chat service bean, and `ChatServiceImpl` (its replacement) has no bean definition
- **arm-index status**: `open` (MR2)

**Current code** (line 74):
```java
@Deprecated
public class DefaultAiChatService extends AbstractAiChatSession implements IAiChatService {
```

**Current beans.xml** (`ai-defaults.beans.xml:6`):
```xml
<bean id="nopAiChatService" class="io.nop.ai.core.service.DefaultAiChatService" ioc:default="true"/>
```

**Verdict**: STILL_OPEN

**Evidence**: The situation documented by MA5.3 is completely unchanged:
1. `DefaultAiChatService` is still `@Deprecated` (line 74)
2. It remains the **only** chat service bean (`nopAiChatService` in `ai-defaults.beans.xml:6`)
3. `ChatServiceImpl` still has no bean definition (P1-MA5.3-001)
4. The MA5.3 recommended resolution (register `ChatServiceImpl` as a bean with `ioc:type="io.nop.ai.api.chat.IChatService"`) has not been applied
5. The `getSession()` method was already fixed (see P1-MA5-001 above), but the underlying wiring inconsistency remains: callers who inject `IAiChatService` get the deprecated implementation, and callers who try `IChatService` fail entirely

This is the most impactful open finding as it blocks migration from the deprecated `IAiChatService` API to the new `IChatService` API.
