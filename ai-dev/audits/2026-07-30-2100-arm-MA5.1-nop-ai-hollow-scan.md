## 摘要

| 严重程度 | 数量 | 关键标签 |
|---------|------|---------|
| **P0** | 0 | — |
| **P1** | 2 | 接口无实现、null返回 |
| **P2** | 5 | 空方法体、弃用死代码 |
| **P3** | 2 | 空 close/flush（可接受） |

总体评价：**nop-ai-agent 模块中的 40+ 个 NoOp 类设计规范**，绝大部分遵循 Minimum Rules #24（No Silent No-Op），有明确的文档注释和 fail-fast 模式（抛出 UnsupportedOperationException 或返回显式空值）。**真正空壳集中在 nop-ai-core 的旧版 API 层**，表现为（1）Method 体为空但不抛异常、（2）接口定义但无实现。

## 发现详情

### P1-01: IVectorStore / IEmbeddingModel / ITokenCountEstimator 接口无实现

| 属性 | 值 |
|------|-----|
| **文件路径** | `nop-ai-core/src/main/java/io/nop/ai/core/api/vectorstore/IVectorStore.java:29` |
| | `nop-ai-core/src/main/java/io/nop/ai/core/api/embedding/IEmbeddingModel.java:10` |
| | `nop-ai-core/src/main/java/io/nop/ai/core/api/tokenizer/ITokenCountEstimator.java:5` |
| **严重程度** | **P1** |
| **模式类型** | 接口有线无实现（Pattern 4） |

**现状描述**：
三个 API 接口定义在 `nop-ai-core` 的公共 API 包中，但**在扫描范围内无任何生产代码实现**：
- `IVectorStore<T>` — 抽象类，声明 store/delete/update/search 四个方法
- `IEmbeddingModel` — 接口，声明 embedAsync/embedAllAsync 两个方法
- `ITokenCountEstimator` — 接口，声明 estimate/estimateForMessage 两个方法

`IEmbeddingModel` 的唯一消费者 `EmbeddingModelBasedClassifier` 存在但需要注入具体实现才能工作。

**风险分析**：
这些接口属于 "defined but unimplemented" 状态。如果应用代码尝试注入或使用这些接口，会在运行时因 NoSuchBeanDefinitionException 或 NPE 而失败。`EmbeddingModelBasedClassifier` 的构造函数直接调用 `embeddingModel.embed()`，若注入 NoOp 则返回 null 数据。

**修复建议**：
1. 短期：在 `nop-ai-agent` 或保留的 `nop-ai-rag` 中提供 InMemory 实现（如 `InMemoryEmbeddingAdapter` 已在 nop-ai-agent 的 memory 包中存在，但不实现 `IEmbeddingModel` 接口）
2. 长期：明确这些接口的定位——如果属于 SPI（供集成方实现），应添加 `@SPI` 注解和文档说明；如果属于废弃，应标记 `@Deprecated`

### P1-02: DefaultAiChatService.getSession() 无条件返回 null

| 属性 | 值 |
|------|-----|
| **文件路径** | `nop-ai-core/src/main/java/io/nop/ai/core/service/DefaultAiChatService.java:619-621` |
| **严重程度** | **P1** |
| **模式类型** | 空方法体 / return null（Pattern 1） |

**现状描述**：
```java
@Override
public IAiChatSession getSession(String sessionId) {
    return null;   // ← 永远返回 null
}
```
该方法从 `IAiChatService` 接口继承而来，接口约定是 "获取指定 ID 的会话"，但实现始终返回 null。

**风险分析**：
任何调用 `getSession()` 的消费者在未做 null 检查时直接使用方法返回值，会触发 NPE。该服务虽已标记 `@Deprecated`，但在迁移完成前仍可能被调用。`IAiChatService.newSession()` 方法也可能存在类似的实现缺失风险。

**修复建议**：
1. 最低：添加 `@throws IllegalStateException` 或 `throw new UnsupportedOperationException("getSession is deprecated, use new API instead")` 以快速失败
2. 若该接口属于废弃/过渡状态，应在 `IAiChatService` 的 `getSession()` 声明处加默认方法抛 `UnsupportedOperationException`

### P2-05: BlockingQueueShellOutput.flush() 空方法体

| 属性 | 值 |
|------|-----|
| **文件路径** | `nop-ai-shell/src/main/java/io/nop/ai/shell/io/BlockingQueueShellOutput.java:37-38` |
| **严重程度** | **P2** |
| **模式类型** | 空方法体（Pattern 1） |

**现状描述**：
```java
@Override
public void flush() {
    // 空方法体
}
```

**风险分析**：
`flush()` 是 `IShellOutput` 接口的约定——当使用缓存输出时需要刷新缓冲区。`BlockingQueueShellOutput` 内部使用 `BlockingQueue` 写入，写入操作是即时入队而不需要手动 flush，但如果有消费者依赖 `flush()` 的语义来确保数据可见性，当前实现可能在某些并发场景下导致数据延迟到达。

**修复建议**：
1. 添加注释说明为什么 flush 是空实现（"each write is immediately enqueued, no buffering occurs"）
2. 或确保 flush 至少触发一次 `Thread.yield()` 或 `Thread.onSpinWait()` 以增加可见性保证

| 属性 | 值 |
|------|-----|
| **文件路径** | `nop-ai-core/src/main/java/io/nop/ai/core/api/tool/DefaultAiChatFunctionTool.java:114-121` |

**现状描述**：

**风险分析**：

**修复建议**：
1. 在 `callTool()` 中添加 null 检查：`Guard.notNull(invoker, "invoker")`
2. 或将 invoker 改为构造函数参数以消除 null 状态

## NoOp 类综合评估

扫描发现 nop-ai-agent 中有 **40+ NoOp/PassThrough 类**。逐一评估后，**无 P0/P1 风险**。原因如下：

| 评估维度 | 结论 |
|---------|------|
| 是否为空方法体 | ❌ 绝大部分有实现（返回空集合/显式值/抛异常） |
| 是否抛 UnsupportedOperationException | ✅ 29/40 的写操作方法会抛异常（如 `NoOpTeamManager.createTeam()`） |
| 是否有完整类级 Javadoc | ✅ 40/40 有详细文档（含设计文档引用和 plan 编号） |
| 是否有消费者引用 | ✅ `DefaultAgentEngine` 将 NoOp 作为 shipped default |
| 是否为设计上的 pass-through | ✅ 明确标记为 "explicit pass-through default, not silent skip" |

**典型示例**（体现良好设计的 NoOp 类）：

| 类 | fail-fast 方式 |
|----|---------------|
| `NoOpStorageAdapter` | 所有方法抛 `NopAiAgentException("not configured")` |
| `NoOpTeamManager` | 写操作抛 `UnsupportedOperationException`，读返回 empty |
| `NoOpActorRuntime` | `isEnabled()` 返回 false；`createActor()` 抛异常 |
| `NoOpHookRegistry` | register/registerMiddleware 抛异常 |
| `NoOpEmbeddingAdapter` | embed/embedBatch 抛异常 |
| `NoOpMailbox` | `offer()` 返回 false（显式拒绝），`poll()` 返回 null |
| `NoOpDenialLedger` | `recordDenial()` 返回 `NOT_COUNTED` 常量 |
| `PassThroughModelRouter` | 返回 pass-through RoutingResult |
| `PassThroughPermissionMatrix` | 返回 `MatrixDecision.allow()` |
