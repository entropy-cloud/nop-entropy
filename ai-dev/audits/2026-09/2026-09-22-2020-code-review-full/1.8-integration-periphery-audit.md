## 维度结论

### 维度 01 集成层边界（独立复核：14 保留 / 1 降级 / 0 驳回）

- **正结论**：starter 注册装配面结构两栈各异但各自成立（spring 唯一 AutoConfiguration.imports + @ComponentScan 级联；quarkus 无 imports 机制靠 app main() 手工调 QuarkusIntegration.start()，18 个 @QuarkusMain 中 16 个调用）；红旗法反向边 0（spring/quarkus 工件 0 反向、network/integration 反向边全部向下合规）；integration/network 正交（唯一重叠点 feishu 自带 JDK HttpClient 传输为文档化选型）；7 组归属名实一致。
- **P1×1（01-02，复核维持并重构理由）**：nop-file-app/nop-credential-app 的 `QuarkusIntegration.start()` 被注释（git 考古：c7ea7b6836 2025-12-05 大提交无说明顺手注释 start()+web-orm-starter+auth-core 三处；NopCredentialApplication 是 1d12af9dcb 对已坏 NopFileApplication 的直接复制——坏模板传播已兑现）。app 不崩溃（IGraphQLEngine 由 NopIoC 满足）但 CDI 桥父容器缺省 + quarkus.profile→nop.profile 传播丢失（prod 配置漂移）+ MeterRegistry 静默回落 + 依赖树无任何 quarkus web/REST 扩展——「可启动、无 HTTP 端点」半拆。P1 锚定：高概率回归且已兑现（坏模板传播）+ 误导公开面（pom「独立服务包」+ yaml 0.0.0.0 + nop-credential.md:231 standalone 部署语义讨论）；降 P2 触发条件已附（正式裁决休眠并文档声明）。
- P2×1（01-03）：starter 聚合面双栈不对等——quarkus-web-starter 注释停用 nop-auth-core/nop-gateway（死坐标：auth-core 已演化为 nop-biz-auth-core，照抄恢复会构建失败；gateway 注释为有提交信息的有意回退，决策应升格文档防二次往返）。
- P3×14：隐式包约定注册（io.nop.spring.proxy 会被误扫入）、grpc 停用残留、mcp 空壳、native-image 目录 typo、feishu/zxing 实现直连 2 处、cli-jdk11 名实不符（target=17）、core-starter 预绑本地文件实现、integration 5/9 实现无生产消费者（email-tencent 有测试无消费者——复核修正）等。
