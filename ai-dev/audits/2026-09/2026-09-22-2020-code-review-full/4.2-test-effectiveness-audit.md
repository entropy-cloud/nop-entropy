## 二、zero-test 清单核定（A 面）

### 2.1 口径（可复现，复核重放零差异）

**zero-test 定义（本清单写死口径）**：pom 模块目录下存在 `src/main`（任意内容），且不存在 `src/test/java` 目录 = zero-test。仅存在 `src/test`（只含资源、无 java）亦计入并标注 `[仅test资源]`。

**可复现命令**（仓库根目录执行）：

```bash
# 1. 枚举 zero-test 模块（排除 target 生成目录）
find . -name pom.xml -not -path "*/target/*" | sort | while read -r p; do
  d=$(dirname "$p")
  [ -d "$d/src/main" ] || continue
  [ -d "$d/src/test/java" ] && continue
  echo "$d"
done | wc -l        # => 120

# 2. 分母（有 src/main 的模块总数）
find . -name pom.xml -not -path "*/target/*" | while read -r p; do
  d=$(dirname "$p"); [ -d "$d/src/main" ] && echo "$d"
done | wc -l        # => 374

# 3. 行为密度信号（每模块 java 文件数 / 非 _gen 非 _ 前缀手写 LOC / @BizModel 文件数）
find <module>/src/main -name "*.java" -not -path "*/_gen/*" -not -name "_*" | wc -l
find <module>/src/main -name "*.java" -not -path "*/_gen/*" -not -name "_*" -exec cat {} + | wc -l
grep -rl "__XGEN_FORCE_OVERRIDE__" <module>/src/main --include="*.java" | wc -l   # 代码生成标记

# 4. 跨模块覆盖误报排除（关键类是否在其他模块测试中被引用）
grep -rl "<ClassName>" --include="*.java" . | grep -v target | grep "/src/test/"
```

**判级依据**：共享前缀 P0–P3；维度 21 补充（P1=测试无法捕获真实 bug / 此处延伸为"行为逻辑零测试保护"；P2=保护力弱有边际价值；P3=低风险真实缺口）。

**裁定三分类**：
- **合理**：api（XGEN 生成 ICrudApi+DTO）/ `_codegen` / app 启动薄壳 / meta 纯资源 / demo / JMH 基准 / 纯资源模块——无实质手写行为逻辑。
- **缺口需补**：含实质手写行为逻辑，可经聚焦补测闭合。
- **移交 R1.0**：行为面大（≥1000 LOC 适配层），需系统性测试投入。

**误报排除口径（重要）**：模块粒度 zero-test ≠ 零覆盖。对每个高密度候选均做了跨模块测试引用检查（上第 4 条命令），跨模块专项覆盖在台账与条目中显式标注，避免把"测试放在别的模块"误报为"完全无保护"。
