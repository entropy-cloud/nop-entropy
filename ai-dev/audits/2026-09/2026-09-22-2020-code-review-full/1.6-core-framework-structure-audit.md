## 维度结论

### 维度 01 组内边界与职责纯度（独立复核：8/8 保留，1 条判级上调采纳）

- 双口径边表：pom 声明 22 条（组内 9 + kernel 12 + 出组 1）vs import 实际 20 条（组内 8 + kernel 11 + 出组 1）；声明无支撑仅 2 条（boot→config/xlang——实为 ServiceLoader 装配边，P3-1.6-002）；import 无声明支撑 0 条。pom 层与 import 层均无环。
- 职责纯度全部合格：boot 5 类纯启动壳（全仓 25 个 main 入口 24 个绕过 boot 直调 CoreInitialization，boot 为可选壳）；security 12 类依赖链单向（rsa→utils→key）全 NopException.adapt；config↔ioc 零 import 缝合。
- P2×2：nop-security junit-jupiter 缺 test scope（compile 泄漏给全部消费方，无条件+全静默+修复一行）；ioc api 包公开 SPI 签名暴露 impl 类型（与 1.2 IXLangCompileScope 同案同判上调 P2：模式/危害半径相同，复核建议、主 agent 采信）。
- P3×6：boot 装配边无注释保护、security BC optional+硬引用无软门控（复核修正触发面收窄为 RsaHelper.genKeyPair→BcCertHelper 类初始化一条路径）、VfsPluginDefinition 跨模块下转型（根因 BeanContainerBuilder 公开 API 缺口）、module-groups.md「plugin-api 零依赖」口径失真、impl↔loader 包级环、nop-security 全仓零消费方+缺席 nop-bom 双缺（治理遗漏定性）。

### 维度 02 文件边界与三项点名标定（独立复核：9/9 保留）

- 行数榜：无 >1500 手写文件（最大手写 BeanDefinitionBuilder 1143 行）；watch×6 移交 4.3（BeanDefinitionBuilder 1143/BeanDefinition 803/PluginManagerImpl 796/BeanContainerImpl 685/VfsPluginDefinition 678/ConfigStarter 551）。

- **点名复核 2——nop-config 弱加密 fail-closed**：默认路径 = `warnEmptyKeyOnce()` 一次性 WARN + 可公开推导弱密钥继续运行（CORE-03 F-C3-1 batch-1 修复现状：「WARN + docs」，非本项新缺陷）；加密值解析失败 fail-closed（v1 截断/GCM tag/base64 均抛异常传播致启动失败）。**新发现 02-06 P2：`nop.crypt.default-enc-key` 仅 -D 系统属性渠道对默认 cipher 生效**（cipher 字段初始化早于 provider 注册，env/yaml/bootstrap 全无效），而 WARN 文案与 owner doc 均将其与 `nop.config.encrypt-key` 并列列为生产前置条件——复核九环节逐行实测成立，维持 P2 不升 P1（四点理由留痕），附 P1 升级触发条件（若 3.11/4.1 认定 default-enc-key 为生产主流配置路径）。
- **点名复核 3——CORE-01 docs 标定：闭环可标 ✅**（残留 nop-security 无 owner doc 属实，LOW 移交 5.1/5.2）。
- P3×3：ConfigConstants L85 死键（props-config-source.refresh-interval 复制粘贴笔误，key/props 双源不可独立调频、`<=0` 停 key 源轮询静默停 props 源凭据轮换）；IStreamCipher 流路径恒走 legacy MD5+静态 IV 不受 versionedFormat 控制（全仓零生产调用方，休眠弱面——**该条目在维度文件中保存丢失，独立复核已验证其声明成立后补档**）；skip-cache-verify=true 激活期零日志（NET-01 审计「logs by comparison」对照证伪）。
