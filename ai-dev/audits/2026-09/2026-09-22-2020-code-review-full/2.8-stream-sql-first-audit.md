**P0-2.8-001（SumAgg 混型累加静默错值）**：`StreamSqlAggregation.SumAgg` 对 Integer+Double 混型流累计时整数部分静默丢弃（sum(1,2,3.5)→3.5）、浮点和为 0 时类型塌缩返回 Long（1.5−1.5+2→2 [Long]）——复核探针实测三例错值一例塌缩；记录载体是无型 Map（schema 类型纯建议性），混型是预期输入非滥用，一条小数记录混入后后续所有整数部分持续丢弃（流上持续放大）；**连带 dim10-10（BigDecimal 全流逐条截断、BigInteger 2^70 回绕 0——无需混型即触发）必须一并设计**（截断在 add 期，getResult 侧修复无效）。

三个 P1：**双流 join null 等值键误配**（bufferKeyOf String.valueOf(null)="null"→左右 null 键互配发射幻影行，违反 SQL NULL 语义且 null 键经 partition 确定到达）；**completeUnmatched 缺水位前缘过滤**（ts>watermark 的未匹配记录被提前补 null 且留缓冲再配对=同记录双发，探针确定性复现，javadoc exactly-once 契约被违反）；**PerKeyOrderedBuffer.putAll 不搬 insertionSeq**（restore 后 seq 对位碰撞→restored 记录从视图与补全双通道静默消失，探针双面实证）。

结构性正结论经复核背书（抽验 8 项全过）：**2.2 P0/P1 不波及 stream SQL 表达式路径**（14 kind 双侧 default-reject、_some/_all 非流路径可达——显式核对交付）；生成管线闭合（stream.xdef 三字段↔生成类↔expandSqlModel 逐行）；WI17 fail-fast 矩阵 live 全对账；WI12/WI13 已修项（MAJ-1 跨 key 清理/句柄孤儿双修）live 复核成立零推翻；join watermark 传播链正确。
