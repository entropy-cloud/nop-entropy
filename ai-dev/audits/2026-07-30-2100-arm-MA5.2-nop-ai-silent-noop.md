### ① Catch-and-Swallow（空 catch 块）

#### F-001 | P2 | BashExecutor.java:66, 76

- **文件**：`nop-ai-toolkit/src/main/java/io/nop/ai/toolkit/tools/BashExecutor.java`
- **行号**：66, 76
- **现状描述**：
  ```java
  // stdoutThread
  } catch (Exception ignored) { }
  // stderrThread
  } catch (Exception ignored) { }
  ```
  两个子线程读取外部进程 stdout/stderr 流，发生任何 `IOException` 时完全静默吞掉异常。`stdout`/`stderr` 变量内容保持吞异常前的部分内容。
- **风险分析**：外部命令的输出流因管道破裂、编码错误、内存不足而失败时，调用方收到**不完整且无标记**的输出，被误认为完整命令结果。子线程静默失败后 join 正常完成，主线程无从得知输出丢失。在 Agent 执行上下文中，这可能导致 LLM 基于残缺输出做出错误决策。
- **修复建议**：在 catch 中记录异常并标记输出为不完整（如在 `AiToolCallResult` 中增加 `truncated` 标记），或至少 `LOG.warn("BashExecutor stream read failed", e)`。

### ⑤ 日志吞异常（catch + 仅 LOG.xxx 不传播）

#### F-016 | P1 | ReActAgentExecutor.java:2823-2841（多实例）

- **文件**：`nop-ai-agent/src/main/java/io/nop/ai/agent/engine/ReActAgentExecutor.java`
- **行号**：2823-2841（及 2663, 2839 等）
- **现状描述**：
  ```java

      if (point == AgentLifecyclePoint.ON_ERROR) {
  ```

  Agent 生命周期钩子（`ON_ERROR`, `PRE_*`, `BEFORE_*` 等）的执行异常被 LOG.warn 后吞掉，引擎使用默认逻辑继续。
- **风险分析**：生命周期钩子是 Agent 扩展的核心扩展点。钩子失败被静默吞掉意味着**钩子实现返回的错误被完全忽略**。这在"防御性编程"意义上是有意的（钩子不中断 Agent 主流程），但在钩子层是**静默跳过错误处理**。例如 `on_error` 钩子本身失败时，原始错误和钩子错误都丢失，运维无从得知错误处理本身也出错了。
- **修复建议**：对于 `ON_ERROR` 钩子的失败，建议打印到独立日志文件或通过事件系统发布告警。至少考虑在 WARN 级别日志中同时包含原始异常上下文。

- **风险分析**：这是向"最少意外"方向的优雅降级：参数无法解析时使用空参数。调用方不会收到 NPE，但工具执行时的行为可能不符合预期（因为参数丢失了）。
- **修复建议**：增加 `LOG.debug("Failed to parse tool call arguments JSON, defaulting to empty map", e)`。

## 附录：扫描命令

```bash
# Pattern 1: 空 catch 块
rg --multiline -n 'catch\s*\([^)]*\)\s*\{\s*\}' --type java --glob '!**/test/**'

# Pattern 2: catch + continue
rg --multiline -n 'catch\s*\([^)]*\)\s*\{[^}]*continue\s*;[^}]*\}' --type java

# Pattern 3: return null (方法体仅有 return null)
rg --multiline -n 'public\s+\w+\s+\w+\s*\([^)]*\)\s*\{\s*return\s+null\s*;\s*\}' --type java

# Pattern 4: 空 @Override 方法
rg --multiline -n '@Override\s*\n\s*public\s+void\s+\w+\s*\([^)]*\)\s*\{\s*\}' --type java

# Pattern 5: catch + LOG.warn/debug 无 rethrow
rg --multiline -n 'catch\s*\([^)]*\)\s*\{[^}]*LOG\.(debug|trace|warn)\([^}]*\}' --type java
```
