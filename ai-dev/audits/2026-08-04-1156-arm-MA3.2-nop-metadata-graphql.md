### [MA3.2-01] 实体路径数据查询绕过 Nop data-auth 过滤器合并（P2）

- **文件**: `NopMetaTableQueryAction.java:88-107`；`query/MetaJoinExecutor.java:274-310`；`query/EntityAggregationProcessor.java:107-160`；`query/EntityEntityJoinAggregationProcessor.java:144-146`；入口 `entity/NopMetaTableBizModel.java:196-219`
- **证据片段**:
  ```java
  // NopMetaTableQueryAction.queryEntityData（entity 类型路径）
  IOrmEntityDao<IOrmEntity> targetDao = castToOrmEntityDao(daoProvider.dao(entityName));
  QueryBean query = new QueryBean();
  if (filter != null) query.setFilter(filter);
  ...
  List<IOrmEntity> entities = targetDao.findAllByQuery(query);
  ```
  ```java
  // MetaJoinExecutor.executeSameDbJoin（entity-entity 路径）
  SQL sqlObj = SQL.begin().allowUnderscoreName(true).sql(sqlText, params.toArray()).end();
  return ctx.orm().executeQuery(sqlObj, null, this::collectRows);
  ```
- **严重程度**: P2
- **现状**: `queryTableData`(entity)/`queryJoinData`(entity-entity)/`queryAggregation`(entity) 通过裸 DAO/EQL 读取任意注册 ORM 实体；平台唯一 data-auth 过滤器合并点在 `CrudBizModel.prepareFindPageQuery`（`AuthHelper.appendFilter`），这些路径从不调用（全堆栈 0 处 `checkDataAuth`/`appendFilter`/`AuthHelper` 引用）；`DaoQueryHelper.newSQL` 不输出 `{filter}` 标记，`IEntityFilterProvider` 也不触发。
- **风险**: 对目标实体配置的行级数据权限（组织/租户 data-auth 规则）经目录 `queryTableData/queryJoinData/queryAggregation` 读取同一数据时被静默绕过（目录表指向任意 ORM 实体，返回原始列 Map）。
- **建议**: entity 路径 QueryBean 在 `findAllByQuery` 前合并 `AuthHelper.appendFilter(...)`；join/aggregation 的裸 `orm().executeQuery` 路径施加等价 data-auth 作用域（或显式 opt-out 标志）；或将 entity 类型目录表限定为 metadata 实体。
- **信心水平**: 很可能（机制对框架代码核实；影响取决于部署 data-auth 配置）
- **误报排除**: 非平台标准 CRUD 路径——这是自定义端点，在 `CrudBizModel.findPage` 之外重新实现查询；标准 findPage 在 CrudBizModel.java:381 明确执行合并。
- **修复归属**: MR2

### [MA3.2-02] 手动分页：limit/offset 参数无 QueryBean、无 total、无默认上限（P3）

- **文件**: `entity/NopMetaTableBizModel.java:196-202, 221-228, 241-252`；`entity/NopMetaTableQueryAction.java:88-93`；`api/dto/QueryTableDataResultDTO.java:28-33`；`entity/NopMetaReconciliationConfigBizModel.java:124-126`
- **证据片段**:
  ```java
  public QueryTableDataResultDTO queryTableData(@Name("metaTableId") String metaTableId,
                                                 @Optional @Name("filter") TreeBean filter,
                                                 @Optional @Name("limit") Long limit, ...
  // QueryTableDataResultDTO —— 无 total / hasMore 字段
  private String tableType;
  private List<Map<String, Object>> items = new ArrayList<>();
  ```
- **严重程度**: P3
- **现状**: 三个表查询端点用裸 limit/offset 而非 QueryBean；结果 DTO 只携带页切片；null limit 产生无界全表拉取（`executeReconciliation` 有意传 null 触发全量加载）。
- **风险**: 客户端无法构建可靠分页 UI（无 total/hasMore）；大表无界拉取造成内存/延迟尖峰；对账全表载入内存。
- **建议**: 改 QueryBean 输入、默认上限（如 1000）、经 countByQuery 返回 total 或 hasMore；`executeReconciliation` 显式 limit。
- **信心水平**: 确定
- **误报排除**: 标准 `CrudBizModel.findPage` 返回带 total/limit 的 PageBean——这些自定义端点偏离平台分页契约。
- **修复归属**: MR2

### [MA3.2-06] judgeByRuleId 是执行外部数据源 SQL 的 @BizQuery（P3）

- **文件**: `entity/NopMetaQualityRuleBizModel.java:372-398`
- **证据片段**:
  ```java
  @BizQuery
  public QualityRuleExecuteResultDTO judgeByRuleId(@Name("ruleId") String ruleId, IServiceContext context) {
      NopMetaQualityRule rule = requireEntity(ruleId, "judgeByRuleId", context);
      ...
      QualityRuleJudgment judgment = ensureTableRefExecutor().execute(ref,
              (conn, metaData, productName) -> executor.judge(conn, ref, effectiveSchema, ...));
  ```
- **严重程度**: P3
- **现状**: query 注解的 action 触发任意规则 SQL（含用户配置的 custom_sql）对目录化外部数据源执行；不持久化元数据行（与 executeQualityRule 不同），但 Query 路径上有重外部副作用，无结果上限或 dry-run 标记。
- **风险**: GraphQL 客户端惯例认为 query 廉价/幂等；此方法每次调用在生产数据源上跑 SQL（重复调用成本/DoS 面），与 executeQualityRule（持久化）语义微妙不同。
- **建议**: 改为 @BizMutation（re-judge 是写向操作）或加显式 dryRun/persist 契约 + 速率/上限守卫。
- **信心水平**: 很可能
- **误报排除**: 标准 Nop query 不执行任意外部 SQL；平台模式把 SQL 执行放 mutation（如 executeQualityRule）。
- **修复归属**: MR2
