## Verified controls

1. **Distributed lock correctness (optimistic CAS)**: fire claiming uses
   `JobFireStoreImpl.tryLockFiresForDispatch` (L85-99) → `tryUpdateManyWithVersionCheck`
   (version-column CAS flipping WAITING→DISPATCHING with dispatcher instance id);
   task claiming uses `JobTaskStoreImpl.tryLockTasksForExecute` (L102-114) — same CAS
   WAITING→CLAIMED with worker instance id; task insertion runs in REQUIRES_NEW and
   re-verifies the fire is still DISPATCHING before committing (`insertTasksAndMarkFireDispatching`
   L101-111, returns false on concurrent drift — caller skips metrics). Worker re-checks
   CLAIMED→RUNNING CAS result before invoking (AR-85 fix, `JobWorkerScannerImpl:283-293`)
   and re-checks task/fire terminal state before applying late results
   (`handleExecutionResult:309-369`). Two workers cannot both execute the same task
   except through the bounded, already-adjudicated liveness/SUSPICIOUS races.
2. **Retry semantics — no amplification**: default retry bridge is `NoOpJobRetryBridge`
   (no automatic re-fire); optional nop-retry integration is an explicit dependency
   (`nop-job-retry-adapter`). Dispatcher no-fitting-worker / no-available-instance paths
   revert the fire to WAITING with a backoff window (`JobDispatcherScannerImpl:170-178`,
   `198-207`) instead of duplicating or dropping it; `fireNow` local-mode guarantees a
   single concurrent execution per jobName (`LocalJobScheduler:209-224`,
   `synchronized(job)` + `running != null` skip).
3. **Trigger authorization**: all schedule mutations (`enableSchedule`, `disableSchedule`,
   `pauseSchedule`, `resumeSchedule`, `triggerNow`, `archiveSchedule`) are `@BizMutation`
   and are admin-gated in `NopJobSchedule.xbiz` (`<auth roles="admin" permissions="NopJobSchedule:<action>"/>`).
   Manual fires are attributed (`fire.setTriggeredBy(JobContextHelper.resolveTriggeredBy(context))`,
   `NopJobScheduleBizModel:203`) and serialized against concurrent status transitions via
   optimistic `updateWithRetry` (L143-155). Enforcement of the declared auth requires
   platform action-auth enabled (default off — AUTH-05 adjudicated deployment constraint,
   referenced, not re-litigated).
4. **Trigger input handling**: `triggerNow(overrideParams)` replaces schedule jobParams
   only for that fire (`resolveJobParams:211-218`, snapshotted onto the fire row);
   `RpcJobInvoker` takes `serviceName` from (admin-controlled) jobParams with mandatory
   validation; user-supplied `headers` map is admin-trust configuration. No
   request-controlled URL/endpoint is honored by workers (log report URL is worker-side
   trusted config `nop.job.log.report-url`, never taken from headers — `JobLogReporter`).
5. **Local-mode default-deny**: `LocalJobConfig.enabled` defaults false; platform job
   files (`wf-due-task-scan`, `wf-remind-task-scan`) are opt-in via `@cfg:` keys
   (default false); scheduler-global switch in `scheduler.yaml`.
6. **Secrets/config hygiene**: module sweep found no credentials; 33 `@cfg:` keys match
   the owner-doc config table (`docs-for-ai/03-modules/nop-job.md` §5 verified against
   live `@InjectValue` defaults — consistent, incl. `execution-timeout-ms|-1`,
   `enforce-attribution|false`, `enable-cluster|false`).

## Explicit no-finding statements

- No duplicated execution path under normal concurrency: fire and task claiming are both
  version-CAS guarded; late results from disowned tasks are discarded
  (`isConcurrentlyFinalized` checks); fire-terminal rollback before invoke
  (`JobWorkerScannerImpl:270-277`).
- No retry amplification: default bridge is no-op; backoff windows prevent tight loops;
  misfire/timeout paths converge through the single fire/task state machines.
- No unauthenticated trigger path: `triggerNow` and all schedule mutations are admin-gated
  in xbiz (subject to the platform action-auth opt-in constraint — AUTH-05 referenced).
- No request-controlled endpoint is used for worker→coordinator reporting (report URL is
  trusted worker config; SSRF-safe design per plan 2254 verified live).
- No secrets in module configs or sources (empty demo datasource password only); config
  defaults verified consistent with owner doc.
- Local mode is single-JVM by construction (`fireNow` mutual exclusion) and documented
  as not multi-instance safe — deployments must use distributed mode for uniqueness needs.
