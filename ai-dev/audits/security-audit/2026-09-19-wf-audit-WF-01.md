> Mission: security-audit (roadmap item 5, deliverable WF-01)
> Date: 2026-09-19. Auditor: ZCode session (plan 2026-09-18-2341-7, Phase 2).
> Severity labels: CRITICAL/HIGH/MEDIUM/LOW and P0/P1/P2/P3 (P0=CRITICAL … P3=LOW).
> Scope: workflow delegation (who may act on behalf of an assignee), scope/tenant checks,
> start/manage authorization on workflow instances, audit trail of delegated approvals.
> Method: full read of `WfActorAssignSupport`, `WorkflowEngineImpl.allowCallByUser/doInvokeAction`,
> `WorkflowServiceImpl` (all @BizMutation entries), `DaoUserDelegateService` +
> `NopAuthUserSubstitution` (the live delegation data source), `WfTaskScanner`,
> schema `wf.xdef`/`assignment.xdef`; bean wiring verified in `_service.beans.xml` /

## Verified controls

1. **Delegation check is on the real action path**: GraphQL/RPC mutation
   `WorkflowServiceImpl.invokeActionAsync` (L132-144) → `WorkflowStepImpl.invokeAction`
   (L226-243) first calls `allowCallByUser(ctx)`; `WorkflowEngineImpl.allowCallByUser`
   (L1151-1174) accepts only: step owner == caller, caller passes
   `canBeDelegatedBy(step, userId)`, or caller is inside the step's group actor.
   Failure throws `ERR_WF_NOT_ALLOW_CALL_ACTION_BY_USER`.
2. **Delegation authorization semantics (live data source)**:
   `WfActorAssignSupport.canBeDelegatedBy` (L71-77) delegates to
   `IUserDelegateService.canDelegate(userId, ownerId, wfInstance.workScope)`; the wired
   implementation is `nop-auth-dao` `DaoUserDelegateService` (`auth-dao.beans.xml:10`),
   which accepts only substitutions that (a) are time-valid (`NopAuthUserSubstitution.isValid(now)`,
   start/end window both nullable), and (b) match the workflow instance's `workScope`
   exactly or carry scope `all`. Direction is correct: the delegate acts for the
   substituted owner only along rows addressed to the delegate.
3. **Manage-operation default auth**: kill/suspend/resume/signalWf go through
   `checkManageAuthByDefault` (L268-287): model-configured `checkManageAuth` XPL, manager
   actor membership, workflow creator, or `nop-admin`/`admin` role; otherwise
   `ERR_WF_NOT_ALLOW_MANAGE_BY_USER`. Model-level `checkManageAuth` IS invoked by the
   engine (`WorkflowEngineImpl:653,663`) — unlike `check-start-auth` (finding F-WF-01-2).
4. **Audit trail of delegated approvals**: the actual caller (delegate), not the owner,
   is persisted — `WfRuntime.getCaller` resolves `serviceContext.getUserId()` (L221-226);
   `doInvokeAction` writes `actionRecord.setCaller(caller)` and step-record
   `setCaller/setLastAction` (L1221-1233); transfers persist an action record with
   operator identity via `saveTransferActorsAsync` → `saveTransferAction` (L236-237).
   A delegated approval is therefore distinguishable (caller != owner) in `nop_wf_action`.
5. **Transfer authorization**: `transferActorsAsync` (L211-255) allows self-transfer of
   one's own active steps only; transfer on behalf of another user requires manager
   membership (`checkTransferActorsAuth` L289-294); target user existence is validated.
6. **Scheduler identity cannot bypass user checks**: `WfTaskScanner` invokes due actions
   through the same `invokeActionAsync` path with fixed identity `wf-scheduler`
   (L150-154); user/dept/role-owned steps reject it (`ERR_WF_NOT_ALLOW_CALL_ACTION_BY_USER`
   handled explicitly L103-109), with per-item error isolation (L77-118).

Constraints recorded (not defects): the substitution table has no tenant column and
neither does any nop-wf table — delegation and workflow data are platform-global
(multi-tenant isolation is roadmap item 1's domain); substitution rows grant
scope-limited, time-windowed authority with no revocation audit row of their own
(managed via nop-auth CRUD — auth-side management surface, ownership pointer for item 9,
consistent with plan's ownership note but with corrected wiring facts).

## Explicit no-finding statements

- No code path lets a non-owner, non-delegate, non-group-member user invoke a step
  action: `allowCallByUser` is enforced before every `invokeAction` execution.
- Delegation acceptance always requires a time-valid, scope-matching substitution row
  addressed to the caller (`DaoUserDelegateService.getDelegateOwnerIds` — no bypass branch).
- Delegated approvals persist the true acting caller in action records (no identity
  laundering into the owner identity).
- `signalWfAsync` and kill/suspend/resume are guarded by `checkManageAuthByDefault`.
- Delegated todo/work listing gap (no `getDelegateOwnerIds` consumer in work queries) is
  a functional availability gap, not an authorization bypass (the check is deny-side only).
- No secrets: nop-wf main sources contain no credentials; the only `password:` is an
  empty datasource placeholder in the demo app yaml (`nop-wf/nop-wf-app/.../application.yaml:26`).
