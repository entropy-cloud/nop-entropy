# AI-03 — Prompt-Injection Posture Classification

> Mission: security-audit (roadmap item 6, deliverable AI-03)
> Date: 2026-09-19. Severity labels: CRITICAL/HIGH/MEDIUM/LOW + P0-P3.
> Scope: classification of platform defenses against prompt injection — structural
> isolation of tool outputs, detection guardrails, content-trust labeling. Posture
> classification only (no model-safety evaluation; absence of model-level defenses is a
> documented limitation per plan "Deferred But Adjudicated: prompt-injection as
> LLM-layer concern").
> Method: full read of guardrail package (`PromptInjectionGuardrail`, `IContentGuardrail`,
  `NoOpContentGuardrail`, rule graph), `AgentPromptAssembly` consultation sites,
  `ContentOrigin`/`DefaultContentTrustEvaluator`/`DefaultLevelHintsProducer`, message
  types (role separation), engine defaults; guardrail corpus/rules inventory.

## Posture classification

| Defense layer | Status | Live anchor | Classification |
|---|---|---|---|
| Protocol role separation | PRESENT | `nop-ai-api/.../messages/*` (system/user/assistant/tool messages; `ChatToolResponseMessage` with tool_call_id pairing enforced through the ReAct loop) | Structural separation of channels exists at the message-model level — tool output is a distinct role, never conflated with the system prompt. This is the only structural isolation present. |
| Untrusted-content framing of tool outputs | ABSENT | `AgentToolDispatcher.commitToolResults` / `ChatToolResponseMessage` — tool results enter the conversation verbatim, with no delimiting, sanitization, or untrusted-marking wrapper | **Documented limitation**: the framework performs no structural isolation of tool-output content (the classic indirect-injection carrier: web fetch/file read returning attacker-controlled text). LLM-layer mitigation only. |
| Input detection guardrail | PARTIAL | `AgentPromptAssembly.checkInputGuardrail` (:65-84) consults `IContentGuardrail` on the **last user message only** (`extractLastUserContent`) | Direct user-prompt injection is screened (when a guardrail is wired); indirect injection arriving via tool results is NOT screened by this seam (no consultation on `ChatToolResponseMessage` content). |
| Output detection guardrail | PRESENT | `AgentPromptAssembly.checkOutputGuardrail` (:287-320) — every iteration's assistant output checked (also catches echoed-back injections); BLOCK preserves tool_call_id pairing with per-tool error responses | Effective when wired; default is `NoOpContentGuardrail`. |
| Shipped detector | PRESENT (opt-in) | `PromptInjectionGuardrail` — regex taxonomy (prompt_override / role_hijack / exfiltration / invisible_char incl. bidi+zero-width), `GuardrailMode.ENFORCE` default when constructed, INPUT+OUTPUT directions | Production-grade pattern detector; bypassable by construction (regex vs natural language) — defense-in-depth, not a boundary. |
| Engine default guardrail | NoOp | `ReActAgentExecutor` defaults `contentGuardrail` to `NoOpContentGuardrail` (WARN emitted because a production alternative exists; IContentGuardrail javadoc) | Zero-regression default; deployments must opt in. |
| Content-trust labeling | PRESENT | `ContentOrigin` (CHANNEL_INPUT/WEB_FETCH/FILE_READ/AGENT_GENERATED) + `DefaultContentTrustEvaluator` (WEB_FETCH/FILE_READ untrusted) + `DefaultLevelHintsProducer` → `trustedSource` feeds security-level hints for the Layer-2 matrix | Untrusted-origin content raises the security bar on dependent tool calls (level hints), but does not isolate the content itself in the prompt. |
| Rule-graph guardrails | PRESENT (opt-in) | `guardrail/rule/*` (`RuleGraphGuardrail`, `RuleSetLoader`, `DependsOnCycleDetector`) + `_vfs/nop/ai/agent/guardrail-rules/enterprise-compliance.yaml` (incl. `redact-secret-token` Modify remediation) | Composable rule sets with depends-on cycle detection; YAML-configurable, deployment opt-in. |
| Red-team harness | PRESENT | `guardrail/test/*` (corpus loader, attack transforms, `TestGuardrailRedteamEndToEnd`) + `_vfs/.../guardrail-test/corpus/*.yaml` (injection/role-hijack/exfiltration/invisible-char corpora) | Regression infrastructure for detector quality — supports the posture claim. |

## Findings

| ID | Severity | Anchor | Description | Remediation suggestion |
|---|---|---|---|---|
| F-AI3-1 | LOW (P3) — documented limitation | nop-ai/nop-ai-agent/src/main/java/io/nop/ai/agent/engine/AgentPromptAssembly.java:65-84 (input check = last user message only); AgentToolDispatcher commit path (no tool-result screening) | **Indirect (tool-output) injection is outside the shipped detection wiring.** The INPUT guardrail seam screens only the last user message; tool results (WEB_FETCH/FILE_READ origins — exactly the untrusted ones `DefaultContentTrustEvaluator` flags) re-enter the conversation unguarded. With the default `NoOpContentGuardrail`, no screening occurs anywhere. Per plan adjudication this remains an LLM-layer residual — recorded as a documented limitation for item 9, not a framework guarantee gap requiring code change. | Item-9 hardening note: (a) wire a content guardrail in production deployments; (b) consider extending the INPUT consultation to tool-result messages (or wrapping tool output with an untrusted-content preamble) as a follow-up enhancement. |
| F-AI3-2 | LOW (P3) — posture note | nop-ai/nop-ai-agent/src/main/java/io/nop/ai/agent/guardrail/IContentGuardrail.java:14-22 (NoOp default javadoc); ReActAgentExecutor defaults | **Guardrails are opt-in with NoOp default.** All detection layers (PromptInjectionGuardrail, rule graph) require explicit wiring; a default deployment ships with zero injection screening. Consistent with the shipped zero-regression defaults posture (AI-02 note), but worth an item-9 deployment checklist entry. | Deployment hardening checklist: wire `PromptInjectionGuardrail` (ENFORCE) or a rule set for any internet-facing agent. |

## Explicit no-finding statements

- No claim of model-level injection immunity is made anywhere in the platform docs read;
  the guardrail javadoc itself scopes the control as pattern detection.
- Tool-call arguments are not "trusted" by construction: Layer-1 path checks and the
  security-level matrix consult content-origin hints for untrusted-origin arguments
  (AI-02 controls 6).
- The output guardrail BLOCK path preserves the tool_call_id pairing invariant
  (per-tool error responses), so a blocked iteration cannot corrupt the next LLM call.

## Adjudication (Phase 3 input)

- F-AI3-1: `watch-only residual` (matches plan's pre-adjudicated "prompt-injection as
  LLM-layer concern" deferral; successor: item 9 documented limitation + optional
  enhancement backlog).
- F-AI3-2: `adjudicated deployment default` (item-9 hardening checklist entry; same
  disposition class as AUTH-01 enc-key constraint).
