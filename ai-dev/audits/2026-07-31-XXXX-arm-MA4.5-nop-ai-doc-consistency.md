## 发现明细

### [MA4.5-001] IVectorStore.search() Javadoc 引用已不存在类型 SearchWrapper

- **文件**: `nop-ai/nop-ai-core/src/main/java/io/nop/ai/core/api/vectorstore/IVectorStore.java:82-89`
- **严重程度**: **P2**
- **现状**: `search()` 方法的 Javadoc 声明 `@param wrapper SearchWrapper`，但实际参数类型为 `VectorQueryBean`（继承 `VectorData`）。`SearchWrapper` 类型在代码库中不存在，可能是重构前名称。
  ```java
  /**
   * search vector data by SearchWrapper with options     // ← 失效名称
   *
   * @param wrapper SearchWrapper                         // ← 失效引用
   * @param options Store Options
   * @return the vector data list
   */
  public abstract List<T> search(VectorQueryBean wrapper, VectorStoreOptions options);
  ```
- **风险**: 误导开发者传递错误类型；自动生成文档会暴露失效类型引用。
- **建议**: 将 Javadoc 中的 `SearchWrapper` 更新为 `VectorQueryBean`，或使用通用描述如"query parameters"。
- **信心水平**: 确定

### [MA4.5-002] IVectorStore 定义为 abstract class 但使用 I 前缀命名

- **文件**: `nop-ai/nop-ai-core/src/main/java/io/nop/ai/core/api/vectorstore/IVectorStore.java:29`
- **严重程度**: **P2**
- **现状**: `IVectorStore` 定义为 `public abstract class IVectorStore<T extends VectorData>` 而非 `interface`。Java 命名规范中 `I` 前缀通常表示接口。
  ```java
  public abstract class IVectorStore<T extends VectorData> {
  ```
- **风险**: 对阅读代码的开发者产生误导；与 `IChatService`（真正的 interface）不一致。
- **建议**: 重命名为 `AbstractVectorStore` 或类似名称移出 `I` 前缀；或改为 `interface` 并调整继承体系。
- **信心水平**: 确定

### [MA4.5-003] IAiChatProgressListener @Deprecated 缺少 forRemoval=true

- **文件**: `nop-ai/nop-ai-core/src/main/java/io/nop/ai/core/api/chat/IAiChatProgressListener.java:16`
- **严重程度**: **P2**
- **现状**: `IAiChatProgressListener` 仅有 `@Deprecated`（无 `forRemoval=true`），但同一包中其他所有 `IAiChat*` 废弃类型（`IAiChatService`、`IAiChatSession`、`AiChatOptions`）均使用 `@Deprecated(forRemoval=true)`。`IAiChatProgressListener` 的 Javadoc `@deprecated` 标记说"will be removed in future versions"，与 bare `@Deprecated` 语义矛盾。
  ```java
  // IAiChatProgressListener.java:12-16
  /**
   * @deprecated This internal AI core interface is deprecated and will be removed in future versions.
   * Please use the new AI API instead.
   */
  @Deprecated   // ← 缺少 forRemoval=true
  public interface IAiChatProgressListener {
  ```

  对比 `IAiChatService.java:12-15`:
  ```java
  @Deprecated(forRemoval = true)
  public interface IAiChatService {
  ```
- **风险**: 编译器不会为此接口产生 `forRemoval` 警告，消费者不会获知移除意图；系内不一致导致维护困惑。
- **建议**: 将 `@Deprecated` 改为 `@Deprecated(forRemoval = true)` 以匹配其他 `IAiChat*` 类型。
- **信心水平**: 确定

### [MA4.5-004] DefaultAgentEngine Builder 与 field 的 callAgentTimeoutMs 默认值不一致

- **文件**: `nop-ai/nop-ai-agent/src/main/java/io/nop/ai/agent/engine/DefaultAgentEngine.java:434,500`
- **严重程度**: **P2**
- **现状**: `DefaultAgentEngine` 的实例 field 默认值为 `60_000L`（60s），但 `Builder` 内部字段默认值为 `120_000L`（120s）。通过构造函数链（8 个构造函数）构造时使用 60s；通过 `Builder.build()` 构造时使用 120s。
  ```java
  // 行 434: 实例 field 默认
  private long callAgentTimeoutMs = 60_000L;

  // 行 500: Builder 字段默认
  private long callAgentTimeoutMs = 120_000L;
  ```
  此外，`setCallAgentTimeoutMs`（行 1994-1998）要求值必须为正数（`<= 0` 抛异常），与文档所说"必须为正数"一致，但 Builder 在 `applyTo`（行 592）无条件调用 `engine.setCallAgentTimeoutMs(callAgentTimeoutMs)`，会将 Builder 的 120s 覆盖 field 的 60s。
- **风险**: 两种构造路径产生不同 timeout 值，导致不可预测行为。Builder 作为推荐方式（行 601-603 提倡使用）与构造函数链行为不一致。
- **建议**: 统一两个默认值。考虑到 Builder 是推荐路径，建议将 field 默认改为 `120_000L` 匹配 Builder，或反之并更新文档。
- **信心水平**: 确定

### [MA4.5-005] docs-for-ai 文档记载的 callAgentTimeoutMs 默认值与 Builder 不一致

- **文件**: `docs-for-ai/03-modules/nop-ai.md:64` vs `DefaultAgentEngine.java:500`
- **严重程度**: **P2**
- **现状**: 文档记载 `callAgentTimeoutMs` 默认值为 `60000`（60s），但 `Builder` 默认值为 `120_000L`（120s）。
  ```
  文档: | `callAgentTimeoutMs` | `60000`（60s） | call-agent 子 agent 执行...
  代码: private long callAgentTimeoutMs = 120_000L;  // 在 Builder 中
  ```
  注：实例 field 默认（`60_000L`, 行 434）与文档一致，但 Builder 默认（`120_000L`, 行 500）不同。
- **风险**: 通过 Builder 构造的消费者实际获得 120s 而非文档所述的 60s；文档与代码不同步。
- **建议**: 将文档更新为 `120000`（120s）以匹配 Builder 默认，同时修复内部不一致（见 MA4.5-004）。
- **信心水平**: 确定

### [MA4.5-006] IToolExecutor 公开 API 接口缺少 Javadoc

- **文件**: `nop-ai/nop-ai-toolkit/src/main/java/io/nop/ai/toolkit/api/IToolExecutor.java:1-11`
- **严重程度**: **P2**
- **现状**: 核心公开 API 接口 `IToolExecutor` 无任何 Javadoc——既无类级别描述，也无方法级别说明。
  ```java
  public interface IToolExecutor {
      String getToolName();

  }
  ```
- **风险**: 工具包的使用者需要阅读实现类或外部文档才能理解该接口的契约。`getToolName()` 的语义（返回与 `AiToolModel.getName()` 匹配的名称？）和 `executeAsync` 的异常行为未定义。
- **建议**: 添加类级别 Javadoc 说明职责（"Executes an AI tool call and returns the result"），以及方法级别 Javadoc 说明 `getToolName()` 的返回值约束和 `executeAsync` 的契约（返回值、异常传播、取消语义）。
- **信心水平**: 确定

### [MA4.5-008] IFileOperator @deprecated 使用中文，与其他废弃类型不一致

- **文件**: `nop-ai/nop-ai-core/src/main/java/io/nop/ai/core/file/IFileOperator.java:13-14`
- **严重程度**: **P3**
- **现状**: `IFileOperator` 的 `@deprecated` Javadoc 使用中文："使用 io.nop.ai.toolkit.fs.IToolFileSystem 替代"。所有其他 `IAiChat*` 废弃类型的 `@deprecated` Javadoc 使用英文。
  ```java
  // IFileOperator.java
  /**
   * @deprecated 使用 io.nop.ai.toolkit.fs.IToolFileSystem 替代   // ← 中文
   */
  @Deprecated
  public interface IFileOperator {
  ```
  对比 `IAiChatService.java`:
  ```java
  /**
   * @deprecated This internal AI core interface is deprecated and will be removed in future versions.
   * Please use the new AI API instead.
   */
  ```
  另：`IFileOperator` 使用 `@Deprecated`（无 `forRemoval`），而 `AI Chat` 系使用 `@Deprecated(forRemoval = true)`。但考虑到 `IFileOperator` 的替代者（`IToolFileSystem`）已是成熟接口，此 P3 仅针对语言不一致。
- **风险**: 代码库中废弃消息语言不一致；`IFileOperator` 的废弃语义（纯 deprecated vs forRemoval）不明确。
- **建议**: 将 `@deprecated` 消息改为英文；考虑是否添加 `forRemoval = true`（取决于替代计划）。
- **信心水平**: 确定

- **文件**: 
  - `nop-ai/nop-ai-api/src/main/java/io/nop/ai/api/chat/IChatLogger.java:1-7`
  - `nop-ai/nop-ai-toolkit/src/main/java/io/nop/ai/toolkit/api/IToolExecuteContext.java:1-21`
