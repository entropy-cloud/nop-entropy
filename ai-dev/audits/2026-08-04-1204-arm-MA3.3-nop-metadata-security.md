### [MA3.3-01] nop-metadata 全模块 0 个 @Auth：自定义敏感 mutation 仅剩平台粗粒度兜底（且默认关闭）——MISSING-AUTH 复核维持 watch-only（P2）

- **文件**: 全模块扫描 `nop-metadata/nop-metadata-service/src/main/java/io/nop/metadata/service/`（41 个 @BizModel，@Auth 命中 0）；兜底机制 `nop-graphql-core/.../reflection/ReflectionBizModelBuilder.java:330-336`；开关 `nop-api-core/.../ApiConfigs.java:87-92`（`nop.auth.enable-action-auth` 默认 **false**、`enable-data-auth` 默认 **false**）；装配 `nop-biz/.../biz-defaults.beans.xml`；`GraphQLEngine.java:345-349`；`GraphQLActionAuthChecker.java:41-44,128-143`；app 配置 `nop-metadata-app/src/main/resources/application.yaml`（无 enable-action-auth/data-auth 配置）

- **严重程度**: P2（watch-only 维持，07-20 裁定不变；无证据显示暴露面比裁定更糟）
- **现状**: 部署默认 action-auth/data-auth 双关（app 未配置）；启用后仅粗粒度 `:mutation`/`:query` 兜底（`NopMetaDataSource:mutation|NopMetaDataSource:testConnection` 格式），无任何细粒度 action 权限。testConnection/syncExternalTables/executeCheckpoint/releaseModule/importOrmModel/rebuildSearchIndex 等 40 个自定义方法全部同权。
- **风险**: 动作级最小权限缺失——任何拥有实体 mutation 权限的用户可执行全部高危动作（含外部数据源连接/执行）；默认配置下动作级校验完全不生效（仅登录）。
- **建议**: 维持 watch-only（与 plan 300 裁定一致：action-auth 默认关闭 + 粗粒度 mutation 兜底 + 产品策略待定）；部署侧开启 `nop.auth.enable-action-auth=true` 并做角色-资源授予演练；后续为高危方法补 `@Auth(permissions="...:<action>")` 细粒度 FNPT（归 MR2）。
- **信心水平**: 确定（全链路代码实证：grep 0 命中 + 4 处平台源码 + app 配置核对）
- **误报排除**: 已排除 xbiz/xml 层补充 auth（web/app 两个 action-auth.xml 均无增量）；已排除工作流层（wf checkActionAuth 属 WfModel 自身配置，不覆盖 GraphQL 直调）。
- **修复归属**: MR2（框架内置支持已存在，仅需模块侧标注 + 部署配置）

### [MA3.3-05] Webhook SSRF 白名单回归核对（一致/通过，含盲区记录）

- **文件**: `quality/CheckpointActionDispatcher.java:65-71,194-266,306-346`；`TestCheckpointActionDispatcherWebhookSsrf.java:117-293`；`NopMetaQualityCheckpointBizModel.java:115-122,385-391`
- **证据片段**:
  ```java
  // 实现 :243-266 validateWebhookUrl：协议白名单 → isInternalHost（RFC1918 172.16-31 精确区间 + 169.254 + localhost + 127.* + ::1）
  ```

- **严重程度**: 无缺陷（回归 PASS）
- **现状**: 实现与测试期望逐条一致：非 http 协议拒绝（file:/ftp:/data:/gopher:/jar:/netdoc:）↔ 协议白名单；内网默认拒绝（127.0.0.1/localhost/10./192.168./172.16-31/169.254.169.254/[::1]，172.31.255.255 边界一致）↔ isInternalHost；allowlist 放行 + URL 透传；外网默认放行；GET/DELETE/TRACE/CONNECT/PATCH 拒绝、POST 默认 + PUT 显式放行 ↔ method 白名单；timeout 30s 默认/5s 配置/0 回退；阻断 URL 不触达 IHttpClient.fetch（fetchCallCount==0）。

- **建议**: 记录盲区即可（本审计项验收通过）。
- **信心水平**: 确定
- **修复归属**: 非阻塞（深挖归 MA7.6）

## 总评

安全面整体处于"框架机制齐备、模块侧未启用"状态：敏感字段防护（connectionConfig 四重防护 + 脱敏链路 + 事件快照 REDACTED + anti-hollow 测试）与 webhook SSRF 白名单（实现/测试逐条一致）质量高；核心裁定项 MISSING-AUTH 经全链路代码实证维持 watch-only（与 plan 300 一致：默认关闭 + 粗粒度兜底 + 产品策略待定）。真正需要关注的是部署决策面：双开关默认 false 意味着动作级/行级校验当前全部不生效，收紧时应同步补齐 NopMetaSearch FNPT（MA3.3-02）与高危方法 @Auth 标注（MA3.3-01 建议）。
