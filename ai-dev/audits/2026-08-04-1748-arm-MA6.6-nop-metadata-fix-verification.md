## RACE 终局定论（Decision）

### 输入事实（live 复核，2026-08-04）

1. **UK 存在性（模型层）**：orm.xml:1315 `UK_NOP_META_TABLE_MODULE_NAME (metaModuleId, tableName)` — YES（模型为 source of truth）
2. **UK 存在性（DDL 快照层）**：**三方言 deploy/sql 全部缺失** — mysql/oracle/postgresql 的 `_create_nop-metadata.sql` 中 nop_meta_table 仅 PK，且**模型 ~35 个 unique-key 一个都没有出现在任何 DDL 快照**（mysql `UNIQUE KEY` 零命中；oracle/postgres 的 "unique" 命中仅为 nop_meta_entity_unique_key 表的列名/表名）。DDL 最近一次再生成（1de696026，P2-MA2-01/02/03 修复）仍未发射 UK
3. **运行时实际防护**：测试/标准部署经 `initDatabaseSchema=TRUE` 从 ORM 模型生成 schema → UK 实际物化；仅从静态 deploy/sql 供给 schema 的部署无 UK 保护
4. **并发败者路径**：`NopMetaDataSourceBizModel.upsertExternalTable:435-474`（全文已读）——按 (metaModuleId, tableName) 查候选 + Java 层 schema 精确匹配；`table == null` 时 `tableDao.saveEntity(table)`（:466）**无 catch-duplicate、无失败后 re-read、非幂等**；唯一兜底为调用方 syncExternalTables :196-203 的 per-table catch（LOG error + ErrorDTO + clearSession + continue）——败者行不创建、数据（schema/querySpace/buildSql）丢失且向调用方浮出虚假错误；应用键 (module,schema,tableName)（javadoc :421-422）宽于 DB UK (module,tableName) → 不同 schema 同名表并发同步必撞 UK
5. **P2-MA3-03**：schema 维度未进 UK（orm.xml:1315 确认仅 2 列）——多 schema 同名表非并发也必然冲突，归 MR2（需 ORM 模型变更 plan-first）

### 终局裁定

**维持 watch-only（RACE 并发面）+ 新增 P2 快照面（MA6.6-001）**

- **并发重复面（RACE 本体）**：维持 **watch-only residual** — 标准供给路径（模型生成 schema，Nop 平台默认）下 UK 已阻止并发重复；败者非幂等为真实但不产生错误数据（完整性由 UK 保住），错误呈现为虚假错误条目而非静默损坏。升级不成立（无数据损坏证据），降级不成立（败者数据确实丢失）。**依据**：MA3.4 初步复核 + 本审计全代码复核（无 catch-duplicate+re-read 模式确认）。
- **新增 MA6.6-001（P2）**：**deploy/sql 快照零 UK 发射** — 从静态 DDL 供给 schema 的部署失去全部 ~35 个 unique-key 保护（含 UK_NOP_META_TABLE_MODULE_NAME），RACE 保护在该部署形态下不成立；且此问题超出 RACE 单点（全部 UK 缺失）。**归属**：MR3 或 DDL 生成管线 owner（再生成 DDL 快照并核验 UK 发射；需核对 gen-ddl 管线为何不发射 UK——模板配置或产物过期）。
- **P2-MA3-03**：确认维持（schema ∉ UK），归 MR2（ORM 变更 plan-first）。
