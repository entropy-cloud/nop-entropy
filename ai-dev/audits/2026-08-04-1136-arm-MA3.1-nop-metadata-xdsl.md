### [MA3.1-01] 3 个 xwf 部署在解析器不可达的 VFS 路径，工作流启动必然失败（P1）

- **文件**: `nop-metadata/nop-metadata-service/src/main/resources/_vfs/nop/metadata/wf/{metaDataContractApproval,qualityBreachApproval,tagLabelConfirmApproval}/v1.xwf`（3 个文件）；触发点 `QualityAlertWorkflowService.java:76` + `_NopMetaDataContract.xbiz` 继承的 approval-support.xbiz:33
- **证据片段**:
  ```xml
  <workflow x:extends="/nop/wf/base/oa.xwf"
            x:schema="/nop/schema/wf/wf.xdef" ...
            wfName="metaDataContractApproval" wfVersion="1" ...>
  ```
  ```java
  // WorkflowManagerImpl.getWorkflowModel()
  String path = NopWfCoreConstants.RESOLVE_WF_NS_PREFIX + wfName;  // "resolve-wf:metaDataContractApproval"
  return (IWorkflowModel) ResourceComponentManager.instance().loadComponentModel(path);
  ```
  ```xml
  <!-- wf.register-model.xml（nop-wf-core） -->
  <resolve-handler resolveInDir="/nop/wf"/>
  ```
- **严重程度**: P1
- **现状**: `ResourceComponentManager.resolveModelLoader`（nop-core:171-209）将 `resolve-wf:{wfName}[/v{version}]` 映射为 `{resolveInDir}/{subName}.xwf` = `/nop/wf/metaDataContractApproval/v1.xwf`；3 个文件实际位于 `/nop/metadata/wf/`（全仓库唯一不在 `/nop/wf/` 下的 xwf），解析失败 → 无 loader → 加载异常。

- **建议**: 将 3 个文件移至 `_vfs/nop/wf/{wfName}/v{version}.xwf`（平台唯一约定，见 `docs-for-ai/03-runbooks/build-approval-flow.md` 及 nop-wf 自身 14 个 example），或在 nop-metadata 增加 delta `register-model.xml` 重映射 `resolveInDir`。修复后补一个工作流模型加载测试。
- **信心水平**: 确定（`WorkflowManagerImpl.getWorkflowModel` → `loadComponentModel` → `resolveModelLoader` 代码路径逐行核实；`find` 确认 3 文件仅存在于 `/nop/metadata/wf/`）
- **误报排除**: 平台 14 个 example 与 nop-wf-service 测试流全部位于 `/nop/wf/` 下；`resolveInDir` 全仓库无 delta 覆盖。非误报。
- **修复归属**: MR2（P1；roadmap 规则：MA3+MA4 的 P1 归 MR2）

### [MA3.1-02] 3 个 xwf 使用 `wf-approval:notifyResult` 标签但从未 import 对应 xlib，模型加载期必然 ERR_XPL_NOT_ALLOW_UNKNOWN_TAG（P1）

- **证据片段**:
  ```xml

      <source>
          <wf-approval:notifyResult bizObj="NopMetaDataContract"
                                     approved="${wfRt.status == 'APPROVED'}"/>
      </source>
  </listener>
  ```
  ```xml
  <!-- oa.xwf base 的 x:config（合并后唯一 config 来源） -->
  <x:config>
      <c:import from="/nop/wf/xlib/oa.xlib" />
  </x:config>
  ```
- **严重程度**: P1
- **现状**: 3 个 xwf 均未声明 `<x:config>`；合并后模型只注册 `oa` 命名空间（`AbstractDslParser.applyCompileConfig`），`wf-approval` 命名空间未注册 → `XplCompiler.getTagCompiler` 在 allowUnknownTag=false 下抛 `ERR_XPL_NOT_ALLOW_UNKNOWN_TAG`。xwf `<source>` 为 xpl 域，模型解析期即编译，非惰性。

- **信心水平**: 确定（编译器代码路径逐行核实；已排除全局 taglib registry / xpl:lib / xdef default-extends 三种可能的注册途径）
- **误报排除**: 非误报——不存在全局 xlib 注册机制；平台标准做法就是 x:config 显式 import。
- **修复归属**: MR2（P1）
