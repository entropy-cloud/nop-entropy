## 发现清单

### [P1-MA4-601] P-1 反模式：18 个"实例化/接口/空参 NPE"测试对核心行为零保护

- **文件**: `query/TestEntityEntityJoinAggregationProcessor.java:12-27`、`query/TestExternalExternalJoinAggregationProcessor.java:13-28`、`query/TestMixedSameDbJoinAggregationProcessor.java:12-27`、`query/TestCrossDbInMemoryAggregationProcessor.java:17-31`、`query/TestEntityAggregationProcessor.java:30-44`、`query/TestSqlAggregationProcessor.java:28-42`
- **证据片段**:
  ```java
  assertTrue(new SqlAggregationProcessor() instanceof AggregationProcessor);   // instanceof
  assertNotNull(processor);                                                    // canInstantiate
  assertThrows(NullPointerException.class, () -> processor.execute(null));     // NPE-on-null
  ```
- **严重程度**: P1（按 skill 判据：改错实现测试仍通过）
- **现状**: 6 个 processor 测试类各含这 3 个模板测试，共 18 个；验证"核心逻辑改错后仍通过"：把任一 processor.execute() 改为 `return emptyResult()`，18 个测试全部通过——它们不触达任何行为分支。
- **风险**: 单元层对 JOIN 分派/执行逻辑零保护（与 MA4.3 P2-MA4-301 同源，此处为 P-1 定性）；null→NPE 未验证防御性契约（真正防御应断言显式 NopException+ErrorCode）。
- **建议**: 删除或改造成最小行为测试（TestSqlAggregationProcessor:45-56 的 unsupported-type mock 测试是正确范式）。
- **信心水平**: 高（逐行核对 18 个方法均无行为断言）
- **误报排除**: 非"测试少"——这是"写了测试但 100% 无信息量"的结构性浪费，同包有正确范式可对照。
- **复核状态**: 未复核
- **修复归属**: MR2

### [P2-MA4-602] P-1/P-4 反模式：helper 镜像测试跨 3-4 文件重复 30+ 方法

- **文件**: safeAlias 5 组：`query/TestEntityAggregationProcessor.java:48-71`、`query/TestExternalAggregationProcessor.java:61-84`、`query/TestSqlAggregationProcessor.java:100-118`（各 5 个，TestCrossDbInMemoryAggregationProcessor.java:281-287 再 1 个）；aggSqlOf 6 组：Entity:75-118、External:87-131、Sql:121-143
- **证据片段**:
  ```java
  // TestEntityAggregationProcessor.java:76 与 TestExternalAggregationProcessor.java:89 与 TestSqlAggregationProcessor.java:123 完全同文
  @Test public void testAggSqlOfSum() {
      assertEquals("SUM(col)", aggSqlOf(_NopMetadataCoreConstants.AGG_FUNC_SUM, "col", "m1"));
  }
  ```
- **严重程度**: P2
- **现状**: safeAlias 同一输入-输出对在 4 个文件出现 5 次；aggSqlOf 6 组断言在 3 个文件完全复制；`assertEquals("SUM(col)", ...)` 镜像 `"SUM(" + func + "(" + col + ")"` 的实现拼接。
- **风险**: 维护成本（改别名规则需同步 4 处）；aggSqlOf 镜像断言在聚合函数改名时误报而非捕获 bug。
- **建议**: 收敛为单一 `TestAggregationHelperEdgeCases`；aggSqlOf 断言改测"输入函数→输出语义"（如 count_distinct 必须含 DISTINCT）。
- **信心水平**: 高（diff 可证实逐字重复）
- **误报排除**: 明确区分"重复但有效"（各 processor 的 buildFromClause 有差异）与"逐字复制且镜像常量"（本发现），只列后者。
- **复核状态**: 未复核
- **修复归属**: MR2

### [P2-MA4-603] P-4 反模式：反射调用私有方法测试（TestMetaJoinTruncateOverflow）

- **文件**: `query/TestMetaJoinTruncateOverflow.java:85-98`
- **证据片段**:
  ```java
  Method m = AggregationHelper.class.getDeclaredMethod("truncateCrossDb", List.class, Long.class, Long.class);
  m.setAccessible(true);
  return (List<Map<String, Object>>) m.invoke(null, rows, limit, offset);
  ```
- **严重程度**: P2（测试有价值但耦合实现私有细节）
- **现状**: 5 个溢出测试中 2 个经反射触私有 `truncateCrossDb`（AggregationHelper 无公开入口）。
- **风险**: truncateCrossDb 改名/改签名即编译期不报错的运行时失败；反射路径若被模块化拒绝则测试变脆弱。
- **建议**: AggregationHelper 增加包级可见重载或经 CrossDbInMemoryAggregationProcessor 公开路径触发。
- **信心水平**: 高
- **误报排除**: 不否定溢出测试的 bug 捕获价值（ErrorCode+param 断言强），只针对"经反射打私有方法"这一耦合手段。
- **复核状态**: 未复核
- **修复归属**: 非阻塞

### [P3-MA4-604] P-4 反模式：断言常量等于内联字面量（TestSqlPaginationOffsetOnly）

- **文件**: `query/TestSqlPaginationOffsetOnly.java:118-129`
- **证据片段**:
  ```java
  @Test public void testWiringToCallSitesConstantsExist() {
      assertTrue(SqlPagination.MYSQL_MAX_LIMIT.equals("18446744073709551615"),
              "constant value matches MySQL约定");
  ```
- **严重程度**: P3
- **现状**: 同一文件其余 7 个测试均为有效行为断言；此方法断言"常量==复制来的字面量"，常量改变（即使行为仍正确）测试失败——纯镜像。
- **风险**: 无真实 bug 捕获能力。
- **建议**: 删除该断言，保留同方法 appendLimitOffset 接线断言。
- **信心水平**: 高
- **误报排除**: 只指向该单个断言，未否定本文件整体价值（明确 7/8 有效）。
- **复核状态**: 未复核
- **修复归属**: 非阻塞

### [P3-MA4-605] P-8 反模式：无效负面测试（null→NPE 断言，与 601 同批）

- **文件**: 6 个 processor 测试类的 `testExecuteWithNullContextThrowsNpe`（文件清单同 601）
- **证据片段**: 见 601。
- **严重程度**: P3（与 601 同一证据从 P-8 视角补充定性，不重复计数）
- **现状**: null 输入断言抛 NPE 而非业务 ErrorCode——Nop 防御性契约是显式 NopException；NPE 断言既验证不了防御，也验证不了"不静默返回空"。
- **风险**: execute(null) 若被改成静默返回空（更危险的降级），NPE 测试反而变红制造误导；该断言不锚定任何业务不变量。
- **建议**: 改为 `assertThrows(NopException.class, ...)` + 断言 ErrorCode（参照 TestSqlAggregationProcessor:45-56 范式）。
- **信心水平**: 高
- **误报排除**: 与 601 是同一证据从 P-1/P-8 双维度定性，非重复计数。
- **复核状态**: 未复核
- **修复归属**: MR2

- **信心水平**: 高
- **误报排除**: 明确两条断言判定同一事实。
- **复核状态**: 未复核
- **修复归属**: 非阻塞

## 16-03 复核（重复 CRUD 反模式·核心域部分）

**结论：核心域未复现"同一实体多份几乎相同的 CRUD 冒烟"。** 5 个 AutoTest 类分别针对 5 个不同实体各 1 个用例，属"每实体一份模板化冒烟"，成本低、无同实体重复副本。真正的重复在另一形态——P2-MA4-602 的 processor helper 测试跨 4 文件逐字复制（30+ 方法）。**核心域部分 16-03 关闭或降为非阻塞；602 作为 MR2 增量项。**
