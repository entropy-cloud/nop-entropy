# 审计报告：MA1.5 — nop-ai 全模块命名与术语一致性

**审计 ID**：ARM-MA1.5  
**日期**：2026-07-31  
**范围**：所有 nop-ai 模块（排除 MCP）  
**维度**：D19 — 命名与术语一致性  

---

## 摘要

审计全部 nop-ai 模块的命名与术语一致性，覆盖 D19 维度。

**总发现数**：9（P1=3, P2=4, P3=2）

| 严重度 | 数量 | 关键主题 |
|--------|------|---------|
| P1 | 3 | contexts/context 关系名不匹配；五种命名约定并存；重复 ORM session/message 模型 |
| P2 | 4 | 错误码前缀不一致；状态模型 enum vs dict 不匹配；列名前缀冗余；类名前缀不匹配模块 |
| P3 | 2 | GptOrmErrors 使用 gpt 命名空间；revision 替代 version 作版本属性名 |

---

## 发现明细

### [P1-MA1-031] NopAiSessionContext 关系 refPropName 不匹配（context vs contexts）

- **模块**: `nop-ai`
- **文件**: `nop-ai/model/nop-ai.orm.xml:1051-1052,1275`
- **严重程度**: **P1**
- **现状**: NopAiSession 的 to-many 名为 `contexts`，但 NopAiSessionContext 的 to-one 中 `refPropName="context"`（单数），导致生成的 xmeta 暴露重复属性 `context` 和 `contexts`。
- **风险**: API 消费者困惑；重复属性指向相同数据。
- **建议**: 将第 1275 行的 `refPropName="context"` 改为 `refPropName="contexts"`。
- **信心水平**: 高

### [P1-MA1-032] 五种命名约定并存

- **模块**: 全 nop-ai
- **严重程度**: **P1**
- **现状**: 至少 5 种命名约定：`NopAi*`（ORM/Dao）、`Chat*`/`IChat*`（新 API）、`Ai*`/`IAi*`（废弃 API）、`Agent*`/`AiAgent*`（agent）、`*Tool*`（toolkit）。
- **风险**: 开发者需在模块间切换约定；代码复用困难。
- **建议**: 采用统一模块命名约定。
- **信心水平**: 高

### [P1-MA1-033] 重复 ORM 模型覆盖 Session 和 Message

- **模块**: `nop-ai-agent` vs `nop-ai`（根 ORM）
- **文件**: `nop-ai-agent/src/main/resources/_vfs/nop/ai/agent/orm/app.orm.xml` vs `nop-ai/model/nop-ai.orm.xml`
- **严重程度**: **P1**
- **现状**: 两套独立 ORM 模型覆盖 Session/Message：`NopAiSession`（`nop_ai_session` 表）vs `AiAgentSession`（`ai_agent_session` 表）；列命名风格也不同（snake_case vs 大写码）。
- **风险**: 数据重复、同步问题、开发者困惑。
- **建议**: 合并 agent ORM 实体到主模型，或明确记录分离边界。
- **信心水平**: 高

### [P2-MA1-034] 错误码前缀不一致

- **模块**: `nop-ai-core` / `nop-ai-service` / `nop-ai-coder` / `nop-ai-dsl-orm`
- **文件**: `AiCoreErrors.java` / `NopAiErrors.java` / `AiCoderErrors.java` / `GptOrmErrors.java`
- **严重程度**: **P2**
- **现状**: `nop.err.ai.*` 根前缀一致，但 `nop-ai-dsl-orm` 使用 `nop.err.gpt.orm.*`。子命名空间结构随意。
- **风险**: 错误码碰撞；调试困难。
- **建议**: 统一子命名空间为 `nop.err.ai.{module}.{specific-error}`；迁移 `nop.err.gpt.orm.*`。
- **信心水平**: 高

### [P2-MA1-035] 状态模型：enum vs dict 不匹配

- **模块**: `nop-ai-agent` vs `nop-ai`（ORM）
- **文件**: `AgentExecStatus.java` / `nop-ai.orm.xml`
- **严重程度**: **P2**
- **现状**: `NopAiSession.status` 使用 int dict `ai/session-status`（CREATED=10, RUNNING=20, ...），`AgentSession.status` 使用 enum `AgentExecStatus`（pending, running, ...）。值不同、名称不同。
- **风险**: 状态转换/映射代码存在 bug 空间。
- **建议**: 统一为一种表示，或清晰定义边界转换逻辑。
- **信心水平**: 高

### [P2-MA1-036] NopAiChatResponse 冗余 ai_ 列前缀 vs NopAiModel

- **模块**: `nop-ai`（ORM 模型）
- **文件**: `nop-ai/model/nop-ai.orm.xml:649-652`
- **严重程度**: **P2**
- **现状**: `NopAiChatResponse` 使用 `ai_provider`/`ai_model`（带 `ai_` 前缀），但 `NopAiModel` 使用 `provider`/`model_name`。
- **风险**: SQL JOIN 需列别名；同一个概念不同命名。
- **建议**: 统一或记录 `ai_` 前缀是区分快照列 vs FK 列的有意设计。
- **信心水平**: 中

### [P2-MA1-037] AiCoreErrors 类名前缀不匹配模块包

- **模块**: `nop-ai/nop-ai-core`
- **文件**: `AiCoreErrors.java` / `NopAiErrors.java`
- **严重程度**: **P2**
- **现状**: `nop-ai-core` 使用 `AiCoreErrors`（缺 `Nop` 前缀），而 `nop-ai-service` 使用 `NopAiErrors`。
- **建议**: 选择一种约定并统一应用。
- **信心水平**: 高

### [P3-MA1-038] GptOrmErrors / GptOrmConstants 使用 gpt 命名空间而非 ai

- **模块**: `nop-ai/nop-ai-dsl-orm`
- **文件**: `GptOrmErrors.java` / `GptOrmConstants.java`
- **严重程度**: **P3**
- **现状**: 类名使用 `Gpt*` 而非 `AiDslOrm*`；错误码使用 `nop.err.gpt.orm.*`；XDEF 路径 `/nop/schema/gpt/orm.xdef`。
- **建议**: 重命名为 `AiDslOrmErrors`/`AiDslOrmConstants`；XDEF 路径迁移至 `/nop/schema/ai/`。
- **信心水平**: 中

### [P3-MA1-039] NopAiSessionContext 使用 revision 作版本属性名

- **模块**: `nop-ai`（ORM 模型）
- **文件**: `nop-ai/model/nop-ai.orm.xml:1231,1253`
- **严重程度**: **P3**
- **现状**: 唯一使用 `versionProp="revision"`（而非标准的 `version`）的实体。
- **建议**: 改为 `versionProp="version"` 或记录理由。
- **信心水平**: 高
