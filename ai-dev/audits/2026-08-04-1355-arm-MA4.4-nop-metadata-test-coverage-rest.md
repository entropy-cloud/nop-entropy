## 发现清单

### [P1-MA4-401] judgeByRuleId 的测试是空洞断言（assertNotNull）——16-04 测试质量部分未达标

- **文件**: `nop-metadata/nop-metadata-service/src/test/java/io/nop/metadata/service/TestNopMetaQualityRuleBizModel.java:297-302`
- **证据片段**:
  ```java
  // ===== judgeByRuleId =====
  @Test
  public void testJudgeByRuleId() {
      GraphQLResponseBean resp = graphQLEngine.executeGraphQL(graphQLEngine.newGraphQLContext(req(
              "query { NopMetaQualityRule__judgeByRuleId(ruleId: \"__not_exist__\") { status } }")));
      assertNotNull(resp);
  }
  ```
- **严重程度**: P1
- **现状**: judgeByRuleId（main：NopMetaQualityRuleBizModel.java:373，requireEntity 后执行判定）的测试只断言 `assertNotNull(resp)`——即使 GraphQL 报错（getData()==null、hasError()==true）也通过；用不存在的 ruleId 调用却未断言错误路径错误码、未断言判定结果 status 语义。
- **风险**: 核心逻辑改成"永远抛异常"或"永远返回固定 status"，测试仍然绿色；这是 QualityRule 执行引擎唯一未语义验证的 action。
- **建议**: 重写为：真实规则+结果 → 断言 status=PASS/FAIL 语义；非存在 ruleId → 断言 hasError() + 错误码；复用现有 exec/assertStatus helper。
- **信心水平**: 高（读取 main 实现与测试全貌）
- **误报排除**: 同文件其它测试均用 assertStatus/assertActualValue 断言真实值，唯独此方法退化；非"测试少"泛论。
- **复核状态**: 未复核
- **修复归属**: MR2

### [P3-MA4-404] Map.toString 子串断言模式（status=PASS）为弱断言

- **文件**: `nop-metadata/nop-metadata-service/src/test/java/io/nop/metadata/service/TestNopMetaQualityRuleBizModel.java:597-607`
- **证据片段**:
  ```java
  private static void assertStatus(GraphQLResponseBean resp, String expected) {
      String data = String.valueOf(resp.getData());
      assertTrue(data.contains("status=" + expected), ...);
  }
  ```
- **严重程度**: P3
- **现状**: 6 个 quality 测试类大量使用 `data.contains("status=PASS")`/`actualValue=3.0` 子串断言。值确实被校验（保护语义存在），但依赖 Map.toString() 格式；DTO 增字段/改 toString/错误消息恰好含同串时误通过或误失败，失败定位差。
- **风险**: 低（当前 DTO 稳定）；重构 DTO 输出格式时产生连锁脆弱。
- **建议**: 长期改为 JSON 字段级断言（TestNopMetaQualityScoreBizModel 已用的 parseJson+toDouble 模式）；非阻塞。
- **信心水平**: 高
- **误报排除**: 与 TestNopMetaQualityScoreBizModel 强断言形成对比，证明此模式非必要。
- **复核状态**: 未复核
- **修复归属**: 非阻塞
