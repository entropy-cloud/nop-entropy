## 发现清单

### [P1-MA4-701] P-1 空洞测试：judgeByRuleId 核心逻辑改错后仍通过（16-04 测试质量评估）

- **文件**: `TestNopMetaQualityRuleBizModel.java:297-302`
- **证据片段**:
  ```java
  @Test
  public void testJudgeByRuleId() {
      GraphQLResponseBean resp = graphQLEngine.executeGraphQL(graphQLEngine.newGraphQLContext(req(
              "query { NopMetaQualityRule__judgeByRuleId(ruleId: \"__not_exist__\") { status } }")));
      assertNotNull(resp);
  }
  ```
- **严重程度**: P1
- **现状**: 按 P-1 验证法：把 judgeByRuleId 实现改为 `throw new NopException(...)` 或恒返回 FAIL，`assertNotNull(resp)` 均通过 → 该测试不区分正确/错误实现。
- **风险**: 判定语义（expectPassWhen 比较、结果 DTO 组装）无任何回归保护；且它是唯一只测 judgeByRuleId 的入口。
- **建议**: 重写为行为断言（真实规则→status 语义；非存在 ruleId→hasError + 错误码）；与 MA4.4 P1-MA4-401 合并处理。
- **信心水平**: 高
- **误报排除**: 同文件其它测试均有真实值断言，唯独此方法退化。
- **复核状态**: 未复核
- **修复归属**: MR2

### [P3-MA4-705] P-7 隐患：MockMessageService 使用 static 可变状态，违反模块"mock 实例级状态"约定

- **文件**: `nop-metadata/nop-metadata-service/src/test/java/io/nop/metadata/service/mock/MockMessageService.java:31-37`

## 复核结论

### 16-09 复核（TestNopMetaQualityRuleBizModel Thread.sleep(1100ms)）

**结论：已修复/已不存在（修复到位性确认，非新发现）**。live `rg "Thread.sleep" nop-metadata-service/src/test` 全量扫描零命中（唯一命中为 TestNopMetaTableBizModel:205 注释"不依赖 Thread.sleep：直接验证两次 profile 结果存在且 snapshotTime 严格递增"）。时间敏感路径改用两种无 sleep 方案：TestNopMetaQualityRuleBizModel.testExecuteQualityRuleTimeSeriesAppend（:281-290）用 `CoreMetrics.registerClock` 注入假时钟偏移 +2000ms；TestNopMetaTableBizModel.testProfileTimeSeriesAppend（:206-211）用 snapshotTime 严格递增断言。并发测试仅用有界 `latch.await(15, TimeUnit.SECONDS)`（符合 testing.md 异步规则）。
