## 二、发现清单（按严重程度排序）

### 1. [P2-MA2-01] NopMetaTagLabel 两个 to-one 的 refPropName 指向不存在的反向集合（tagLabels 悬挂）

- **文件/行号**: `nop-metadata/model/nop-metadata.orm.xml:3304-3317`（NopMetaTagLabel.tag / glossaryTerm）；缺失方 `NopMetaTag`（3202-3224）、`NopMetaGlossaryTerm`（3047-3069）
- **证据片段**:
  ```xml
  <to-one displayName="标签" name="tag" refEntityName="...NopMetaTag" refPropName="tagLabels" .../>
  <to-one displayName="业务术语" name="glossaryTerm" refEntityName="...NopMetaGlossaryTerm" refPropName="tagLabels" .../>
  <!-- 反向：NopMetaTag relations 仅有 classification/parentTag/children，无 tagLabels -->
  <!-- 反向：NopMetaGlossaryTerm relations 仅有 glossary/parentTerm/childTerms，无 tagLabels -->
  ```
- **严重程度**: P2
- **现状**: 模型其余 37 个 to-one 的 refPropName 均能在目标实体找到同名反向 to-many（脚本全量校验），仅此两处悬挂。
- **风险**: 生成 xmeta/页面无法从 Tag/GlossaryTerm 导航到标注它的资产集合；ORM 双向同步（set 关系时维护反向集合）失效；运行时若代码依赖 `getTagLabels()` 反向遍历会编译失败或静默返回空。
- **建议**: 在 NopMetaTag 与 NopMetaGlossaryTerm 上各补 `<to-many name="tagLabels" .../>`（cascadeDelete 视语义决定），或删掉 refPropName 改单向。
- **信心水平**: 高（脚本校验 + 人工复核两实体 relations 块）
- **误报排除**: 非自引用误报——自引用场景（baseModules/childTerms/children/childDomains）的 refPropName 均指向真实存在的反向 to-one，本处反向实体是不同实体且确实缺失该集合。
- **修复归属**: MR1/MR2 裁决（model-first 流程，需改 `model/*.orm.xml` + 重新 codegen）

### 2. [P2-MA2-02] NopMetaDataProduct.businessDomain 的 refPropName 指向不存在的 dataProducts 反向集合

- **文件/行号**: `nop-metadata/model/nop-metadata.orm.xml:3499-3506`；缺失方 `NopMetaBusinessDomain`（3403-3418）

- **严重程度**: P2

- **风险**: 同 P2-MA2-01——反向导航缺失 + 双向同步失效；域→产品是治理核心导航路径。

- **信心水平**: 高

- **修复归属**: MR1/MR2 裁决（model-first 流程）

### 3. [P2-MA2-03] SQL 保留字 PRIMARY / CONSTRAINT 仍用作列 code（历史 `2026-07-20-1554#维度04-02`，live 仍 open）

- **文件/行号**: `nop-metadata/model/nop-metadata.orm.xml:747`（`code="PRIMARY"`）、`920`（`code="CONSTRAINT"`）
- **证据片段**:
  ```xml
  <column code="PRIMARY" displayName="主键" domain="boolFlag" name="primaryField" propId="12" .../>
  <column code="CONSTRAINT" displayName="约束名" name="constraintName" precision="100" propId="7" .../>
  ```
- **严重程度**: P2
- **现状**: 未修复。PRIMARY/CONSTRAINT 在 MySQL/PostgreSQL/Oracle 均为保留字；已生成 SQL 中列名未加引号（`_create_nop-metadata.sql` 直出 `PRIMARY TINYINT`），MySQL 下 `PRIMARY` 作为列名在部分上下文会解析失败。
- **风险**: 方言未引号包裹时 DDL/DML 语法错误；跨库迁移隐患。
- **建议**: `code="PRIMARY"`→`IS_PRIMARY`（name 保持 primaryField），`code="CONSTRAINT"`→`CONSTRAINT_NAME`；改后重新 codegen。
- **信心水平**: 高（保留字事实 + 已生成 SQL 佐证）
- **误报排除**: 历史已确认非偏好问题；live 模型两处原样保留，属于"已知未修"。
- **修复归属**: MR1/MR2 裁决（model-first 流程；历史归属 ORM 维护项）

### 4. [P3-MA2-04] 6 个 dict 引用列缺 precision（裸 VARCHAR）

### 6. [P3-MA2-06] NopMetaTagLabel 唯一键不覆盖 glossary 标注去重（tagId 可空 + UK 缺 glossaryTermId）

- **文件/行号**: `nop-metadata/model/nop-metadata.orm.xml:3319-3322`、`3251-3255`
- **证据片段**:
  ```xml
  <column code="TAG_ID" name="tagId" precision="32" .../>            <!-- 可空 -->
  <column code="GLOSSARY_TERM_ID" name="glossaryTermId" precision="32" .../>  <!-- 可空 -->
  ```

- **信心水平**: 中-高（依赖 MySQL NULL 语义，其他 dialect 行为不同）
- **误报排除**: 历史 04-02 修复的是"无唯一约束"，本项是其遗留语义空洞，非重复发现。
- **修复归属**: deferred（P3，ORM 维护项）
