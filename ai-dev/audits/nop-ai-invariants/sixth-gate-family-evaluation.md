## 1. 候选定义

**「探查工具化候选」指什么**：将 I2 人工执行的「兄弟路径探查」与 I4 的「类别清扫」纪律自动化——对某族任一实例被新增或修改时，强制检查该族全部兄弟实例（声明级 + 行为级），而非仅修点名实例。**它不是**「门禁覆盖新实例声明」——后者已由门禁①-④ 的表完备性机制承担（新 Default* 类 / 新编排入口 / 新 ToolExecutor / 新 entry-point 不入表即 red）。

**Scope 决定（登记在案，来源区分）**：

- I2 显式登记的候选 = **兄弟路径探查**（I2 plan Non-Blocking Follow-ups 原文：「若兄弟路径探查发现高频模式，建议在 I6 收口时评估沉淀为第六门禁族（Cycle 2 派生输入）」）。
- 「类别清扫（修一族穷举一族）」是 **I4 执行纪律**（I4 plan Non-Goals / Closure Gates「类别清扫执行（修一族穷举一族），无只修点名实例的情况」），**没有独立的工具化登记**。
- 本评估将两者作为**同一模式**（同族实例联动重审）合并评估——两者共享同一失败前提（「同一族实例修改后兄弟未重审」），区别仅在作用时点（修改前探查 vs 修改时清扫）。该 scope 决定记录于本文档，供 I6 与后续 Cycle 复核。

**候选的边界形态（供检测方法设计，见 §3）**：候选门禁需回答「触碰某族任一实例时，如何机械证明该族全部兄弟实例已被重审」。

### 2.3 证据盘点结论

**结论：非高频**（三态之一，明确无模糊词）。

依据：

1. Cycle 1 实际数据：人工兄弟路径探查/类别清扫的边际产出 = **1 起正证（R-2-3）**，且其根因是 owner-doc drift（排除理由错误），已由「补表 + 排除理由更正 + 门禁②表完备性机械派生」承接——该根因面现已被机械拦截，人工纪律不再必要。
2. I4 类别清扫执行记录 = 零新缺口——门禁落地后清扫纪律的增量发现为零。
3. 历史高频证据（§2.1）全部属于「无门禁时代」；对应面已被五族门禁的全表声明复查 + 表完备性机械覆盖，不作为当前高频判据。
4. 「高频」判据（兄弟路径反复漏网、反复依赖人工纪律）在 Cycle 1 不成立。

## 3. 检测方法候选规格（INV-6 候选，供复触发后 Cycle 2 消费）

> 本规格按 plan Phase 1 要求设计并评估可行性；评估结论（不可机械验证 → 空转风险）见 §3.3。即使裁定 watch-only，规格仍作为 Cycle 2 / I1 的派生输入存档。

### 3.1 INV-6 候选陈述

- **陈述（候选）**：对任一失败族（INV-1~5）中任一实例的修改（fix commit 触碰），必须伴随该族**全部兄弟实例**的重审；重审结果必须可机械观测。
- **覆盖失败族（候选）**：同族兄弟漏网（secure-default 6 兄弟 / timeout 5 兄弟 / 清理 3 兄弟 / Lesson 05 / Lesson 08 的历史复发模式）。
- **预期目标集（候选）**：catalog §3.1~§3.4 四张表（33 / 17 / 30 / 8）。

### 3.2 候选门禁形态（两种备选）

| 形态 | 机制 | 可行性评估 |
|---|---|---|
| (a) commit 面门禁 | 对 `fix(nop-ai)` commit 触碰某族任一实例时（diff 路径 → 族映射），静态扫描要求「该族全表实例重审声明」出现在提交面（提交说明或门禁输出确认） | 误报面：diff 路径 → 族映射需维护；多族触碰 / 非族文件触碰边界模糊；判定标准需机械可验证形式（见 §3.3——不可验证则空转） |
| (b) 审计流程门禁 | 周期复探时将清扫纪律作为固定步骤（复探时对全部族穷举兄弟实例并记录结果） | 成本低（grep 级）；但周期复探本身已是 I6 复触发登记项——该形态实际 = 把已有纪律写进复探流程，不构成独立门禁族 |

### 3.3 Anti-Hollow 维度（必评）

- **声明式重审门禁 = 空转门禁**：「要求重审声明」（提交说明打勾 / 门禁输出确认）无法机械证明重审真实发生——执行者可以机械打勾（Lesson 08「声明 ≠ 接线」同构）。这违反 Anti-Hollow 规则（不可空转的判定标准），不满足「行为式断言或不可空转」要求。
- **行为式断言替代**：「触碰任一实例的 commit 必须包含该族全部实例的回归测试运行证据」——但门禁①-④ 每次 CI 已对全表实例机械复查（声明级），该断言在声明级为空（已由现有门禁承担）；行为级（接线/语义）复核需要人工/AI 判断，不存在可自动判定的行为式断言。
- **结论**：机械可验证的重审面（声明级全表复查）已被门禁①-④ 承担；不可机械验证的重审面（行为级）无法做成非空转门禁。**不存在满足机械可验证性的第六族门禁形态**——这正是 §4 watch-only 裁定的核心依据。

## 4. 裁定与落盘

> 本段由评估 plan Phase 2 写入（2026-08-12）。

### 4.1 裁定

**`watch-only residual`**（不沉淀 INV-6，不派生 Cycle 2 实现计划）。

### 4.2 Why Not Blocking Closure

1. **证据盘点结论 = 非高频**（§2.3）：Cycle 1 正证 1 起（R-2-3），根因 owner-doc drift 已修复并被门禁②表完备性机械承接；I4 清扫零新缺口。
2. **成本 > 收益**：候选的机械可验证核心（全表声明级复查 + 表完备性）已由门禁①-④ 每次 CI 承担；唯一新增面 = 行为级联动重审，**不可机械验证**（§3.3 Anti-Hollow 维度否决）——沉淀第六族门禁只能得到空转声明门禁，徒增维护成本（族→实例映射表维护、commit 面扫描基建、误报面）且违背 Lesson 08 教训。
3. 不阻塞稳态判定：本裁定结果 = 「零新族」，是 I6 稳态判定的合法分支（「零新族且零red → 稳态暂停 待复触发」），无 in-scope 遗留。

### 4.3 复触发条件（可判定，无模糊时间词）

1. **周期复探锚点**：周期复探执行时（周期由 I6 裁定登记），若发现 **≥2 起**同族兄弟漏网实例（声明级或行为级，即门禁全绿但兄弟实例存在未重审缺口）→ 复核 tool-ize。
2. **事件锚点**：出现**第 1 起**「同族实例被修改后，其兄弟实例发生行为级回归且五族门禁全绿」（= 门禁机械面盲区的实际击穿）→ 复核 tool-ize。
3. **结构性锚点**：Cycle 2 派生新不变式族（任何原因）且**首轮审计发现 ≥2 起兄弟漏网**→ 将清扫纪律 tool-ize 并入新族门禁设计（防同族兄弟漏网在新族上复发）。

复触发条件已由评估 plan Follow-up 显式交 I6 循环收口登记（catalog §6 复触发条件登记段），候选复核机制不在 I6 关闭后断裂。

## 5. 与现有门禁边界核对

| 现有门禁 | 拦截语义 | 与 INV-6 候选的关系 |
|---|---|---|
| 门禁①-④ | 表完备性（新实例不入表即 red）+ 全表声明级复查（每次 CI） | **声明级无 overlap**——候选的声明级重审 = 现有门禁已执行的机械动作；候选仅新增「行为级联动重审」面（现有门禁明示不验证行为语义，I1 裁定） |
| 门禁⑤ | fix-commit 实质 diff > 0（防虚假关闭） | **语义不同、基建可共享**：候选若走 commit 面形态 (a)，可与门禁⑤共享 commit 扫描基建（subject-only 过滤已落地）；但拦截语义不同（实质 diff vs 联动重审）。若候选走审计流程形态 (b)，与门禁⑤零 overlap |

**边界核对结论**：INV-6 候选与门禁①-④ 无 overlap（声明级已被覆盖，行为级是现有门禁的有意盲区）；与门禁⑤ 语义可区分（无重复拦截）；唯一的新增面（行为级联动重审）不可机械验证（§3.3）——故不构成独立门禁族的落地面。
