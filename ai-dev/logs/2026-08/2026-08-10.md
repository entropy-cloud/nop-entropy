### 2026-08-10（FIX：DataBaseSchemaInitializer ioc:force-init 修复 ALL_LAZY 测试模式 schema 不创建回归）

- **根因**：commit `7e06450ff`（08-07，`feat(ioc): ioc:before/after/depends-on 统一为 resolvedDepends`）移除了 `BeanContainerImpl` 中 `ioc:after` → `addNextBean` 的 pull-in 机制。此前 `DataBaseSchemaInitializer`（`ioc:after="nopOrmSessionFactory"`）在 sessionFactory 创建时被 pull-in 创建；重构后在 `ALL_LAZY` 启动模式下（单元测试缺省），`DataBaseSchemaInitializer` 既无 `ioc:delay-method` 也无 `ioc:force-init`，不在 `startContainer` 的 eager-creation 路径中（`BeanContainerImpl.java:450-454` 仅创建 `hasDelayMethod && !lazyInit` 或 `isIocForceInit` 的 bean），故 `@PostConstruct init()` 从不执行 → H2 测试库 schema 不创建 → `NOP_SYS_SEQUENCE` 表不存在 → `SysSequenceGenerator.lazyInit` NPE。
- **影响面**：所有 `extends JunitBaseTestCase` + `@NopTestConfig(localDb=true, initDatabaseSchema=TRUE)` 的测试（nop-app-erp: `TestErpMdCurrencyRefreshRatesDate` + `TestErpFinVoucherTemplateActiveByDate` 等）。`JunitAutoTestCase` 子类不受影响（经 `AutoTestCaseDataBaseInitializer` 在 `initDao()` 中创建 schema）。
- **修复**：`orm-defaults.beans.xml` `DataBaseSchemaInitializer` bean 增 `ioc:force-init="true"`，使其在 `ALL_LAZY` 模式下强制 eager 创建 → `init()` 执行 → schema DDL 正常生成。一行属性增补，恢复 `7e06450ff` 前行为。
- **验证**：`mvn install -pl nop-persistence/nop-orm -am -DskipTests` → BUILD SUCCESS；nop-app-erp `mvn test` 全 156 模块 BUILD SUCCESS（0 failures / 0 errors）。
