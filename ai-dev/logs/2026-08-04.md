### flux-control.xlib / control.xlib view-file 模板空指针修复

- 现象：`nop.web.render-mode=flux` 下，含 `stdDomain="file"` 字段的实体页（ErpB2bEdiDoc / ErpCtContract / ErpCtDocument 等）在 flux 前端运行时报 `Template evaluation failed for: ${xxxComponentFileStatus.name}(${xxxComponentFileStatus.fileSize})`。根因：`xxxComponentFileStatus`（FileStatusBean 关联字段）在行数据中为 null（未加载附件时），flux 表达式求值器对 null 成员访问抛异常（`Cannot access member of null or undefined`），AMIS 运行时静默返回 undefined。
- 根因：`flux-control.xlib:view-file` 与 `control.xlib:edit-file` 的 `label` 模板使用非空安全的 `.` 成员访问（`${nameComponentFileStatus.name}`），未考虑 `ComponentFileStatus` 为 null 的场景。`visible` 条件仅检查 `name != null`（文件 ID），但 `ComponentFileStatus` 是独立的关联字段，可能异步未加载。
- 修复：`nop-frontend-support/nop-web/src/main/resources/_vfs/nop/web/xlib/flux-control.xlib` + `control.xlib`（两者同步）：
  - `label` 模板 `ComponentFileStatus.name` → `ComponentFileStatus?.name`（optional chaining，flux 求值器 `node.optional` 分支返回 undefined 不抛异常）
  - `label` 模板 `ComponentFileStatus.fileSize` → `ComponentFileStatus?.fileSize`
  - `source` 模板 `ComponentFileStatusList` → `ComponentFileStatusList || []`（null 合并为空数组）
- 验证：下游 `nop-app-erp` CRUD E2E（flux 模式）b2b/contract 域 smoke 恢复（待重建后确认）。
