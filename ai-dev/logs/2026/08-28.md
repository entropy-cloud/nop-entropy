### 2026-08-28（IndexHtmlProvider 注入 data-nop-extension 锚点属性 + 部署目录对齐）

- **目标 A**：让 `IndexHtmlProvider.appendExtensionHtml()` 在生成 `<link>` 与 `<script>` 时携带 `data-nop-extension` 与 `data-nop-extension-id` 属性，使 nop-chaos-next host 的 `apps/main/src/extensions/config.ts` `getDomExtensionSources()` 能在生产部署中识别 Java 端注入的扩展。
- **目标 B**：将部署目录 `extension/{name}/`（单数 `extension`，VFS 路径）改为 `extensions/{name}/`（复数 `extensions`，与 URL base path `/extensions` 对齐），让 Spring/Quarkus 默认 `classpath:/META-INF/resources/**` 静态映射无需额外配置即可命中资源。
- **修改文件**：
  - `nop-frontend-support/nop-web/src/main/java/io/nop/web/page/IndexHtmlProvider.java` — `appendExtensionHtml()` 中 `<link>` 与 `<script>` 现在分别带 `data-nop-extension` 与 `data-nop-extension-id="<id>"` 属性。
  - `nop-frontend-support/nop-web/src/main/java/io/nop/web/WebConfigs.java` — `CFG_WEB_INDEX_EXTENSIONS_DIR` 默认值从 `null` 改为 `extensions`（复数），与 `CFG_WEB_INDEX_EXTENSIONS_BASE_PATH` 默认 `/extensions` 对齐。
  - `nop-frontend-support/nop-web/src/test/java/io/nop/web/page/TestIndexHtmlProvider.java` — `testGenerateHtml()` 更新断言以匹配新输出。
  - `docs-for-ai/02-core-guides/index-html-extensions.md` — 部署结构改为 `extensions/{id}/`，新增路径相对基点表。
- **验证**：
  - `./mvnw test -pl nop-frontend-support/nop-web -Dtest=TestIndexHtmlProvider` — 6/6 通过。
  - `./mvnw test -pl nop-frontend-support/nop-web` — 86/86 通过。
- **路径契约闭环**：
  - `extension.json` 内路径（`entry` / `styleAssets` / `assets`）相对 `extension.json` 自身，如 `./assets/index.js`
  - Java 端拼接 URL 时去除 `./` 前缀：`/extensions/{id}/<stripDotSlash(entry)>`
  - 部署到 `META-INF/resources/extensions/{id}/`（复数）
  - Spring/Quarkus 默认静态映射 `classpath:/META-INF/resources/**` → `/`，HTTP `/extensions/{id}/assets/...` 自动路由到 `META-INF/resources/extensions/{id}/assets/...`
