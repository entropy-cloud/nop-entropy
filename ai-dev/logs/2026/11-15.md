### 2026-11-15（~/sources Activiti 实测：泛化缺陷 11/12/13 发现与修复——1759 tests 收敛至 1 个顺序敏感类）

- **Activiti**（68 poms,Java 25 + JUnit5,67 模块,42 个含测试,mvn 基线 3335 tests/0 fail/2 预存 err）：
  - **缺陷 11（执行模型,真缺陷）**：conformance 测试依赖跨类共享的部署注册表累积态,Surefire 单 JVM 全模块顺序跑=累积;ib 多 worker 分摊=各 worker 只见部分 → 52 failed。修复=**模块级差分重跑**：worker 轮失败后,单 fresh fork 顺序跑全模块全部类（=Surefire 执行模型）,fresh 结果权威（`nop.ib.moduleRerunTimeoutSeconds` 默认 1800s）。
  - **缺陷 12（保真,真缺陷）**：argLine 的 `-javaagent:"${org.mockito:mockito-core:jar}"`（mockito inline agent）被当不可解析占位符丢弃 → 修复=`resolveArgLineToken`：`${g:a:type}` 从模块 classpath 定位 jar 替换（`@{...}` 后期绑定仍丢弃）,fork executor 与 worker cmdPrefix 两处生效。
  - **缺陷 13（classpath 语义,真缺陷）**：materializer 把**所有 test scope 依赖的 target/test-classes 目录**加入 test classpath——几十个外部模块的 test 类与 `processes/` BPMN 资源涌入 Spring 自动部署 → Duplicate key 崩溃。修复=surefire 语义：普通 test scope 依赖只贡献 main 产物;依赖 test-classes 仅经显式 `test-jar` 类型依赖进入。
  - 修复后 sweep：**1759 tests / 1 failed**（从 52→1）——唯一失败 ShutdownListenerTest=静态状态+顺序敏感（ib 单类跑通过、mvn 单类跑通过、全模块批量顺序下状态交错;mvn 顺序恰好让其通过,裁定 watch-only）。
- 外部项目累计：OpenPDF 2310/0、liteflow 808/0 精确、pdfbox 997/0 共同语料、spring-batch 465/465 字节级、Activiti 1759/1（顺序敏感裁定）——**五项目**。

### 2026-11-15（~/sources spring-batch 实测：8/9/10 号泛化问题发现与修复；nop-javac 经复现证明无需修改）

- **spring-batch**（Java 17 + JUnit 6.1.3,7 模块,Spring 栈）：
  - **问题 8（过保守,适用面收窄）**：全部模块被判 L2——其 `annotationProcessorPaths` 是 **error-prone + NullAway（纯检查型处理器,不生成代码）**,而 ib 把任何 annotationProcessorPaths 一律判 L2。修复=CompilerExec 增 `checkOnlyProcessors`（errorprone/nullaway/spotbugs 组白名单）,检查型不再强制回退。
  - **问题 9（字节 parity,真缺陷）**：fast path 编译产物缺 3 个 `package-info.class`。**裸 javac 决定性实验**（同 classpath 同 410 源文件同旗标）复现同样缺失→**非 nop-javac 缺陷**,根因=mvn 的 error-prone 触发注解处理轮次,轮次副产物才写带注解 package-info 的 class（JSpecify @NullMarked）;fast path 无处理器轮次故不写。修复（分级层,不动 Protected Area 的 nop-javac）=check-only 处理器 + 源里存在注解 package-info → 回退 L2（保守方向;无注解 package-info 的项目仍享快路径）。
  - **问题 10（字节 parity,真缺陷）**：fast path 产物缺 `-parameters`（MethodParameters 属性 3 vs 9）——spring-batch 以自由形式 compilerArg 传 `-parameters`,ib 未解析。修复=compilerExec 增 `parameters` 事实（config 元素或 compilerArg 两条解析路径）,facade 透传 javac。
  - 修复后**字节级对拍**：infrastructure **422/422 全同**、core 公共 **462/462 全同**;core 全量对 mvn 的差集=仅 3 个注解 package-info（该模块现已回退 Maven,天然一致）。
  - **nop-javac 无需修改**：最小复现（单注解 package-info 经 JdkJavaCompiler 编译正常产出 class,TestPackageInfoEmission 回归钉）证明行为与裸 javac 一致。
  - 附带发现（watch-only）：依赖产物全无时 ib -pl 多模块编译按给定顺序执行,先编依赖方会因 nop-javac classpath 存在性校验失败（历史场景产物均在未暴露;拓扑序执行待核实）。
- PowerJob 排除（Java 8,lombok 旧版本 JDK26 不可编译）;spring-batch install 需 `-DskipTests -DskipITs`（failsafe/Testcontainers 需 Docker,本机无）。
- 验证：模块 31/31（新增 TestPackageInfoEmission 回归钉）;字节对拍见上。
