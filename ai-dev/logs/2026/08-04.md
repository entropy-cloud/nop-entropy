### nop-job vs PowerJob vs snail-job 三方深度对比分析

- **背景**：用户要求对 nop-job 与 PowerJob（v5.1.2，`C:\can\sources\PowerJob`）、snail-job（v2.0.2，`C:\can\sources\snail-job`）做深度对比，覆盖功能/性能/架构/核心逻辑/配置/未来可扩展性，客观中立。
- **方法**：3 个 explore subagent 并行逐文件审查三套源码（nop-job 全模块+4 份设计文档、PowerJob 全模块、snail-job 全模块），提取代码证据（文件路径+行号），再综合。
- **产出**：`ai-dev/analysis/2026-08/2026-08-04-nop-job-vs-powerjob-vs-snail-job-deep-analysis.md`。
- **关键结论**：三者代表三种哲学——nop-job（DB-as-bus 最简内核，集群协调模型最优雅：确定性分区+乐观锁+无选主，但调度延迟最高~15s+、功能面最窄）；PowerJob（重型 Actor 计算平台，1ms 时间轮+MapReduce+DAG 最成熟，但 Akka/Spring Boot 2.7 是战略负债）；snail-job（gRPC 解耦重试优先平台，多语言+国产化最前瞻，但 v2.0 实为 server-push 非 client-pull，HTTP-over-gRPC 路由层是审美争议）。
- **重要修正**：早期分析（`2026-05-17-snail-job-vs-nop-job-comparison.md`）基于"snail-job 是 client-pull"的认知，源码审查证实 v2.0 是 server-push（gRPC + Pekko actor 管线），"pull"指 server 从 DB 拉取行而非客户端拉取作业。
- **最深刻洞察**：nop-job 论证的"确定性分区函数 + 幂等乐观锁 = 无需选主"是三者中最优越的分布式协调设计，值得所有调度系统借鉴；PowerJob/snail-job 仍依赖锁/选举。
- Doc-sync: No owner-doc update required（纯分析，无代码/约定变更）。
