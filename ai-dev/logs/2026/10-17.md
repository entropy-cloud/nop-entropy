# 2026-10-17

### flux 页面按钮丢失修复 + 三个新平台缺陷（icon/上传/弹窗选择）+ 静态检查器 + nop-auth e2e 实测

用户报告：功能演示的下载按钮、validate 页面按钮在 flux 下消失；询问是否有统一页面 yaml 检查工具；要求 nop-auth 的图片上传/icon 选择/弹窗选择/下拉选择在 e2e 覆盖。四路并行调研后逐项落地，并按用户要求**实跑 e2e 确认**。实跑又暴露 3 个此前未知的平台缺陷（icon 标准域、文件上传、picker 弹层），均已定位。

**① 两个按钮丢失根因（用户报告的直因，浏览器实测已修复）**
- **报表演示下载按钮**：flux `page` 渲染器**没有 `toolbar` region**（`flux-renderers-basic/page.tsx` 只读 `header` 槽位并渲染进 `data-slot="page-toolbar"`），`demo.flux.yaml` 沿用 amis 页面级 `toolbar:` → 编译但从不渲染。修复：`toolbar:` → `header:`；`actionType: download` 的 `ajax`+blob → flux 原生 `download` 动作（`{ api: { url, method, responseType:'blob' } }`）。
- **validate 页面按钮**：flux **没有 `button-toolbar` 渲染器**，`test-validator.flux.yaml` 的 `type: button-toolbar` 使 6 个按钮全灭。修复：改 `flex` + `button`。
- **浏览器实测（nop-quarkus-demo 8083，chromium）**：报表演示页 `下载报表模型`/`导出Excel`/`更新显示` 各命中 1；validate 页 6 个按钮全部命中。用户报告的两处已确认修复。

**② 静态检查器 `ai-dev/tools/check-flux-pages.mjs`（用户追问"没有统一 validate 工具吗"）**
- 调研：本仓**无**统一页面 yaml 格式校验器；服务端仅 `PageProvider.validateAllPages()`（"能否加载不抛错"冒烟，不检测 flux 渲染器缺失、不扫 `_dump`）。nop-chaos-next **只有 JS/TS 仓库治理工具**，无页面/flux 校验器，且其脚本本仓从未调用（仅 3 个 e2e config 启动其 vite dev server）。flux 权威诊断是 nop-chaos-flux `schema-compiler`（仅构建期，本仓未接入）。
- 新增高置信度 denylist 检查器：扫 `*.flux.yaml`（可选 `_dump`），报 AMIS-only 类型/键（`button-toolbar`/`service`/`static`/…、`actionType`/`visibleOn`/`validations`/`asideResizor`/`initApi`/…）与页面级 `toolbar`。error 非 0 退出。npm script `check:flux-pages`；文档 `ai-dev/tools/README.md`。

**③ 检查器立即可捕获的第三个缺陷**：`change-self-pass.flux.yaml` 用了 AMIS 字段级 `validations.equalsField` → flux 下重复密码校验静默失效。改表单级 `rules` + 新增 i18n key `common.passwordNotMatch`（amis 版保持不变）。

**④ 实跑 e2e 暴露的三个新平台缺陷**
- **icon 标准域未注册（已修，本仓）**：`NopAuthResource.icon` 的 `<schema stdDomain="icon"/>` 用于驱动 `edit-icon`/`view-icon` 控件，但 `icon` 标准域**从未注册**，任何带 icon 的保存被 `SimpleSchemaValidator` 以 `nop.err.xlang.xdef.unknown-std-domain` 拒绝——**图标"能选不能存"**（curl 实测 `NopAuthResource__update {icon}` 先报 unknown-std-domain，修复后 `icon=settings` 持久化）。新增 `IconStdDomainHandler`（nop-ui）+ 在 `XuiCoreInitializer` 注册；回归测试 `TestIconStdDomain`（去掉修复即红）。
- **flux 文件上传未落地（跨仓缺口，登记）**：flux 的 `input-file/input-image` 只认字段级 `uploadAction`（`flux-renderers-form-advanced/upload-field.tsx`，无 `receiver` 支持），而生成器 `flux-control.xlib` 的 `edit-file/edit-file-list` 仍输出 AMIS 的 `receiver: /f/upload?...`，且宿主无上传动作 → 上传请求根本不发出，表单只提交空文件引用。需 nop-chaos-next 提供上传动作 + 生成器改输出 `uploadAction`。e2e 用例 `.fixme` 并注明。
- **picker 弹层在 flux 下不可用（缺口，登记）**：生成的 picker（edit-relation）弹层数据列渲染为空（只显示序号列），点选行后 `[data-slot="picker-confirm"]` 仍 disabled（选区未登记到 `$_picker.selection`）→ 无法完成"弹窗选择"。e2e 用例 `.fixme` 并注明。

**⑤ nop-auth e2e：图片上传 / icon 选择 / 弹窗选择 / 下拉选择**
- 扩展 `e2e-shared`：`EngineAdapter` 增 `setFieldFiles`/`selectIcon`/`selectPickerRow`；`FluxAdapter` 按渲染器 `data-slot` 契约实现（upload 隐藏 `input[type=file]`；icon-picker `[data-slot="icon-picker-trigger"]`+`[role="option"][aria-label]`；picker `picker-trigger`/`picker-dialog-content`/`picker-confirm`）；`FormDialog`/`CrudListPage` 增透传（含 `switchDialogTab` 处理 `layoutControl="tabs"` 隐藏字段）。
- PO/spec：`UserPO.uploadAvatar`/`selectPosition`、`ResourcePO.selectResourceIcon`；fixture `avatar.png`；新增 4 条用例。
- **实测结果（`pnpm test:auth`，后端 8080 flux + H2）**：**40 passed / 2 skipped / 0 failed**。`icon 选择`、`下拉选择并回读` 通过（其中 icon 用例先暴露并驱动了 ④ 的标准域修复）；`上传头像`、`弹窗选择职务` 因 ④ 的两个跨仓缺口 `.fixme`（含确凿根因），待后端/生成器修复后去掉 `.fixme` 即启用。
- 实测还发现既有模式约束：页面登录会换发 token，request 上下文须在页面登录后 `loginRpc` 重新登录再调 RPC（已在用例中处理）。
