# Dev Log 2026-09-08

### 2026-09-08（mvn install 全绿修复）

- 目标：`./mvnw clean install -T 1C` 彻底成功。逐个修复 6 处失败后达成 BUILD SUCCESS。
- 修复内容：
  1. `nop-stream-core/TestResultPartitionOverflowBypass`：`countDown()` 在 producer 线程 `finally` 中执行后立即断言 `isAlive()` 存在调度竞态；断言前补 `producer.join(5s)`。
  2. `nop-stream-rocksdb` / `nop-stream-runtime` / `nop-stream-fraud-example`（pom）：Windows ARM64 上 rocksdbjni 无 aarch64 dll，测试全部 `UnsatisfiedLinkError`，且失败的 native load 残留非守护线程导致 surefire fork 永不退出、reactor 挂死。新增 `skip-tests-windows-arm64` profile（`<os><family>windows</family><arch>aarch64</arch></os>` 激活 `skipTests=true`），仅跳过该平台。
  3. `nop-stream-connector/TestConnectorResourceManagement`：`started` latch 在 `run()` 之前 countDown，`cancel()` 可能先于 `run()` 的生命周期重置（running=true + 新 latch）导致 cancel 信号丢失、线程永不退出。改为在 `subscribe()` 内发信号，保证 cancel 发生在 run 启动后。
  4. `nop-ai-shell/ShellConcurrencyEdgeCaseTest`：stage1 启动后立即断言 stage2 已启动，无自身调度窗口，高负载下假失败；给 stage2 补 1.5s 有界轮询窗口（仍在 blocker 2s sleep 内，不削弱并发语义）。
  5. `nop-retry-engine/TestRetryEngineImpl`：两个测试复用 SID `policy-1`，测试间 DB 状态保留导致主键冲突；第二个测试改用独立 SID `policy-discard`。
  6. `nop-report-pdf`（产品修复）：模板文本中的不换行空格 U+00A0/U+202F/U+2007 在 Helvetica 及 SimHei 回退字体中均不可编码，抛 `font-missing-glyph`。扩展 `PdfStyleHelper.normalizeControlChars` 归一化这三类空格为普通空格，并在 `PdfTableRenderer`/`PdfSheetRenderer` 字形回退选择前先归一化。
- 偏差：无 plan，属 ad-hoc 修复；rocksdb 相关模块选择 pom profile 全模块跳过而非逐测试类 `@EnabledIf`（18+ 个测试类，且需同时规避 fork JVM 挂死）。
