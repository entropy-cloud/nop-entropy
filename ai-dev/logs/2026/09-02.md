### XScript `delete` 表达式接通（plan 2259）

- 启动 plan `ai-dev/plans/2259-xscript-delete-expression.md`，status 由 draft → active → completed。
- 关键决策（用户 2026-09-02 裁定）：
  1. **Bean 路径语义统一为 `set null`**：Map 走 `remove`（删除条目），Bean 一律 `set null`（清空值，不删 key）；List 走 `List.remove(int)` / `List.remove(Object)`。**不修改 `nop-core` 的 `IBeanModel` / `BeanTool` 接口**——`setExtProperty(null)` 已存在满足扩展属性清空语义。
  2. **裸标识符错误码可达**：grammar 改用 `Delete expression_single`（不是 `Delete memberExpression`），由语义层校验 argument 必须是 `MemberExpression` → `ERR_XLANG_DELETE_NOT_MEMBER_EXPR` 可达。
  3. **`delete obj?.x` 不支持**：JS 自身不支持 `delete obj?.x`，与现有 `memberExpression` rule 不接受 `?.` 一致，无须扩 grammar。

- Phase 1 落地：
  - g4 `XLangParser.g4:542` 解除注释，标签从 `memberExpression` 改为 `argument=expression_single`（带 `argument=` 标签是关键，否则 codegen 不识别 argument 字段，`visitDeleteStatement` 会直接返回 expression_single 而不包装 DeleteStatement）
  - ANTLR codegen 重生成（DeleteStatementContext / visitDeleteStatement 自动生成）
  - `XLangASTBuilder.delete(loc, MemberExpression)` 工厂
  - `TypeInferenceProcessor.processDeleteStatement` 保持原状（仅返回 BOOLEAN_TYPE）——**实际发现**：原计划三条编译期校验放在 `TypeInferenceProcessor` 不可达，因为 `nop.xlang.type-inference.enabled` 默认 false。**最终将三条编译期校验放在 `BuildExecutableProcessor.processDeleteStatement`**。
  - `XLangErrors` 新增 7 个错误码常量

- Phase 2 落地：
  - `XLangSemantics.deleteProperty`：null → Map → IMapLike（含 DynamicObject.toMap() unmodifiableMap fallback 到 prop_remove 真删除）→ 普通 Bean 路径（用户 2026-09-02 反馈：DynamicObject 有 removeProp 方法，应该走真删除而不是 set null）
  - **2026-09-02 增量修正**：`DynamicObject.prop_remove(String)` 已覆盖 `IPropSetMissingHook.prop_remove` 的 default 实现，改为调用 `removeProp` 真删除条目（与 Map-like 语义对齐）。同步 `XLangSemantics.deleteProperty` 的 fallback 路径从 `prop_set(null)` 改为 `prop_remove(name)`。新加测试 `delete.test.md #14 delete DynamicObject 属性 - 真删除条目` 验证 `'foo' in u` 在 delete 后为 false。
  - `XLangSemantics.deleteAttr`：null → attr 为 null 分派 → attr 为 Integer 时 List 走 `remove(int)`（边界校验返回 false 而非抛 IOOBE）；Map 走 `remove(Object)`；Bean 走 deleteProperty
  - `XLangSemantics.deleteScopeValue`：记录旧值 → removeLocalValue → 返回旧值非 null 的 boolean
  - `DeletePropertyExecutable`、`DeleteAttrExecutable`、`DeleteScopeVarExecutable` 三个 Executable 类
  - `BuildExecutableProcessor.processDeleteStatement` 三路分派（$scope / non-computed / computed）

- **关键发现**（实施中暴露）：
  - codegen 模板对 `expression_single` 不带 label 的语法节点会简化包装 → 必须写成 `Delete argument=expression_single`
  - `nop.xlang.type-inference.enabled` 默认 false → TypeInferenceProcessor 三条编译期校验不会触发 → 校验实际放在 BuildExecutableProcessor
