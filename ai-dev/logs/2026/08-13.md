### docs-for-ai：BIGINT 主键/外键强制 `stdDataType="string"`（JS long 精度）

AND expire_at>?`（SQL 原子递增，对齐 Redis INCRBY 方案 A），读回用 `findInt`（原始 SQL 绕过 ORM 会话缓存避免脏值）。TTL 清理惰性（peek/consume 过期即删）。`TestDbMfaChallengeStore` 8/8 绿（含**并发断言**：20 线程 incrFailCount 最终值=20 无丢失）；`TestDbSmsCodeStore` 9/9 绿（三态/消费/失败计数/maxAttempts 作废/重发/TTL/explicit consume）。无静默跳过。
- **Phase 3 — MfaStoreProvider collect-beans 装配 + 默认 db + 条件式 Redis 注册**：
  - `MfaStoreProvider` 改为 collect-beans name-prefix 声明式装配（`nopMfaChallengeStore_`/`nopSmsCodeStore_`，`as-map`），按 store-type 选择；默认 `STORE_TYPE_DB`；fail-closed（请求类型未注册显式抛异常）。零 `INosqlService` 类型引用（W4 不变式保持）。
  - **关键发现**：collect-beans 必须加 **`ioc:ignore-depends="true"`**——缺此属性时 mfaStoreProvider 经 store bean（→ daoProvider/jdbcTemplate）形成硬依赖链，与 `nopBizObjectManager` 的 @BizModel 收集（`by-annotation`，也用 ignore-depends）产生初始化顺序冲突，导致 `biz_NopAuthUser` proxy 在 runLazyProperties 阶段以空 bizModelBeans 构建（`convert-to-type-fail` for `INopAuthUserBiz`，影响所有加载 app-test.beans.xml 的测试）。加上 ignore-depends 后解除环依赖，全绿。平台 collect-beans 标准模式均带 ignore-depends（biz-defaults/nopBizObjectManager、channelBindService）。
  - store bean `autowire-candidate="false"` + `lazy-init="true"` 隔离不污染类型注入（避免与 `mfaChallengeStore` 工厂产物在 nopLoginService @Inject 处冲突）。
  - Redis bean 经 `ioc:condition`（`if-property store-type=redis` + `on-class INosqlService`）条件激活——classpath 无 nosql 时根本不注册、不被收集、类不加载（ai-dev/lessons/15 类加载安全回归守门）。store-type=redis 但无 Redis store 注册时 provider 显式 fail-closed（不静默回退）。
  - `TestMfaStoreProvider` 7/7（默认 db/local/db/redis 选择 + fail-closed 三态）；`TestMfaStoreWiringDb` 3/3（IoC 接线：store-type=db 返回 DbMfaChallengeStore 实例断言 + Redis bean 在 store-type≠redis 时不被收集 = 类加载安全回归守门）。
