### WI18 收口构建挂死根因修复：无界 Docker 探测（8 个测试类同族缺陷）

- WI18 全量恢复遍(`install -T 1C -rf :nop-stream-connector-kafka`)挂死：200 模块完成 197，Maven 0% CPU 5.5 小时。`jstack` 定位根因——`~/.docker/run/docker.sock` 为 Docker Desktop 半挂死遗留的陈旧 socket(连接建立不响应)，而多个测试类把**无界** Docker 探测放在类初始化器/assumeTrue 前置，socket 半挂死时永久阻塞。独立佐证：`docker version` CLI 自身同样挂死。
- 两种缺陷变体：A) `DockerClientFactory.isDockerAvailable()` 无读超时，`catch (Throwable)` 挡不住无异常的无限阻塞——kafka/pulsar E2E、stream-runtime ×2、debezium ×4 共 8 处逐字相同的 `detectDocker()`；B) `BashSandboxTest.isDockerAvailable/isImageAvailable` drain-before-wait——先排空子进程管道后 `waitFor(10s)`，子进程不退出则 read 永久阻塞在超时之前。
- 修复：变体 A 统一有界探测(守护线程 + `Future.get(15s)` + `shutdownNow()` 中断打断 NIO 阻塞读)；变体 B 改 wait-first-then-drain(先 `waitFor(10s)` 超时即 `destroyForcibly` 返回不可用，后排空)。修复后走既有 `assumeTrue` 门，可见 SKIP 语义不变。详见 `ai-dev/bugs/2026-10/2026-10-20-testcontainers-detect-docker-blocking-clinit.md`。
- 验证：6 模块串行 solo(`ai-toolkit/job-local/message-kafka/message-pulsar/stream-runtime/connector-debezium`)BUILD SUCCESS——70+73+98+1212+302+50 全绿，skip 全为 Docker 门控 E2E 设计内跳过；并行构建中的 `ToolManagerImplParallelTest` 停摆证实为连带症状(单跑 1.15s 5/5 绿)。WI18 收口构建证据补录 plan 2487 Closure。
- 评估后不新增确定性回归测试：超时路径需模拟"接受连接不响应"的 socket/子进程，testcontainers 静态门面 mock 成本过高；保护即探测本身的有界性，回归症状(构建挂死)可由任意全量构建暴露。
