## GLR 恢复停滞修复落地——契约恢复："语法错误不抛异常"对一切输入成立

重新梳理后放弃在恢复 extent 的表示层语义上继续纠缠（那是 Decision 3/4 两次被实测否决的路线），
改走一条**不需要回答表示层问题**的路：**停滞回退**。

核心洞察：`recoverFromError` 在 1226 行本来就有 EOF 收尾分支（C 的 "still in the error state
at the end of the file → wrap everything in an ERROR node and terminate" 的移植）。停滞的
version 之所以永远完不成，只是因为它**到不了 EOF**。于是 backstop 触发时不再抛异常，而是把
**剩余未消费输入整体包进一个 ERROR 节点**推到 EOF，交给既有路径 wrap + accept。

选择这个方案的理由（与被否决的两个对照）：
- **正是 plan 的目标**："this plan is about not aborting"，shape 是明确 Non-Goal；
- **不可能回归任何现状为绿的东西**——唯一被改的行为是原本就 throw 的路径；
- **C 在该状态下无行为可对照**（其恢复从不停滞），唯一权威是本模块自身契约。

实测：五个复现输入全部返回含 ERROR/MISSING 的树，无一抛异常——
- `echo ${x! y}` / `echo ${x!yy`（fix1 已收敛，不触及 backstop）：**与 C oracle 逐字节一致**；
- `echo ${x!y}` / `echo ${x!y}z` / `echo ${x!yy}`（走停滞回退）：best-effort 树，断裂点标
  `(UNEXPECTED '!')` 而 C 是 `(word)`——按 Non-Goal 记录为接受的形状偏差。

**629 tests / 0 failures / 2 skipped**：bash corpus 100/100、九语法 corpus 不变、java/json
的 C 核实 golden 不变。`scan-hollow high` 0；`-Pqa verify` 0；doc-links 0 errors。

  ——`splitProven` 返回 `Unproven[SYNTAX_ERROR]`、`summarize` 报 `NOT_PROVEN` 且无 proven 命令。
  guardrail 对不可解析输入退化为"拒绝"而非崩溃，这正是该层契约想要的。
