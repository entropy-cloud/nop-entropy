### 2026-09-09（flaky test fix: manifestRowsStayBoundedAndRestoreStillRebuildsRefCount）

- Fix: `TestCheckpointCoordinatorJdbcRetainedManifests.manifestRowsStayBoundedAndRestoreStillRebuildsRefCount` CI flaky failure
- Root cause: async retention cleanup chain (`scheduleRetentionCleanup` CAS coalescing) may not fully converge before `cc.shutdown()` terminates the retention executor. The checkpoint plane requires multiple `deleteCheckpoint` calls in a loop; if the chain is interrupted by shutdown, convergence is not guaranteed. Manifest plane converges because `pruneEpochManifests` is atomic in one SQL call.
- Fix: Added synchronous `cleanupOldCheckpoints()` call in `CheckpointCoordinator.shutdown()` before terminating executors, guaranteeing at least one final cleanup pass.
- Changed: `CheckpointCoordinator.java:1540-1549` (added ~10 lines in `shutdown()`)

### 2026-09-09（flaky test fix: TestRetryEngineImpl stale-callback race）

- Fix: `TestRetryEngineImpl` flaky failures from stale `scheduleImmediateRetry` callbacks leaking across tests
- Root cause: `scheduleImmediateRetry` captures `this` in a lambda; when the stale callback fires during a subsequent test, `getExecutor()` returns the **new** test's executor (because `this.executor` field was replaced), causing retry leakage. Additionally, the stale callback's synchronous `doExecute` call consumes mock responses from the shared singleton queue.
- Changes:
  - `RetryEngineImpl.java`: Added `executor` field + `setExecutor()` setter; `getExecutor()` lazy-inits from `GlobalExecutors` if null; `scheduleImmediateRetry` captures `getExecutor()` in a local var to prevent stale retry leakage into a different test's executor
  - `DefaultScheduledExecutor.java`: `destroy()` changed from `shutdown()` to `shutdownNow()` to cancel pending tasks
  - `MockRpcServiceInvoker.java`: Refactored from `ArrayList` + `AtomicInteger` index to `ConcurrentLinkedQueue` for thread-safe response polling
  - `TestRetryEngineImpl.java`: `@BeforeEach` creates test-local `DefaultScheduledExecutor` and sets via `retryEngine.setExecutor()`; `@AfterEach` destroys it
- Commit: `5df03f4d4b` — `fix(retry): fix flaky test race from stale scheduleImmediateRetry callbacks`
- Verification: `./mvnw clean install -T 1C` — BUILD SUCCESS; `./mvnw test -pl nop-retry/nop-retry-engine` — 27 tests, 0 failures
