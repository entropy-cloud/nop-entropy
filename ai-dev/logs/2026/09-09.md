# 2026-09-09

## nop-treesitter roadmap item 9 — incremental reparse (plan 2026-09-08-0234-3) 执行开始

- Baseline verified: `./mvnw -pl nop-treesitter -am test -T 1C` green — **270 tests**（plan 起草时 134，item 7/8 落地后增长）。
- 读 C 参考：`lib/src/get_changed_ranges.c`（并行迭代器 + `ts_range_array_add` 合并 + 尾部差值）、`reusable_node.h`、`parser.c` 的 `ts_parser__reuse_node` / `ts_parser__can_reuse_first_leaf` / `ts_parser__advance`。gotreesitter `tree.go` `DiffChangedRanges`/`diffNodes` 作第二参照。
- **关键发现（记录进 plan 的 Decision）**：
  1. C 复用复合节点时经 `breakdown_lookahead` 拆开、实际只 shift 叶子 → Java 侧按**叶子粒度**复用，上层全部由 reduce 重建，形状/production id/dyn-prec 与全量解析构造性一致。
  2. C 的 `ts_tree_edit` 会把旧树**变异**到新坐标并用 `has_changes` 位门控复用；本实现保持 `TSTree` 不可变，复用门控改为**编辑区间相交判定**（同一谓词、无需 write-only 版本列）。arena 版本列按 Minimum Rules #24（防空壳）裁定移除。
  3. `getChangedRanges` 采用叶子 spine + **位置无关内容相等**（借各自 TSTree 保留的 source bytes）+ 并集区间合并 —— 比绝对位置相等更紧（不移位尾部过报），且能报出 `1`→`2` 这类纯 token 内容变化。`TSTree` 因此增加 source 保留（修正 plan baseline 的"无需保留"判断）。
  4. 复用门控保守项：外部 lex 状态不复用；cell 含 REDUCE 不复用（`preferShift=false` 下 shift+reduce 是真 GLR 分叉）；keyword-capture token 不复用；零长叶子不复用。
- Phase 1 landed：`parser/incremental/` 包新增 `TSPoint`（row/UTF-8-byte column + `fromByteOffset`）、`TSRange`（points+bytes+`overlapsOrTouches`）、`TSInputEdit`（old/new byte triple + `of(oldSource,newSource,...)` + `isNoop`），全部不可变 record、typed error 校验；`TSEditValueTypesTest` 10 tests green。
