### 2026-10-10（plan 2379 nop-find：独立模糊文件查找工具，Phase 1-4 落地）

- **模块组新建**：`nop-find/`（父 POM + `nop-find-core` + `nop-find-cli` + `nop-find-bom`），JDK ≥ 22 profile 挂入根 reactor `<modules>`（同 nop-rg `java22-modules` 模式）。core 依赖 `nop-rg-core` 复用 `ParallelFileWalker` / `GlobMatcher`。
- **核心算法**：`FuzzyFileScorer` 三级打分（前缀 `len(text)-len(query)` / 子串 `100+indexOf` / 子序列 `200+Σ相邻间隔+len 差`）+ name/relativePath/path 三路取最优（+0/+25/+300）；`TopKCollector` 按 `(score, index)` 全序的定长列表 + 二分插入 + 「已满且不优于末尾即跳过」快速路径 + `mergeFrom` K 路归并。
- **确定性设计（关键裁定）**：`index` 取自 `ParallelFileWalker` 排序后候选列表的下标，与线程数无关 → `(score, index)` 全序 → `threads=1/2/4/8/16` 返回结果逐元素一致（同分 tie-break 天然等于路径字典序，与设计文档的输出契约一致）。`FindCoordinatorTest` 用 300 文件 fixture 对 threads=2/4/8 做了逐行比对。

- **契约细化（相对设计稿）**：文本输出打印 **relativePath**（设计稿写的是 `PATH`，但"喂编辑器/复制粘贴"的消费场景需要相对路径；绝对路径由 `--json` 的 `path` 字段提供）。已在 `01-architecture.md` 决策 6 同步为定稿表述。

### 2026-10-10（EQL 写语句扩展：upsert + insert/delete returning 设计与计划起草）

- **起因**：用户问「EQL 是否支持 upsert / UPDATE RETURNING」。核查结论——EQL 文法只有 `SELECT`/`INSERT`/`UPDATE`/`DELETE`（`nop-persistence/nop-orm-eql/model/antlr/Eql.g4:32-51`），无 `MERGE`/upsert；`RETURNING` 只挂在 `sqlUpdate` 上（`DMLStatement.g4:32`）。二者都是 `ai-dev/backlog/eql-cross-db-compat-roadmap.md` 的**已完成 WI0..WI12**（`:81-96` 全 done）之外的显式排除项：「明确不做的事」`:51`「不把 UPSERT 做进语法层（改走 DAO 原语）」+ ledger `MERGE` 行 `:146-147` 的 WI11「显式移出」终裁。
- **scope 裁定（用户显式选择）**：upsert 取中立形态 `upsert into T(...) values(...) on conflict(k) do update set ...`；RETURNING 补 `INSERT` + `DELETE` 两个子句位；方言范围锁定 **PostgreSQL 族 / MySQL·MariaDB 族 / H2 族**，其余编译期响亮失败。
- **设计文档**：`ai-dev/design/eql-cross-db-compat/2026-10-10-eql-upsert-and-returning-design.md`，5 条核心决策。其中两条安全约束是本次设计的主要价值：①**冲突键列集编译期校验**必须等于实体声明的唯一键或主键——因为 MySQL 族 `ON DUPLICATE KEY UPDATE` 完全忽略冲突键列表，声明的键若非真实唯一键会**静默退化为普通插入**；②**H2 更新列集约束**——H2 `MERGE ... KEY ... VALUES` 固定按 VALUES 列清单整列更新，更新集与「列清单 − 冲突键」不一致时产出的是与 PG/MySQL **语义不同的 SQL**，故编译期报 `feature=upsertPartialUpdate`。错误面「零新增码 + 1 个专用码」（`dialect-not-support-feature` 复用 + 新增 `invalid-conflict-columns`）。v1 **不引入 `excluded` 伪表**（会把 H2 分支从「受限可用」降级为「一律不可用」），已记为 successor。
