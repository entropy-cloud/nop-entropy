## nop-rg Glob 性能对齐 globset：源码调研 + 设计文档 + roadmap

- **源码获取**：`~/sources/globset-src`（ripgrep 仓库 clone，globset crate 在 `crates/globset/src/{lib.rs,glob.rs,pathutil.rs,fnv.rs}`）。
- **独立子 agent 分析结论**（fresh session，agent_7769199a-f767-4ddb-bc2c-e4354e90487a）：瓶颈不在策略分发，而在热路径分配——`globSet` 基准 3 条规则全落 SLOW，每次 accept 对同一路径 `splitPath` **3 次**（`path.split("/")` + 每段 substring + ArrayList）；`matchesAny` 先算 basename（substring）却被 SLOW 丢弃；`singleGlob` 也每次泄漏一次 `substring`（23k/s 的直接原因）。globset 的核心不是更快算法，而是 **Candidate 式路径预分解**（每路径准备一次，所有策略共享，零拷贝偏移）。
- **排序建议**：① Candidate 预分解 + 区间化 segmentMatches + 编译期 isDoubleStar 元数据（零语义风险，预期数倍）；② `**/REST` 分解（把 `**/*.java` 从 SLOW 拉回扩展名策略，基准集收益 10×+）+ ext 哈希 + 必需扩展名预滤；③ 长度位掩码、前缀/后缀策略。
- **明确不移植**：Aho-Corasick（数十条规则下 Java 朴素循环更快）、regex-automata RegexSet（手写两指针匹配更快）、byte[]/FNV（路径是 String）。
- **产出**：设计文档 `ai-dev/design/nop-rg/02-globset-parity-design.md`（6 条决策 + 不移植清单 + 语义保真约束 + 度量口径）；执行分解 `ai-dev/backlog/nop-rg-globset-parity-roadmap.md`（G1 分配消除 / G2 分类扩展 / G3 小额优化，含 2026-11-20 基线数值与复核命令）；nop-rg-roadmap 加交叉引用。
