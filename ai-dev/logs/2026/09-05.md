### 2026-09-05 XLang 类型推导 P1/P2 缺陷修复与回归测试（nop-xlang）

- **背景**：`ai-dev/analysis/2026-09/2026-09-05-xlang-type-inference-correctness-audit.md` 审计发现类型推导算法多处缺陷。本次修复其中 8 项并补 9 个回归测试。
- **修复**（`nop-kernel/nop-xlang`）：
  - `TypeInferenceProcessor`：新增 `processSwitchStatement` 覆写（此前 switch 整棵子树不做推导）；`processBlockStatement`/循环（while/do-while/for/for-of/for-in）通过新增 `mergeChildAssignments` 将内层对外层变量的赋值合并回外层（block 传播 + 循环 widening）；`processSequentialNodes` 只收集带 `returnAST` 标记的 return 语句类型（函数返回类型不再混入 `let` 声明等杂音），`union()` 与 `processExpressionStatement` 透传 return 标记（switch/if 内的 return 能计入函数返回类型）；`processLogicalExpression` 右操作数改用同一作用域；字符串 ADD 判断改用 `isStringType`（typeName 而非引用相等，兼容 resolved `java.lang.String`）。
  - `UnionTypeNarrower`：`instanceof`/`typeof`/`!= null` 的假分支从 `state.getVariableType`（声明类型）而非本次条件 result map 取原类型，独立条件下的 else 分支窄化恢复生效。
  - `XLangExprParser.buildExecutable`：类型推导错误改为以 `LOG.warn` 逐条暴露（此前 collector 用完即弃、错误静默丢失），不中断编译。
- **测试**：`TestTypeInferenceProcessor` 新增 9 个用例（switch 推导、switch-return 计入函数返回类型、函数返回类型排除非 return 语句、block 赋值传播、循环 widening、`&&` 右侧赋值传播、instanceof/typeof 假分支窄化、resolved String 的 ADD 推导）。
- **验证**：`./mvnw test -pl nop-kernel/nop-xlang` 全量 699 tests, 0 failures（2 skipped 为既有）。
- **未修**（见审计报告 P2/P3 剩余项）：call 实参校验、varargs/spread、泛型边界 `validateTypeBounds` 桩、编译 scope 桥接、`new Foo()` 构造类型、class/enum/for-range AST 覆盖等。
