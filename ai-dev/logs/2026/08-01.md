### Phase 1 — 声明式 filter-chain DSL 与解析（completed）

- **D1 裁定（filter ID 解析来源）**：采纳**方案 B**（agent 内 `<filter-definitions>` 自包含 id→impl 映射）。约束分析：`AgentExecutorResolver` 经 Builder/构造注入，**不持有 `IBeanContainer`**；仓库 `*.beans.xml` 无任何已注册 `IAgentMiddleware` bean。方案 A（IoC bean ID）需先打通容器注入路径（架构改动大），而方案 B 复用既有 `resolveMiddlewares` 的 `ClassHelper.safeNewInstance` 路径，零 IoC 改动。跨 agent 复用为首版 Non-Goal，方案 C 混合留作后续迭代。
- **D2 裁定（input/output → 生命周期点映射）**：input-filters 默认装到 **PRE_CALL**、output-filters 默认装到 **POST_CALL**（请求/响应边界，单次触发，避免 PRE_REASONING/PRE_ACTING 的 N+M+K 多触发语义错误）。filter 可用 `points` 属性覆盖默认映射（如 `points="pre_reasoning"`）。
- **DSL（`agent.xdef`）**：新增 `<filter-chain xdef:name="AgentFilterChainModel">`，含 `<filter-definitions>`(list,key=id) + `<input-filters>`(list) + `<output-filters>`(list)。`<input-filters>/<filter xdef:name="FilterRefModel" ref points>`，`<output-filters>` 经 `xdef:ref="FilterRefModel"` 复用同模型（避免 `xdef:name` 全局唯一约束——`XDefinitionParser.collectLocalRefs` 对重复 xdef:name 抛 `ERR_XDEF_DUPLICATE_LOCAL_REF`，故 output 用 xdef:ref 引用 input 已定义的 FilterRefModel，codegen 两 getter 均返回 `List<FilterRefModel>`，与 gateway.xdef `requestMapping`/`responseMapping` 模式同构）。
- **codegen 产物**：`_AgentFilterChainModel`(filterDefinitions/inputFilters/outputFilters)、`_FilterDefModel`(id/impl)、`_FilterRefModel`(ref/points)；`_AgentModel.getFilterChain()`。手写壳类 `AgentFilterChainModel`(+`hasAnyFilters()`) / `FilterDefModel` / `FilterRefModel`。
- **解析器**：`FilterChainResolver.resolve(chain)`（D1 方案 B）：index filter-definitions → 按 ref 解析为 `IAgentMiddleware`（`ClassHelper.safeNewInstance`，per-id cache → 同 filter 在 input+output 引用时实例 identity-shared，使 D3 重复检测无歧义）→ 按 D2 映射分组。**无静默跳过**：未知 ID / 缺 impl / 非 IAgentMiddleware / 未知 points 名 / 实例化失败 均抛 `NopAiAgentException`（含 ID 名 / point 名，5 个 error code）。
- **ResolvedFilterChain**：持有 `inputFilterRefs`/`outputFilterRefs`（声明侧，可序列化）+ `resolvedByPoint: Map<AgentLifecyclePoint,List<IAgentMiddleware>>`（执行侧），不可变视图（声明后不可运行时修改）。
