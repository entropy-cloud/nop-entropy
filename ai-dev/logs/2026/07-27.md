### 2026-07-27 (flux e2e: 发现 rolldown `require("react")` error boundary bug + 文档路由改进)

- **发现 flux 模式下浏览器测试失败根因**：通过 `page.content()` 抓取 DOM，发现 `main-content` 区域渲染了 React error boundary，内容为 `Calling "require" for "react" in an environment that doesn't expose the "require" function`。这不是 FluxAdapter 选择器的问题，而是 `nop-chaos-next` 的 rolldown 打包产物在 ESM runtime 下试图 `require("react")` 导致报错。侧边栏正常加载（因不依赖出错的 chunk），但所有路由页面均无法渲染。此前误判为 SPA 路由/选择器问题，实际是前端打包/运行时兼容性 bug。
- **修复 `flux-web.xlib` NormalizeAction**：`throw new NopException("Unsupported actionType: " + actionType)` 改为 `new NopScriptError(errorCode).param(...)`（`NopException` 没有 `(String)` 构造函数，只有 `(ErrorCode)`，导致 `ClassCastException: String -> ErrorCode` 阻塞 Quarkus 启动）。同时新增 `actionType: submit` → `{ action: 'submitForm' }` 和 `actionType: custom` → pass-through。
- **修正文档路由**：
  - `AGENTS.md`: 「编写或运行平台 E2E 测试」的 Then read 列追加 `e2e-testing-troubleshooting.md`；新增「E2E Playwright 测试失败排查」独立行。
  - `debugging-and-diagnostics.md` 测试失败调试铁律：新增「Playwright E2E 调试铁则」子节，规定 DOM 排查优先（`page.content()`）。
  - `e2e-testing-troubleshooting.md`: 新增「通用调试方法」节（`page.content()` + `curl` 验证 API）。
