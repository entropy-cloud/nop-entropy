# 2026-11-01 开发日志

### 2026-11-01（nop-orm DDL：MySQL 8 建表两处兼容修复，来源 nop-app-mall mobile-visual-fidelity V6 MySQL 补验）

- **问题 1 — 主键列显式 NULL**：`ddl_mysql.xlib` 的 `ColNullDef` 对非 `mandatory` 列一律输出 `NULL`，主键列未声明 mandatory 时生成 `ID VARCHAR(50) NULL ... primary key (ID)`；MySQL 5.7 仅告警并隐式转 NOT NULL，MySQL 8 直接报 error 1171（All parts of a PRIMARY KEY must be NOT NULL），`DataBaseSchemaInitializer` 在首个失败表中止，后续全部表缺失。**修复**：`ColNullDef` 改为 `col.primary or (col.mandatory and !allNullable) ? 'NOT NULL' : 'NULL'`——主键列无条件 NOT NULL（nop-app-mall `litemall_reset_code` 实证）。
- **问题 2 — 唯一键长度超 InnoDB 3072 字节上限**：`nop_auth_mfa_credential.CREDENTIAL_ID VARCHAR(1400)` 上的 `UK_NOP_AUTH_MFA_CREDENTIAL_CRED`，utf8mb4 下 5600 字节，报 error 1071（Specified key was too long）。**修复**：`ddl.xlib` 把唯一键列列表抽为可覆盖标签 `UniqueKeyColumns`（基实现=原列名列表，其它方言行为不变）；`ddl_mysql.xlib` 覆盖：VARCHAR/CHAR 列 precision > 768 时输出前缀唯一索引 `COL(768)`（768 = 3072/4 utf8mb4 上限）。语义注：前缀唯一索引只保证前 768 字符唯一；WebAuthn credentialId 的 base64url 远超前缀碰撞概率可忽略，若需严格唯一应在模型侧改为定长哈希列（留 nop-auth 侧评估）。
- **验证**：nop-app-mall 全模型（57 litemall + nop 平台表）在 MySQL 8.0（docker）从空库 `init-database-schema` 一次建全 105 表、零 `bad-sql-grammar`、LoginApi 200；`SHOW CREATE TABLE nop_auth_mfa_credential` 可见 `UNIQUE KEY (CREDENTIAL_ID(768))`；H2 路径回归（mem 库建表 + init data + 登录 200，零 DDL 错误）。验证方式为把两份 xlib `jar uf` 进 mall 应用 fast-jar 的 nop-orm jar 后实跑（模块单测未覆盖 DDL 文本生成，建议后续补 `ddl_mysql` 黄金文本测试）。
- **影响面**：仅 MySQL 方言 DDL 文本（主键 NOT NULL、超长唯一键前缀）；`ddl.xlib` 的 `UniqueKeyColumns` 抽取对 H2/PostgreSQL/Oracle/MSSQL/MariaDB 输出等价。
