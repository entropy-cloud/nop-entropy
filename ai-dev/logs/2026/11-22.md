## 任务历史改为仅内存保留（用户裁定：不落盘）

- 文档 reconcile：design 10 §三（"仅内存保留——重启即清空"）、README、/v1/help history 字段。


## 任务历史持久化（最近 100 始终可查）+ 超限拒绝裁定 + 取消/队列子代理验证抓到 3 个真缺陷修复

- **历史保留（用户需求）**：新增 `JobHistory`——每个终态 job（done/failed/cancelled，含 QUEUED 取消与 RUNNING 取杀两路）追加一行 JSON 到各项目 `.nop-ib/history.jsonl`（崩溃安全：追加写 + 读时跳过残行）；内存 registry 的 prune 改为保留最近 100 条终态 job（不再按 10 分钟时间淘汰），超出的才连同日志文件清掉（幂等键同步清理）；`GET /v1/jobs` 合并「内存 + 各项目 history.jsonl」，重启后立即可查——服务侧维护 served-roots 台账（`~/.nop-ib-service/served-roots.txt`，`nop.ib.rootsLedger` 可覆盖）定位曾服务过的项目。历史条目带 `bootId`（服务启动时间戳）区分跨重启复用的 job id。
- **超限策略裁定（用户问询，AI 自主场景）**：**满员 429 拒绝新提交，绝不自动 drop 最老排队记录**——drop 会让在等结果的 agent 轮询到 job 消失（静默破坏），且惩罚最久等待者、诱发频繁重提交挤重队列；429 是响亮可操作信号（带 clientRequestId 退避重试）。已写入 design 10 §三 与 /v1/help queueing.capacity。
- **子代理实测抓到 3 个真缺陷（均已修）**：
  1. **DELETE QUEUED job 返回 NPE 500**（取消实际成功）——`registry.cancel` 成功返回 null，HTTP 层 `Map.of("result", null)` 抛 NPE。2588 以来的潜伏缺陷（单元测试只测 registry 层）。修：ServiceCore.cancel 归一 null→"cancelled"。回归：TestJobHistory.cancelledQueuedJobIsRecordedInHistory 走 HTTP 层语义。
  2. **未启动取消的 job durationMs = finishedAt 裸时间戳**（startedAt=0 相减）——修：startedAt==0 时 duration=0 并附 queueWaitMs。
  3. **safe()/job handler 两处 catch 只打 e.toString 无堆栈**，NPE 无法定位——修：printStackTrace 进服务日志（本轮正是靠它定位到 Map.of NPE）。
- **子代理验证结论（HTTP 层全路径）**：取消 QUEUED（生效→cancelled→进历史）、取消 RUNNING（37ms 杀进程树、exit=-1、下一 job 接棒、`already-terminal` 契约正确）、队列探知（depth/pending/queueAhead/queueAheadIds/runningJobId 全链路正确、批量取消后 lane 清空）、历史会话内保留 ✓。
- **登记 watch**：一次 wait=true 响应外层 JSON 报"Invalid control character"（未能复现，本轮同命令响应干净；payload 内嵌 CLI 输出的控制字符防护已在 writeString 覆盖 <0x20）；/v1/jobs 终态条目内嵌完整 payload/stderr，超大输出时列表查询偏重（列表裁剪归入后续增强）。
- **验证**：nop-ib 207/0（+3 历史测试：追加/重启恢复/取消入史/残行跳过）；重启持久化主控实测——重启后不提交任何新任务，/v1/jobs 直接返回重启前 7 条历史（含 bootId 区分）；~/nop-ib 已重打包重启。


## coalescing 语义修正（只合并 QUEUED，不合并 RUNNING——缓存优先不牺牲新鲜度）+ 双独立 agent 大项目压测验证

- **语义修正（用户裁定）**：初版同参合并对 RUNNING job 也生效——被用户指出缺陷：运行中 job 的输入集已快照，源码若在其启动后变更，合并会返回改码前的陈旧结果。修正为**只合并到 QUEUED（未启动）job**（启动时按当时源码分类，结果等价）；RUNNING 一律重新排队——重跑时源码未变则快路径指纹命中测试缓存（近零成本），变了则正确重建。**缓存负责"没变别重跑"、排队合并负责"重复提交别重复排队"，互补且都不牺牲新鲜度**（design 10 §四）。
- **实现**：JobRegistry.findActive 仅匹配 QUEUED；BuildJob 增加 coalesced 标记；/v1/help 新增 coalescing 契约节；ib-run 进度行补齐任务日志路径与轮询 URL（`queued: N ahead (running: job-K) — waiting, Ns so far | log: <path> (poll GET …)`）。回归钉 `identicalQueuedSubmissionCoalescesButRunningDoesNot`（三场景：QUEUED 合并/异参独立/RUNNING 与终态不吸收）；TestServiceCore 两个串行不变式测试与 TestServeHttpAsync 长轮询测试原为同参提交，按新语义改异参保留意图；nop-ib 204/0。
- **双独立 agent 大项目压测（两个子代理互不协调并行行动，主仓 model-stale 环境下 Maven 回退 ~31-38s/次）**：
  - 有序性：两 agent 观察一致——lane 严格串行（前一 job finishedAt == 后一 startedAt 逐次衔接），全程无同 lane 双 RUNNING，无冲突。
  - 合并：Agent B 的同参重试（agent-B-2）合并到自身在途 QUEUED job（coalesced:true+replayed:true，同 id），一次 Maven（30.97s）服务两次提交；**跨 agent 时机落在对方 RUNNING 窗口时按新语义独立排队**（A 的 job-2 与 B 的 job-3 各自执行一次）——正是"不牺牲新鲜度"的实证。
  - 消息：ib-run stderr 含排队行（前方数/运行者/等待秒数/日志路径/轮询 URL）；queued 快照实测无 progress/logTail（泄漏修复实证），running 快照有 progress+logTail。
  - 登记：nop-git review 提示行出现在 Maven 日志尾部（nop-git PATH 覆盖与 Maven 进程交互的环境现象，exit 不受影响，watch）。

## GlobMatcher 下沉 commons（IPathMatcher 实现）+ 多 agent 并行协调实测与收敛（独立子代理验证）

- **GlobMatcher 下沉（用户裁定）**：引擎原样迁入 `nop-commons/io.nop.commons.path.SegmentGlobPathMatcher`（实现 `IPathMatcher` 全接口；`matchStart` 用追加 `/**` 近似、模板变量/combine 按 glob 语义给出最小实现）；语义零漂移（只拒 `[]{}()^\`、`|` 转义字面、`**` 吞尾斜杠——迁移中一度把 `a/**` 边界规则写反，以原引擎行为为准修正测试）；ib 侧 `GlobMatcher` 变薄壳并保留 NopIbException（exit 3）配置错误契约。回归钉 `SegmentGlobPathMatcherTest` 7 例；nop-commons 490/0、nop-ib 203/0。
- **多 agent 并行协调实测（独立子代理，全程 HTTP/ib-run，时间盒 12 分钟）**：核心机制全部实证成立——同项目 3 并发提交严格 FIFO 串行（started==前一 finished）、跨项目双 lane 并行（startedAt 差 13ms）、测试缓存命中 ~1ms vs 全跑 ~25s、队列满 429 契约在案。缺口清单 7 条（详见子代理报告，已入日志归档）：2 条高优先级当场修复（见下），其余裁定记录于 design 10。
- **修复（高）**：① queued job 快照泄漏 lane 级 `progress`/`logTail`（会排队 agent 误读为自身执行进度）——`BuildJob.snapshot/pendingSnapshot` 对 QUEUED 态全部抑制，RUNNING 独享；回归钉 `progressVisibleOnlyToRunningJob`（旧测试钉的是泄漏行为，按新裁定改写并同包模拟 execute() 状态翻转）。② 快照形态补齐排队者决策信息：`queueAheadIds`（FIFO）、`runningJobId`、`cmd`、`queueWaitMs`/`runMs`（拆分排队/运行时长，elapsedMs 保留兼容），提交响应（wait=false）也走 queue-aware 快照。
- **ib-run 改异步轮询模式**：排队时 stderr 显式输出 `queued: N job(s) ahead (running: job-K) — waiting`，运行期输出 `running: <phase> (Ns)`，`--quiet` 关闭进度通道（不透传给构建命令）；实测双 job 并发提交，排队提示/进度/结束行全部按预期输出。首轮实现用长轮询（waitMs=20000）会跳过排队期（状态不变不唤醒），改 waitMs=0 + 2s 轮询后正确。
- **契约收敛**：/v1/help 新增 `queueing` 节（lane 模型/32 上限与 429/agent etiquette/字段语义/refresh 成本说明）；`/v1/queue` 的 `depth`（仅排队数）与 `pending`（运行+排队）语义写明；design 09 中间态字段 reconcile。
- **新文档**：`ai-dev/design/nop-incremental-build/10-multi-agent-coordination-design.md`（协调模型裁定/排队者契约/etiquette/缓存三级阶梯与「pom 变更先 refresh」规范/拒绝的替代方案：全局锁、ETA 依据不足暂缓、抢占重排）；design README 索引补 09/10 行（顺手修复 08 行描述复制粘连）；analysis 平台复用报告 GlobMatcher 行更新为「已迁移」终局裁定。
