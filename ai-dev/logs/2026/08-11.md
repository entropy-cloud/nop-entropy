**两个补全的语义**：

1. **子节点 `x:extends` 的隐式 `replace` 语义**：子节点一旦自己 resolve 过 `x:extends`，立即被自动标记 `x:override="replace"`，父继承方向在该子树上不再合并（即父继承的同名子节点被整体丢弃，不是 merge）。两条链路实现一致：
   - XDSL 链路：`XDslExtender.java:125`（`ret.setAttr(null, keys.OVERRIDE, XDefOverride.REPLACE)`）+ `extendsSub` 递归 `:408-436`。
   - 纯 JSON 链路：`JsonExtender.java:88-92`（`ret.put(CoreConstants.ATTR_X_OVERRIDE, CoreConstants.OVERRIDE_REPLACE)`，附中文注释"处理过x:extends之后，标记节点为replace，不再参与其他合并处理"）+ `extendsMapEntries` 递归 `:182-206`。

2. **无 xdef 的并行 JSON 合并链路（`DeltaJsonLoader`）**：`nop-core` 中存在一条独立的、不依赖 xdef 的 `x:extends` 合并链路，全程在 `Map<String,Object>` 上操作，不经过 `XNode`。与 `XDslExtender`（`nop-xlang`，需要 `x:schema`）形成平行对照。两条链路对"子节点自动 replace"语义实现一致，但 `JsonExtender` 不支持 `x:gen-extends` / `x:post-extends` 的 XPL 编译期执行（仅支持可选的 `x:gen-extends` 字符串形式 + 外部 `IDeltaExtendsGenerator`）。典型适用场景：`_nop-auth.i18n.yaml`、amis 页面 JSON。配套 `DeltaJsonSaver` 提供"自动 diff 写回最小差量"能力（XDSL 链路没有这条路径）。
